# 🍊mikanBox Cloudflare版 アップデート手順リファレンス

自分でコマンドを実行して更新する人と、AIが更新を進めるときのための詳細です。通常の利用者向けの説明は[Cloud版マニュアル](cloud_ja.md#アップデート)にあります。

## ダウンロードして更新する（コマンド）

自分でコマンドを実行する場合は、最新版の[リリースページ](https://github.com/yoshihik0/mikanBox-cloud/releases)から **Source code (zip)** をダウンロードして展開し、そのフォルダで `npm ci`、`npx wrangler login`、`npx wrangler whoami` を実行します。Cloudflareのアカウントが既存サイトと一致していることを確認します。これは新規インストールではありません。既存のD1、管理Worker、公開Workerを使います。

設置時の `wrangler.production.json` を展開先に用意します。アカウントID、管理Worker名、D1 ID、R2を接続している場合のバインディング、ルートや独自ドメインが現在の実際の構成と一致することを確認します。設定が不明なら、Cloudflareの管理画面で既存Workerの設定とバインディングを確認し、正確な構成を復元するまで公開しないでください。新規用のサンプル値をそのまま使わないでください。

次に、次の2コマンドを順番に実行します。`--keep-vars` は既存の環境変数を保持します。既存のWorkerの秘密情報も保持されます。

```sh
npx wrangler d1 migrations apply DB --remote --config wrangler.production.json
npx wrangler deploy --config wrangler.production.json --keep-vars
```

既存サイト用に `JWT_SECRET` や `SETUP_TOKEN` を作り直さないでください。特に新しい秘密ファイルを使って `npm run deploy:cloud` を実行すると、登録済み端末の認証等に影響する可能性があります。公開側の初期ページ用 `wrangler.public.json` を既存サイトに再デプロイしないでください。公開サイトが初期ページに置き換わります。完了後は管理画面を再読み込みし、バージョン、記事、画像を確認します。

## GitHub Actionsの動作詳細

Actionsは既存の管理WorkerとD1/R2の接続を照合し、ビルド、未適用D1マイグレーション、管理Workerの公開を行います。接続が違う場合や未対応の追加バインディングがある場合は中止します。接続やルートを変更したらGitHubに保存した設定も更新してください。DB更新とWorker公開は一つの処理ではないため、途中で失敗するとDBだけ更新済みの場合があります。失敗した工程と現在の状態を確認してから再実行してください。適用済みマイグレーションは再適用されません。

## 実装上の仕様メモ

公開用ファイルの取得はダウンロードとして扱い、管理画面の権限でコードを実行しません。公開ヘルプでは製品側のスクリプトだけを許可します。削除したページが配信先に残っている間は未反映として表示します。端末停止では、その端末が発行した未使用コードも取り消します。初期設定・復旧トークンは同時要求でも一度だけ使用できます。

管理画面はGitHubのCloud版リリース情報を確認し、現在と最新のバージョン、新版の有無を表示します。「再確認」は最新情報だけを取得します。現在のバージョンを更新後に確認するには画面を再読み込みしてください。手動更新の初回設定は下記を参照してください。`CLOUD_RELEASE_MANIFEST_URL` でHTTPSのCloud専用JSONを指定することもできます。
