# 🍊mikanBox Cloudflare版 マニュアル <small class="manual-version">v0.14.0</small>

このマニュアルはCloudflare版の導入と、PHP版との違いを説明します。共通の操作は[操作マニュアル](https://yoshihiko.com/mikanbox/help_ja.html)も参照してください。flat版・SQLite版との使い分けは、[README](https://github.com/yoshihik0/mikanBox-cloud#readme)を参照してください。

## 初期設定・配布について

### 新規インストールと公開

新しいサイトを作る手順です。既存サイトの更新では、D1やWorkerを新規作成せず、[アップデート手順](#manual-update)を参照してください。

画面を見ながら進める場合は、[画像付きインストールガイド](/mikanbox/guides/install-ja.html)を使います。

#### AIに依頼する（おすすめ）

ファイルの取得やコマンド実行ができるAIを使います。作業フォルダで新しい会話を開き、次のように依頼します。

「https://github.com/yoshihik0/mikanBox-cloud からCloudflareにインストールしてください」

ファイルの取得、設定、配置はAIが進めます。利用者が行うのは次の5つです。

1. **Cloudflareにログインしておく。** アカウントがなければ作成します。設置するアカウントでログインしてください。
2. **Cloudflareの認可画面で、設置先のアカウントを確認して「Authorize」を押す。**
3. **サイトのアドレスを決める。** 管理画面と公開サイトの名前を別々に選びます。`workers.dev` のアドレスは公開されるため、メールアドレスやログインIDは使わないでください。公開サイトに独自ドメインを使うこともでき、あとから設定もできます。
4. **普段使うブラウザで管理画面（`/admin`）を開き、端末を登録する。** AIが案内するファイルの `SETUP_TOKEN` を入力します。トークンはチャットに貼らず、管理画面に直接入力します。詳しくは[端末認証](#端末認証)を参照してください。
5. **公開の設定をする。** 管理画面の「サイト」→「Cloudflare公開設定」に、Workers Scripts Edit 権限のAPIトークンを保存し、ページ一覧の「静的サイトをビルド」で公開します。ビルドが終わるまで画面を開いておきます。

#### 注意

- **既存の公開サイトには新規インストールを行わないでください。** 公開サイトが初期ページに置き換わります。更新は[アップデート手順](#manual-update)を使います。
- 設定ファイルと秘密情報（`.env.production.secrets` など）はGitHubに公開せず、安全に保管します。設定ファイルは後の更新にも使います。
- Cloudflareの画面や料金・無料枠は変更されることがあります。
- 管理側のAPIトークンは、Wranglerのログインとは別のものです。D1の書き出し・復元も使う場合は、D1編集権限も必要です。

#### 自分でコマンドを実行する場合

Node.js（22以上）とnpm、ターミナルが必要です。コマンドと設定ファイルの詳細は[詳細リファレンス（インストール手順）](https://github.com/yoshihik0/mikanBox-cloud/blob/HEAD/docs/reference_ja.md#インストール手順)を参照してください。公開URLをあとから変更する手順も、同じリファレンスにあります。

### アップデート

[画像付きアップデートガイド](/mikanbox/guides/update-ja.html)では、GitHubの画面を見ながら設定と更新ができます。

管理画面の「サイト」で、現在のバージョンとGitHub上の最新版を確認できます。最新版は、GitHubで公開されたリリースから読み取ります（v0.10.3から。開発中のブランチの変更だけでは表示は変わりません）。「再確認」は最新版の情報を取り直します。画面は再読み込みせず、結果は右下に表示します（v0.11.1から）。更新後は、画面を再読み込みして現在のバージョンを確認します。

更新は、記事や画像を初期化する操作ではありません。**更新の前に**、「データ移行・インポートツール」で必要なバックアップを保存してください。非公開データを含むため、安全に保管します。

#### 更新方法を選ぶ

更新方法は2つです。どちらを選んでも、記事や画像はそのまま残ります。

| | GitHubから更新 | ダウンロードして更新 |
| :--- | :--- | :--- |
| 更新のしかた | 管理画面のボタンから、GitHubで実行 | 最新版をダウンロードし、AIまたはコマンドで実行 |
| 最初の設定 | 必要（フォーク、APIトークン、Secretの登録） | 不要（Cloudflareにログインできればよい） |
| 2回目以降 | ボタンひとつ | 毎回ダウンロードして実行 |
| 向いている人 | 頻繁に更新する人、GitHubに慣れた人 | 設定を増やしたくない人、たまに更新する人 |

更新されるのは管理画面（管理用Worker）です。公開ページや画像の変更は、更新後も管理画面の「静的サイトをビルド」で配信します。

#### GitHubから更新する

設定が済んでいれば、更新はボタンを押すだけです。

##### 更新のしかた

1. 管理画面「サイト」で新しいバージョンを確認し、**GitHubでアップデート**を押します。
2. GitHubで **Run workflow** → 表示された **Run workflow** を押します。
3. 実行履歴で **Success** を確認し、管理画面を再読み込みします。現在のバージョンと記事・画像を確認します。**Failure** の場合は、失敗した工程を開いて内容を確認します。

##### 初回設定（少し難しいですが、最初の1回だけです）

初回だけ、自分のGitHubにコピーを作り、Cloudflareへの権限を登録します。次の3つの手順です。

###### 初回1：自分のリポジトリを作る

1. GitHubにログインし、[制作元のリポジトリ](https://github.com/yoshihik0/mikanBox-cloud)を開きます。
2. 画面右上の **Fork** を押し、所有先を自分のアカウントにして **Create fork** を押します。すでに自分が管理するコピーがある場合はそれを使えます。
3. 作成した自分のリポジトリの **Actions** タブを開き、無効なら表示される有効化ボタンを押します。**Update mikanBox Cloud** が表示されることを確認します。ワークフローがない古いコピーでは、最新版の `.github/workflows/update-cloud.yml` を自分のリポジトリの既定ブランチに追加する必要があります。

###### 初回2：更新先と権限を登録する

トークンを新しく作る場合は、Cloudflareダッシュボードのプロフィールから **APIトークン → トークンを作成する** を開き、「カスタムトークンを作成する」の **始める** を押し、権限に「アカウント / Workers スクリプト / 編集」と「アカウント / D1 / 編集」を追加します。アカウントリソースで対象アカウントを指定し、**概要に進む → トークンを作成する** を押します。表示された値は再表示できないため、安全に控えます。トークンはGitHubのSecret欄へ直接貼り、チャットに送らないでください。

自分のリポジトリで **Settings → Secrets and variables → Actions** を開き、**New repository secret** から次の2件をそれぞれ登録します。Nameに名前、Secretに値を入れて **Add secret** を押します。制作元ではなく自分のリポジトリに登録してください。

- Name：`CLOUDFLARE_API_TOKEN`。Secret：既存サイトのCloudflareアカウントを対象に、**Workers Scripts Edit** と **D1 Edit** の両方の権限を持つAPIトークン。管理画面の公開設定で使ったトークンに両方の権限があれば再利用でき、別のトークンでも構いません。公開設定に保存した値は再表示できません。独自ドメインやルートの操作には追加のゾーン権限が必要になる場合があります。トークンをチャットや公開ファイルに貼らないでください。
- Name：`MIKANBOX_UPDATE_CONFIG`。Secret：現在のサイト用 `wrangler.production.json` の**全文**。設置時のファイルを使い、アカウント、管理Worker、DB、ルート・独自ドメインなどが現在の構成と一致することを確認します。JSONにはJWT_SECRET、SETUP_TOKEN、APIトークンを入れません。ファイルがない場合はCloudflareのWorker設定・バインディング・ルートを確認して構成を復元する必要があります。不明な設定のまま実行しないでください。

###### 初回3：実行してリンクを設定する

自分のリポジトリの **Actions → Update mikanBox Cloud → Run workflow** を開き、表示された **Run workflow** を押します。実行履歴を開き、**Success** になるまで待ちます。成功後、管理画面を再読み込みすると「GitHubでアップデート」が自分のリポジトリを開きます。管理画面に「手動アップデートの設定」がすでにある場合は、自分のリポジトリを `所有者/リポジトリ名` の形式で保存してリンクを設定することもできます。

以上で設定は完了です。次回からは「更新のしかた」の3ステップだけです。

##### 知っておくこと

- Actionsは制作元の最新公開リリースを毎回取得します。公開プレリリースも対象です。
- v0.10.3のワークフローは、リリースのタグが指すコミットを最初に確かめ、そのコミットだけを取得し、取得したものが一致することを確認してから準備と配置に進みます。使うGitHubのアクション（`actions/checkout` など）も、公式リリースのコミットで固定しています。
- フォーク側のワークフロー自体は自動更新されません。その修正が公開された場合は、自分のコピーにも反映します。v0.10.3のワークフローに替えるには、自分のリポジトリで **Sync fork** を押すか、`.github/workflows/update-cloud.yml` を最新版に置き換えます。古いワークフローのままでも更新はできますが、上のコミットの確認は行われません。
- 管理WorkerとD1の接続が設定と違う場合や、未対応の追加バインディングがある場合は、Actionsが中止します。接続やルートを変更したら、GitHubに保存した設定も更新してください。
- Workers Buildsなど別の仕組みでGitHubへのpush時に自動デプロイしている場合は、手動更新とは別にその設定を確認してください。
- DBの更新とWorkerの公開は別の工程です。途中で失敗するとDBだけ更新済みの場合があります。失敗した工程を確認してから再実行します。適用済みのDB更新は再適用されません。

動作の詳細は[詳細リファレンス（アップデート手順）](https://github.com/yoshihik0/mikanBox-cloud/blob/HEAD/docs/reference_ja.md#アップデート手順)を参照してください。

#### ダウンロードして更新する

1. 最新版の[リリースページ](https://github.com/yoshihik0/mikanBox-cloud/releases)から **Source code (zip)** をダウンロードして展開します。
2. 既存サイトと同じCloudflareアカウントでログインします。認可画面で対象アカウントを確認し、**Authorize** を押します。
3. 更新を実行します。**AIに頼むか、コマンドで行います。**

AIに頼む場合は、展開したフォルダでAIの新しい会話を開き、既存の管理画面URLを伝えて「このサイトを最新版に更新してください」と依頼します。AIが設定を確認して更新を進めます。コマンドで行う場合の手順は、[詳細リファレンス（アップデート手順）](https://github.com/yoshihik0/mikanBox-cloud/blob/HEAD/docs/reference_ja.md#アップデート手順)を参照してください。

**注意：** 更新には、設置時の設定ファイル `wrangler.production.json` が必要です。現在のサイトの構成と一致しているものを使い、新規用のサンプル値は使いません。見つからない場合は、Cloudflareで既存Workerの設定を確認してから進めてください。

### 端末認証

パスワードはありません。管理画面に入れるのは、登録した端末（ブラウザ）だけです。

#### 最初の端末を登録する

インストール後、ログイン画面で `SETUP_TOKEN`・ユーザー名・表示名・端末の名前を入力します。使った `SETUP_TOKEN` は二度と使えません。

#### 端末を追加する

1. 登録済みの端末で、サイト →「端末とユーザー」→「端末を追加する」を開き、追加用のコードを出します。
2. 新しい端末のログイン画面で、そのコードを入力します。

その端末は、コードを出した人と同じユーザーとして登録されます。コードは3時間有効で、1回だけ使えます。

#### ほかの人を招く

「端末とユーザー」の「ほかの人を招く」で招待のコードを出して渡します。ユーザーIDと表示名は、招待された人が、ログイン画面で自分で決めます。

#### 端末の管理

- **期限：** 最後に使ってから30日（標準）・90日・180日で切れます。使うたびに延びます。
- **止める：** 「端末とユーザー」の一覧から止めます。ユーザーを削除すると、そのユーザーの端末と、発行した未使用のコードも止まります。同じIDで作り直しても、旧端末は使えません。
- **制限：** コードで追加してから3日以内の端末は、ほかの端末を止める、ほかのユーザーを削除・変更する、ユーザーごとの復元、D1の時刻指定の復元ができません。`SETUP_TOKEN` で登録した端末には、この制限はありません。
- **お知らせ：** 新しい端末が登録されると、ほかの端末で管理画面を開いたときに知らせます。
- **表示名：** 「端末とユーザー」の自分のユーザーにある入力欄から変更できます。ユーザー名は変更できません。

#### すべての端末を失ったとき（復旧）

`wrangler secret put SETUP_TOKEN` で新しい値を設定し、ログイン画面の「復旧」から既存のユーザー名で登録します。登録済みの端末はすべて止まり、未使用のコードとMCPキーも消えます。

#### 注意

ブラウザのCookieを消す、別のブラウザに変える、プライベートモードで開くことは、端末を失うのと同じです。端末の管理（画面ロック、紛失時の対応）は利用者の責任です。

仕組みの詳細は[詳細リファレンス（端末認証と標準コンテンツ）](https://github.com/yoshihik0/mikanBox-cloud/blob/HEAD/docs/reference_ja.md#端末認証と標準コンテンツ)を参照してください。

## 全体像

### 標準コンテンツ

初回設定時に、SQLite版と同じ標準データを、選択した言語で取り込みます。日本語・英語それぞれ、ページ8件（ホーム、404、検索、各見本、DB見本）とコンポーネント11件（レイアウト、ヘッダー、フッター、カード、検索、AI指示の見本など）です。

- 既存のページ・コンポーネントは上書きしません。設定・アカウント・秘密は、この取り込みに含めません。
- 検索ページは、公開ページだけを対象にします。下書き・承認待ち・DBは含めません。検索の仕組みは「サイト内検索」を参照してください。
- AI指示の `DESIGN_sample.md` / `DESIGN.md` を編集できます。AI質問の `{{AI_QUESTION}}` と `{{AI_QUESTION:セクションID}}` に対応します。
- 見本の中の画像は同梱されていません。メディア画面から、必要な画像をアップロードしてください。
- 外部取得の `EXT_MD` は使えません。

### 公開と配信

Cloud版では、管理画面と公開サイトが別々のWorkerで動きます。公開サイトは静的ファイルだけで、閲覧されてもWorkerやD1の利用枠を使いません。

<a id="public-worker"></a>
v0.10.3から、公開用のWorker（管理用とは別の名前）が設定されていないときは、ビルド・公開・画像の自動公開のどれでも配信を行いません。管理用のWorkerへ公開ページを出すと、ページのJavaScriptが管理画面と同じアドレスで動いてしまうためです。この状態では、ビルドボタンの下に「公開用のWorkerを設定してください」という案内が出ます。公開用のWorkerは、管理用Workerの変数 `CLOUDFLARE_PUBLIC_WORKER_NAME`（公開用Workerの名前）と `PUBLIC_SITE_URL`（公開サイトのURL）で指定します。設置時の `wrangler.production.json` の `vars` に書き、管理用Workerを配置し直します。手順は[詳細リファレンス（インストール手順）](https://github.com/yoshihik0/mikanBox-cloud/blob/HEAD/docs/reference_ja.md#インストール手順)を参照してください。公式の手順でインストール・アップデートしたサイトは設定済みです。

v0.12.0から、手元の `wrangler dev` も同じ構成です（1つのWorkerへ公開する以前の動作は、開発用にも残していません）。公開用のWorkerを設定していないときも、管理用のWorkerは管理画面・MCP・プレビューだけを返し、ログインしていない相手にはサイトの内容を返しません。

#### ビルドして公開する

ページ一覧の下の「静的サイトをビルド」を押すと、公開ページのHTMLを作り、公開側へ配信します。

- 進み具合と結果はボタンの横に表示されます。完了まで画面を開いたままにしてください。
- 変更のあったファイルだけを送ります。
- 公開側に反映していない変更のページ数と、最後に公開した日時も表示します。
- ページ一覧の地球のアイコンで、公開サイトのページを開けます（PHP版と同じ役割。編集中の内容の確認は、ページ編集のプレビューで行います）。青は公開側が最新の内容、グレーは変更が未反映のページです。下書き・承認待ちのページと、まだ公開していないページでは、押せないグレーで表示します。ほかのページの変更（ページ一覧のコンポーネントなど）で変わる部分は、ビルドするまで反映されません。
- 公開先のURLは、ビルドボタンの近くに表示します。

##### 公開用のAPIトークン

ビルドには、Cloudflareで作ったAPIトークン（Workers Scripts Edit 権限）が必要です。サイト設定の「Cloudflare公開設定」に入力すると、暗号化して保存します。保存したトークンは再表示されず、バックアップにも含まれません。

トークンは最初に1回だけ作ります。作り直すのは、Cloudflare側でトークンを削除・失効させたとき、権限を変えたとき、サイトのJWT_SECRETを変えたとき、バックアップやTime Travelで別のDBへ戻したときだけです。未設定のときは、ビルドボタンの下に案内が出ます。Cloudflare APIがエラーの詳細を返した場合は、エラーコードとメッセージを表示します。

#### ページの状態

| 状態 | 動作 |
| :--- | :--- |
| 下書き・承認待ち | 非公開。ログインした編集者だけがプレビューできます。 |
| 公開 | ビルドでファイルを作り、静的ファイルとして配信します（HTML、Markdown、JSONなど、出力形式に応じたファイル）。 |

ページごとの静的・動的の選択はありません。MCPやインポートで `public_dynamic` を指定しても、「公開」として保存します。

以前の公開設定「DB」は、出力形式「mikanBox DB」になりました（PHP版2.18.0と同じ）。既存の「DB」のページは、更新時のデータベース移行（`0017`）・バックアップの復元・取り込み・MCPで、「公開」＋出力形式「mikanBox DB」に読み替えます。

#### 公開をやめる（取り下げ）

配信先に出したファイルはWorkerを通らないため、元データを消しても配信先に残ります。配信先から取り除くことを取り下げと呼びます。

非公開にしたページと削除したページは、ビルドのときに配信先から取り除き、URL別名も取り消します。**ビルドまでは読める状態が続きます。** 公開をやめたら、ビルドも行ってください。

画像の削除時は、メディア画面の操作が自動で取り下げます。名前変更・WebP変換時は、次のビルドまで元の公開画像を維持します。「画像の静的配信」を参照してください。

#### 管理側と公開側の違い

- 管理側のアドレスでは、ログインしていない人にページ・画像・サイトマップなどを出しません。検索エンジンにも載せません。
- v0.10.2から、`http://` で開いた管理側のアドレスは、同じアドレスの `https://` へ移ります（ページを開くときだけ。手元の `wrangler dev` の `localhost` などは移りません）。
- ログインした端末で管理側の `/about` などを開くと、プレビュー（`/preview/about`）に移ります。プレビューの中では、ページのJSからCookieや `localStorage` を使えません。
- 公開ページ、サイトマップ、RSSには公開サイトのURLを使います。サイトマップ・RSS・DBページのJSONは、公開側にファイルとして出します。
- 404ページは、PHP版と同じくサイトマップとRSSに載せません。
- 画面上部のログアウトボタンはありません。この端末を使わなくなるときは、「端末とユーザー」で止めます。
- AIの質問ボックスは、公開側では動きません。

仕組みの詳細は[詳細リファレンス（公開と配信）](https://github.com/yoshihik0/mikanBox-cloud/blob/HEAD/docs/reference_ja.md#公開と配信)を参照してください。

#### サイト内検索

サイト内検索は、Googleのサイト内検索を使います。`{{SEARCH_RESULTS}}` は、Googleでこのサイトの中を検索するフォームになります（`as_sitesearch` にサイトURLを入れます）。検索ページ（ID `search`）も静的に公開し、標準の検索ボックス（`_search_box`）から `index.php?page=search&q=…` に送られた検索語は、検索ページからそのままGoogleへ渡します。Googleに登録されたページだけが見つかり、公開したばかりのページはしばらく出てきません。入力した言葉はGoogleに送られます。

## ページ・ページ編集

基本の操作はPHP版と同じです。[ページ](https://yoshihiko.com/mikanbox/help_ja.html#page-mgmt)と[ページ編集](https://yoshihiko.com/mikanbox/help_ja.html#page-edit)を参照してください。ここでは、Cloud版で押さえておくことを説明します。

### 編集と保存

- 保存のたびに履歴を残します。履歴は1ページにつき直近10件を保存し、それより古いものは自動で削除します（ビジュアル編集は、1回の作業につき1件です）。
- 同じページを複数の端末で同時に編集できないよう、編集中のロックがあります。古い内容のまま保存して上書きすることはできず、競合した場合はエラーが表示されます。再読み込みして、最新の内容から編集し直してください。
- ページ・設定とも、取得したあとに他で変更されていると保存できません。
- カテゴリーを削除すると、候補の設定だけでなく、各ページに付いたカテゴリーも削除し、履歴を保存します。対象のページが編集中、または更新済みの場合は、全体を中止します。

### ビジュアル編集

使い方は、PHP版と同じです。[ビジュアル編集](https://yoshihiko.com/mikanbox/help_ja.html#visual-edit)を参照してください。ページ一覧の ビジュアル編集ボタン（鉛筆とプレビューの間）、ページ編集画面の右上のボタン、または管理画面と同じ場所の `/admin/visual`（ページを選ぶ画面）から開きます。Cloud版の違いは次のとおりです。

- **公開サイトへの反映**: 保存は、管理側のページに反映されます。公開済みのページは静的ファイルなので、[ビルドして公開](#ビルドして公開する)し直すまで、公開サイトは変わりません。公開済みのページを保存すると、画面にその旨が表示されます。
- **履歴**: ページを開いてから閉じるまでを1回の作業として、保存前の状態を1件だけ、ページの履歴に残します（こまめに保存しても、履歴が押し流されません）。元に戻す・やり直しは、直近3回分です。作業が変わると、元に戻す履歴は破棄します。
- **競合と編集ロック**: 保存時に、ページが取得したときのままでなければ、保存しません。ほかの端末や管理画面で変更されていたら、再読み込みしてください。ほかのユーザーが編集中（編集ロック）のページは、保存できません。ビジュアル編集で保存すると、開いたままのページ編集画面は古い内容になり、そのままでは保存できません（再読み込みが必要です）。
- **画像**: 一覧は新しい順です。貼り付け・ドラッグ・選択で追加できるのは、png / jpg / gif / webp（10MBまで、4,000万画素まで）です。
- **安全のための制限**: 登録した端末でログインしているときだけ使えます。書き込みは、同じサイトの画面から、CSRFトークンつきのものだけ受け付けます。ページに書かれたスクリプト（インライン、外部、コンポーネントのJavaScript、アップロードしたJS）は、管理者の権限で動かさないため、この画面では動きません。JavaScriptで表示が変わる部分は、プレビューや公開サイトで確認してください。
- **無料プランと長いページ**: 入力中の反映は、ほとんどブラウザの中で行うので、WorkerのCPU時間もリクエストも使いません。`{{…}}` タグ・サイト内リンク・画像を含むブロックを直すときなどは、サーバーで本文全体を描画し直します（同時に1つだけ）。Cloudflareの無料プランでは、その描画が続くとCPU時間の上限で失敗することがあります。試験では、本文2万字までは失敗せず、3万〜4万字では、続けて描画すると一部が失敗しました。失敗すると、パネルに「ページに反映できませんでした」と出ますが、保存はできます。開いているだけでは、サーバーに問い合わせません。

### プレビュー

- ページ編集画面のプレビューは、**編集中の内容**（保存していない内容も、新規ページも）を管理画面で新しいタブに開きます。ボタンの横に「編集中の内容を表示します（保存はされません）。」と出ます。保存はされず、表示は今までどおり隔離されます（管理画面のオリジンでスクリプトは動きません）。編集中の内容は、30分だけサーバーに一時保存され（1人4件まで、本人だけが開けます）、その後に消えます。ページ一覧には、プレビューの代わりに公開サイトを開く地球のアイコンがあります（PHP版と同じ）。
- HTMLを出すページ（HTML、HTML + Markdown）は `/preview/ID` で開きます。Markdownだけのページ・データ形式・mikanBox DBは `/admin?page_preview=ID` で、実際に出る中身を文字コードUTF-8のテキストとして表示します。
- 下書き・承認待ちのページは非公開で、ログインした編集者だけがプレビューできます。公開前の画像もプレビューで表示できます。

### ページのURL

ページIDを `test/index` とすると、`/test/index.html`、`/test/index/`、`/test/`、`/test` から表示できます（ビルドが必要です）。`test` 自体のページもある場合は、そちらを優先します。

下書き・承認待ちのページは、公開ページのPOST_MD・ナビ・フィード・APIから読み出せません。

### 出力形式（Cloud版の配信）

出力形式（HTML、HTML + Markdown、Markdown、JSON・XML・CSV・テキスト・JavaScript・CSS、mikanBox DB）の考え方・タグの扱い・URLの規則は、PHP版と同じです。[出力形式](https://yoshihiko.com/mikanbox/help_ja.html#output-formats)を参照してください。Cloud版は公開サイトを静的ファイルだけで配信するため、次のように出します（どれもビルドが必要です）。

| 出力形式 | 配信先に置くファイル | `/ID`・`/ID/` で開くもの |
| :--- | :--- | :--- |
| HTML | `/ID.html` | HTML（URL別名） |
| HTML + Markdown | `/ID.html` と `/ID.md` | HTML（URL別名は増えません） |
| Markdown | `/ID.md` | Markdown（URL別名の行き先を `.md` にします） |
| データ形式 | `/ID.拡張子`（例 `/news-list.json`） | 404 |
| mikanBox DB | `/api/ID.json` | 404（`/api/ID` は `/api/ID.json` の別名） |

- **URL別名の上限**: `/ID`・`/ID/` の別名は、Cloudflareの `_redirects` の上限（2,000件）に数えます。Markdownだけのページは行き先が変わるだけで、件数は増えません。データ形式は別名を作りません。
- **Content-Type**: ファイルごとに、`text/markdown; charset=utf-8`、`application/json; charset=utf-8` などを付けて配信します。Cloudflareは拡張子から種類を決めると、JSONとXMLに文字コードを付けないため、公開されているJSON・XMLのデータファイルと `/api/ID.json`・`/api/ID` には、`_headers` にファイルごとの指定を自動で書き足します（作者の作業はありません。`_headers` の規則は合計100件までなので、それを超えた分は拡張子による種類のままになります）。すべて `X-Content-Type-Options: nosniff` 付きです。
- **mikanBox DB**: `/api/ID.json` が実体です。従来の `/api/ID` も同じJSONを返します。下書きにすると、次のビルドで配信先から取り除きます。
- **`{{PAGE_URL:ID}}`**: データ形式・mikanBox DBのページの `?v=` は、ビルドで作ったファイルのハッシュです。プレビューでは本文のハッシュです。
- **`EXT_MD`**: Markdown版・データ形式でも使えません（何も出しません）。
- **ナビゲーション**: Cloud版の一覧（`NAV_LINKS`・`NAV_CARDS`・`@same`）は、公開中のページだけを出します（承認待ちのページは出しません）。
- **ビジュアル編集**: HTMLを出さないページ（Markdownだけ、データ形式、mikanBox DB）では使えません。ボタンはグレーになります。

### JavaScript

ページ・コンポーネントのJavaScriptは、管理者が書いたコードとして公開ページで実行されます。コンポーネントのJavaScriptは、使用するページのHTMLに埋め込まれます。単独で配信するJSはメディアに置きます。

内部動作の詳細は[詳細リファレンス（ページ操作）](https://github.com/yoshihik0/mikanBox-cloud/blob/HEAD/docs/reference_ja.md#ページ操作)を参照してください。

## サイト

共通の設定は[サイト](https://yoshihiko.com/mikanbox/help_ja.html#site)を参照してください。

### 保存容量

ページ・履歴・設定はD1データベースに、メディア（画像と、アップロードしたJS・CSS）のファイルは公開サイトに保存します。D1には、メディアの名前・大きさなどの情報だけを残します。Cloudflareで支払い方法を登録しなくても、無料枠の範囲で使えます。

- サイト画面の「保存容量」に、D1データベースの使用量を表示します。450 MBを超えると、注意を表示します。
- メディアは、1ファイル10 MB・10,000ファイルまでです（Cloudflareの無料プランでは、公開サイトは1ファイル25 MiB・20,000ファイルまで）。ファイル数が上限の90%を超えると、メディアの画面に注意を表示します。
- 公開サイトが、メディアの唯一の置き場です。データ移行・インポートツールの「書き出し」（JSONと画像）で、定期的に保存してください。

参考: [D1の制限](https://developers.cloudflare.com/d1/platform/limits/)、[Workersの制限](https://developers.cloudflare.com/workers/platform/limits/)。

### 最近の操作記録

サイト画面の「最近の操作記録」に、MCPの有効・停止とキーの発行、ページの公開状態の変更、端末の登録・停止とコードの発行、ログインの失敗、ユーザーの削除、データの復元を、直近50件表示します（PHP版と同じ項目と表示です）。記録は200件を上限に、古いものから消えます。IPアドレスは一部を伏せます。

### AIから管理する（MCP）

MCPに対応したAIから、ページ・コンポーネント・画像を直接読み書きできます。

#### 接続する

1. 管理画面のサイト設定で、Cloud専用のAPIキーを生成します。
2. AIの接続設定に、管理用のアドレス `/mcp` を登録し、APIキーを `Authorization: Bearer` か `X-API-Key` ヘッダーで渡します。

MCPの `upload_media` で送ったファイルも、すぐに公開サイトへ置きます（サイトを一度も公開していないときや、Cloudflareがほかのファイルの送り直しを求めたときは、管理画面でビルドするよう案内します）。

「MCP を有効にする」のチェックを外して保存すると、キーを残したまま、管理用MCPへの接続をすべて断ります（PHP版と同じです）。現在のキーが最後に使われた日時も表示します（1時間に1回だけ記録します）。

APIキーはサイトの管理操作権限を持つため、公開しないでください。

#### できること

- ページ・コンポーネントの一覧、取得、作成、更新、削除
- 履歴の取得、サイト設定の取得（APIキー・認証情報は返しません。管理メモは認証済みのAIも読めます）
- AI指示書（DESIGN.mdなど）の一覧、取得、更新（`get_ai_context` の最後には、出力形式の使い方を説明する組み込みの項目 `mikanbox-output-formats` が付きます）
- ページの結果の確認（`preview_page`。保存しません）
- 画像のアップロード
- 静的HTMLの生成（`build_ssg`）。生成のみで、公開側への配信は管理画面のビルドで行います。

使い方のポイントは次のとおりです。

- 接続したら、最初に `get_site_info`、続けて `get_ai_context` を呼びます。書き込みの前には、`get_site_info` で接続先のサイトIDを確認してください。`get_site_info` の `version` が前回と違うときは製品が更新されています。ツールの一覧と `get_ai_context` を読み直してください。
- `preview_page`（読み取り専用）で、保存や公開の前にページの結果を確かめられます。IDだけなら保存済みのページ、本文などの項目を渡すと保存せずにその内容で描画します（新しいIDでも使えます）。出力形式（HTML・Markdown版・データ形式・mikanBox DB）のとおりの結果が返ります。
- 更新は、指定しなかったフィールドをそのまま保持します。
- 編集には、URLのディレクトリ省略ではなく、正確なページIDを指定します。
- 画像のアップロードは、JPEG・PNG・GIF・WebP・SVGの10 MBまでです。同名のファイルは上書きせず、エラーになります。大きな画像は、通常の管理画面からのアップロードも使ってください。音声・動画はアップロードできません。

ツールの一覧や詳細は[詳細リファレンス（MCPとヘルプ）](https://github.com/yoshihik0/mikanBox-cloud/blob/HEAD/docs/reference_ja.md#mcpとヘルプ)を参照してください。

### Cloud版のヘルプをAIに読ませる

公開の `/public-mcp` は、APIキー不要・読み取り専用です。AIがこのヘルプを検索して読めるようにします（`search_help`、`get_help_section`、`get_product_info`、`get_agent_instructions`）。人向けのヘルプは `/public-help.html?language=ja` で読めます。

対応するブラウザやAIでは、公開ページと管理画面からヘルプを使えます。すべてのブラウザ・AIクライアントで使えるとは限りません。

## データ移行・インポートツール

共通の操作は[データ移行・インポートツール](https://yoshihiko.com/mikanbox/help_ja.html#data-migration)を参照してください。

### 書き出しと読み込み

「書き出し」「読み込み」「公開サイトの書き出し」は、PHP版と同じ画面・同じ動きです（[データ移行・インポートツール](https://yoshihiko.com/mikanbox/help_ja.html#data-migration)）。保存したZIPは、PHP版のサイトにも読み込めます。Cloud版で違うのは次の点です。

- **書き出し**：画像は、ブラウザが公開サイトから1つずつ読んで、ZIPにまとめます。公開サイトのファイルが記録と違うときは止まるので、サイトをビルドしてから、もう一度保存してください。「データベース」を選ぶと、D1データベース全体（ページ・設定・アカウント・メディアの情報）を、1つのSQLファイルに保存します。画像のファイルそのものは含みません。戻すには、`wrangler d1 execute` でCloudflareのデータベースへ読み込ませます。「データベース」は、D1編集権限を持つトークンをCloudflare公開設定に登録すると選べます。
- **読み込み**：画像を読み込むと、そのまま公開サイトへ送ります（サイト全体をビルドします）。送れなかったときは、同じファイルを「同じIDのものを上書きする」で、もう一度読み込んでください。ページだけを読み込んだときは、PHP版と同じく、サイトをビルドすると公開ページに反映されます。
- **公開サイトの書き出し**：今公開しているファイルを、ブラウザが公開サイトから読んでまとめます。
- 大きなサイトでは時間がかかります。終わるまで画面を開いたままにしてください。

### D1の指定時刻への復元

データベースを、Cloudflareが保持している期間内（無料プランは直近7日）の指定時刻に戻します。公開サイトは変わらないので、復元にはサイトをビルドしてください。

### 更新の途中で失敗した場合

プログラムの更新は、ビルド、未適用のデータベース移行、管理用Workerの配置の順に進みます。ビルドに失敗したときは、データベースは変わりません。

## デザイン

共通の操作は[デザイン](https://yoshihiko.com/mikanbox/help_ja.html#design-mgmt)を参照してください。

### コンポーネントの絞り込み

コンポーネント一覧の「AIに聞く」の右側に、絞り込みのセレクタがあります（PHP版と共通です）。「すべて」「選択中のカテゴリ」「ページ」「パーツ」「AI指示」「標準コンポーネント」から選べます。

- **標準コンポーネント：** IDの先頭が `_` のものです。通常の新規作成・複製では付けません。標準として扱いたいときに付けます。
- **選択中のカテゴリ：** 管理画面上部で選んだカテゴリを使い、画像と同じようにIDの接頭辞で判定します。たとえば `apps_header` は `apps` カテゴリに含まれます。カテゴリを選んでいないときは絞り込みません。

### CSSとheadの設定

ページとコンポーネントのCSSは、自動的に挿入されます（PHP版と共通です）。挿入位置を指定したいときは `{{HEAD_CSS}}` を書きます。複数あれば最初の1つだけに出力し、残りは取り除きます。省略すると `</head>` の直前に入ります。

デザインコンポーネントの「なし」、不足するhead情報の補完、サイト共通の計測ID・計測コード（headとbody開始直後）、ページ単位の計測除外に対応しています。詳しくは共通ヘルプを参照してください。

## メディア

共通の操作は[メディア](https://yoshihiko.com/mikanbox/help_ja.html#media-mgmt)を参照してください。

### 画像アップロードと制限

メディア欄で画像を選ぶか、画面へドラッグしてアップロードできます。選んだファイルは、まず公開サイトへ送られ、公開サイトにあることを確かめてから、メディアの一覧に載ります（下書きのページだけで使う画像も公開されます。公開してはいけない画像はアップロードしないでください）。送れなかった場合は、何も登録されません。

ファイル名をクリックするとコピーできます。本文には `![説明](ファイル名.png)` または `{{IMAGE:ファイル名.png}}` と書きます。見出しの行にある種類の絞り込みとファイル名検索、カテゴリー絞り込み、ページ送りが使えます。

- 1ファイル **10 MB** 以下、最大 **10,000ファイル**です。
- 形式は **JPEG / PNG / GIF / WebP / SVG** と、UTF-8の **JS / CSS**。拡張子と先頭の形式情報を確認します。動画・音声には対応していません。
- 同名ファイルは上書きしません。
- サイトを一度も公開していないときは、最初のアップロードでサイト全体をビルドして公開します。

### 画像の加工

アップロード時に、長辺2,000pxへの縮小を既定で選べます。JPEG・PNG・WebPのリサイズとWebP変換はブラウザで行い、処理後の画像を公開サイトへ送ってから、一覧の画像を置き換えます。WebP変換は、押すと確認を出してから行います。

### 名前変更とWebP変換

名前変更は、本文・CSS・JavaScript・OGP画像・コンポーネントの参照先も更新します。WebPへの名前変更でも同じです。

- 拡張子の変更と、同名での上書きはできません。
- メモと過去の履歴は書き換えません。参照を更新したページには、履歴を保存します。
- 同時編集や競合があれば、画像を含む操作全体を中止します。
- 変更した静的ページは、再ビルドが必要です。コンポーネントに参照があれば、全静的HTMLを再ビルドしてください。
- 外部サイトや独自JavaScriptで組み立てたURLは更新しません。

操作後も、可能な範囲でメディア一覧のスクロール位置を保ちます。各画像の操作は、PHP版と同じ「リサイズ▼」「名前変更▼」「WebP に変換」の順です。WebP変換はJPEG・PNGだけに表示します。上部のカテゴリ選択は、ファイル名の接頭辞でメディアを絞り込み、`g_` で始まる共通画像も表示します。アップロードには、選択カテゴリの接頭辞が付きます。

### 公開サイトのメディア

- 名前変更・WebP変換をした画像は、次のビルドまで元の名前でも公開サイトに残ります（公開済みのページが、元の名前で参照しているためです）。次のビルドで、新しい名前だけになります。元の名前は、それまで別の画像に使えません。
- 公開済みの画像を削除すると、先に公開サイトから取り下げます。Cloudflare公開設定の接続が必要です。
- 管理画面のプレビューでも、画像は公開サイトのものを表示します。管理画面で画像のアドレス（`/media/…`）を開くと、公開サイトへ移ります。
- 静的ビルドでは、ローカルの画像に `width`・`height` と読み込みのヒントを自動で付けます（PHP版と同じです）。

### JS・CSSライブラリ

メディアでブラウザー用の `.js`・`.css` をアップロードできます。UTF-8の空でないテキスト、1ファイル10 MB以下を受け付け、元のコードをそのまま、画像と同じくすぐに公開サイトへ置きます。管理画面では実行しません。カテゴリ接頭辞と画像変換は適用しません。公開URLは `/media/ファイル名` です。

- **データ移行・インポートツールを、PHP版と同じ形にしました。** 「書き出し」は、保存する内容（JSONと画像／JSONだけ／画像だけ／データベース）を選んでダウンロードします。「読み込み」は、ファイルを選ぶと中身を見分けて、JSONと画像を読み込みます（ZIP・WordPressのXML・画像のファイル）。同じものがあるときは、「上書きしない」「同じIDのものを上書きする」「丸ごと置き換える」から選びます。保存したZIPは、3つの版で同じ形です。
- これまでの「データ一括ダウンロード（JSON）」「メディア一括ダウンロード」「フルバックアップ」「バックアップファイルの復元」「コンテンツパッケージ（ZIP）インポート」「WordPressデータ移行」は、この2つにまとめました。0.13.2で保存したフルバックアップのZIPも、「読み込み」で読み込めます。
- ユーザーは、書き出しにも読み込みにも含めません（ユーザーと端末は「端末とユーザー」で管理します）。
- **公開サイトの書き出し**に「相対パスにする」を付けました。
- 読み込みのあと、画面は読み込み直しません。
