# 🍊mikanBox Cloudflare版 開発マニュアル <small class="manual-version">v0.6.0</small>

この版は開発中です。SQLite版のUIと機能を基準に移植していますが、まだ完全互換ではありません。既存版への変更は明示的に依頼された共通設定の修正に限り、既存データや公式サーバーは変更していません。

以下の「v0.4.3の管理画面操作」が新しい仕様です。管理画面からの自動配信とD1操作は専用Cloudflareトークンの設定が必要で、未設定の環境では実行できません。専用トークンでの実接続とUI全体の完全一致は引き続き未検証です。

2026-10-04の明示的な依頼により、サイト共通設定の配置・入力欄・説明、SSG説明の太さ、サイトURLの未設定時の扱いを3版共通で修正しました。元の保護用ハッシュ一覧は保持し、許可された変更は別の一覧で記録します。サイト環境はAIへの用途の目印で、アクセスや操作を制限しません。サイトURLはAIの識別情報で、空欄ならトップページの場所を使い、SSGの出力先とは分けます。

管理画面はCloud版自身の現在・最新バージョンを比較します。PHP版のリリース番号は使いません。本公開先では `/mikanbox/cloud-release.json` のCloud専用リリース情報を確認します。`CLOUD_RELEASE_MANIFEST_URL` を設定していない別の環境では「Cloud版のリリース情報は未公開」と表示します。HTTPSのJSON（`edition: "cloud"`、`version: "0.5.0"`、任意のHTTPS `url`）を読み取ります。1クリックでのコード更新は未実装で、新しいWorkerの公開と必要なDB更新を行います。再構築による静的ファイル配信の更新とは別です。

メディア画面では画像変換の補足と最大ファイルサイズの行を省き、ページ内での利用方法を案内します。Markdownはファイル名だけ、HTMLは `media/ファイル名` を標準とします。画像の従来の `images/ファイル名` も利用できます。

## 配信モードと取り下げ（開発版 v0.6.0）

配信モードは設置時に決まります。公開用 `wrangler.production.json` の `vars` にある `STATIC_DELIVERY` が、`wrangler deploy` のときにWorkerの環境変数として適用されます。管理画面からは変更できません。Cloudflareのダッシュボードでも Worker の環境変数として書き換えられますが、次の `wrangler deploy` で設定ファイルの値に戻ります。配信更新はそのときのバージョンのバインディングをそのまま引き継ぎます。

- **静的配信**（`STATIC_DELIVERY` が `true`）: 公開済みのページと画像を配信先の静的ファイルから配信します。閲覧でWorkerもD1も動かないため、Workerの1日あたりのリクエスト数とD1の読み出し行数を使いません。
- **Worker配信**（既定）: 静的ページもWorkerがD1の生成済みHTMLから配信します。閲覧でWorkerとD1の利用枠を使います。配信先がないので、サイト生成はHTMLの再構築だけを行います。

現在どちらで動いているかは、サイト画面の「サイト生成」に表示します。

ページごとの静的・動的の選択は、これとは別です。公開方法を「静的」にしたページはサイト生成でHTMLを作り、「動的」にしたページはアクセスごとに生成します。動的ページはどちらの配信モードでもWorkerが処理します。

### 取り下げ

静的配信では、配信先に出したファイルはWorkerを通らないため、元データを消しても配信先に残ります。配信先から取り除くことを取り下げと呼びます。

ページの取り下げはサイト生成で行います。非公開にしたページと削除したページは、サイト生成のときに配信先から取り除き、URL別名も取り消します。**サイト生成までは読める状態が続きます。** 公開をやめたら、サイト生成も行ってください。

画像の取り下げはメディア画面の操作が自動で行います。下記の「画像の静的配信」を参照してください。

Worker配信では配信先がないため、取り下げの操作はありません。非公開・削除はすぐに反映されます。

## 公開と管理の分離（試作）

`CLOUDFLARE_PUBLIC_WORKER_NAME`（公開用のWorkerの名前）と `PUBLIC_SITE_URL`（公開サイトのURL）を設定すると、公開ページを別のWorkerに出力します。公開用のWorkerは静的ファイルだけで、プログラムは動きません。管理画面とMCPは今のWorkerに残ります。設定しなければ、今までどおり1つのWorkerで動きます。

- 管理側のアドレスでは、ログインしていない人にはページ・画像・コンポーネントのJS・サイトマップを出しません。検索エンジンにも載せません（`X-Robots-Tag: noindex`）。
- ログインした端末で管理側の `/about` などを開くと、プレビュー（`/preview/about`）に移ります。プレビューにはCSPの `sandbox` を付け、ページのJSから管理画面に手が届かないようにします。プレビューの中では、ページのJSからCookieや `localStorage` を使えません。
- 公開ページ、サイトマップ、RSSには `PUBLIC_SITE_URL` を使い、管理側のアドレスを出しません。サイトマップ・RSS・DBページのJSON（`/api/ページID`）は、公開側にファイルとして出します。
- 公開側への出力は、変わったファイルだけを送ります。ページのハッシュはビルドのときに保存します。
- サイト内検索とAIの質問ボックスは、公開側では動きません。検索ページはサイトマップとRSSに載せません。
- 404ページは、分離するかどうかにかかわらず、PHP版と同じくサイトマップとRSSに載せません。

## 画像の静的配信（開発版 v0.6.0）

配信更新に画像を含めます。保存しているファイルは、どのページからも参照されていないものも含めて全件公開します。動的ページも静的ページと同じ `/media/ファイル名` を読むためです。

公開済みの画像はStatic Assetsから配信し、WorkerもD1もR2も通りません。閲覧はWorkerの1日あたりのリクエスト数とD1の読み出し行数を消費しません。まだ公開していない画像は静的ファイルが存在しないため、Workerへ引き継がれてD1/R2から配信します。アップロードした画像は配信更新を待たずに、下書きのプレビューでも動的ページでもすぐ表示されます。

配信先の上限は1バージョンあたり20,000ファイル、1ファイル25 MiBです。画像は1ファイル10 MB・最大10,000件のため、ページとコンポーネントを合わせても上限内に収まります。

静的ファイルはWorkerを通らないため、公開済みの画像は配信先から取り下げてからでないと削除・名前変更できません。メディア画面の削除・名前変更は、取り下げ（その画像を除いた配信更新）を自動で実行し、完了後に本来の操作を行います。操作は1回で、ページの再構築は行いません。取り下げに失敗した場合は元のファイルを残して中止します。

同じファイル名での差し替えは公開URLが変わらないため取り下げは不要です。ただし公開済みの画像は、配信更新を行うまで配信先に古い内容が残ります。

静的配信を使わない構成では、従来どおりWorkerがすべての画像を配信します。

## JS・CSSライブラリ（開発版 v0.5.1）

メディアでブラウザー用の `.js`・`.css` をアップロードできます。UTF-8の空でないテキスト、1ファイル10 MB以下を受け付け、元のコードをそのまま保存します。管理画面では実行せず、カードからURLや読み込みタグをコピーして、ページ本文・コンポーネントのHTMLに貼ります。アップロードだけでは自動挿入しません。信頼できる管理者・APIキーから、提供元を確認したコードをアップロードしてください。形式検査は安全性を保証しません。

カテゴリ接頭辞と画像変換は適用しません。種類による絞り込み、同じ拡張子のままの名前変更、削除に対応します。同名ファイルは上書きせず、別名でのアップロードを求めます。フォルダ階層をまとめてアップロードする機能はありません。

保存先はメディア設定のD1/R2に従い、公開URLは `/media/ファイル名` です。完全JSONバックアップと復元、D1からR2への移行にも含まれます。コード欄の内容はD1に保存します。静的ページ公開では配信先の静的ファイルから配信します。下記の「画像の静的配信」を参照してください。別サーバー向けの静的ZIPにはHTMLから参照するファイルを同梱します。

## D1からR2への移行（開発版 v0.5.0）

最初はR2を有効にせずD1で利用できます。サイト画面の「メディアの保存先」で現在の保存先と使用量を確認し、「D1からR2へ移行」を実行します。これは画像の保存先の切り替えで、ページ・設定・ユーザーなどはD1に残ります。

R2の準備にはCloudflareで支払い方法を登録してR2を有効にする必要があります。無料枠内でも登録が必要です。バケットを作成し、WorkerのR2接続名を `MEDIA` にします。ローカルのWrangler設定にはテスト用接続がありますが、公開用設定にR2接続は追加していません。公開用 `wrangler.production.json` に次の設定を追加し、実際のバケット名でコードをデプロイしてください。この準備だけでは保存先は切り替わりません。

```json
"r2_buckets": [{"binding": "MEDIA", "bucket_name": "実際のバケット名"}]
```

確認の画面で移行を開始します。1画像ずつコピーし、チェックサムとR2への保存結果を検証します。移行中はD1の原本を表示し、画像の追加・変更・削除を止めます。画面を閉じても、同じメニューから再開・中止できます。全件の確認が完了するとD1の画像データを除去し、R2の参照へ一括で切り替えます。未完了・失敗・中止ではD1の原本を保持します。成功後にD1へ戻すメニューはありません。移行前に完全JSONバックアップを保存してください。画像URLと本文中のファイル名は変わりません。

D1の画像上限は400 MBです。D1 Freeは1DB500 MB、Paidは1DB10 GBまでで、プラン変更は別途必要です。R2へ移行すると画像合計400 MBの制限を外し、1画像10 MB・10,000件の制限を維持します。R2 Standardの無料枠はアカウント全体で月間10 GB-month・書込み系100万回・読出し系1,000万回です。容量の上限ではなく超過分は課金されます。

サイト画面にはD1のDB使用量と、管理対象のR2容量（一時画像・保持画像を含む）を表示し、無料枠の80%程度で注意を表示します。他サイトや管理外のR2オブジェクトは含みません。実際のアカウント全体の使用量・リクエスト数・料金はCloudflareで確認してください。料金通知は利用を停止する機能ではありません。D1から画像を削除してもDBの確保済み領域がすぐ小さくなるとは限りません。

R2の書き換えは新しい一意のオブジェクトへ保存してからD1の参照を切り替えます。「不要な一時画像を整理」で、使用中・移行中・復元中の画像を除き、24時間以上保持した未使用画像を最大20件ずつ削除できます。完全JSONバックアップは画像も含み、D1・R2のどちらの保存先にも復元できます。復元先の保存先設定は維持します。D1復元は画像400 MB・現在と一時画像の合計450 MBまで、R2復元は原本と一時画像の両方を使用量に含めます。D1 Time TravelとSQL書き出しにはR2の画像実体が含まれず、古い参照先が整理済みの場合は戻せません。R2では完全JSONバックアップを使用してください。

画像は保存先にかかわらず公開URLが `/media/ファイル名` です。公開済みの画像はStatic Assetsから配信し、未公開の画像はWorkerがD1/R2から配信します。生成済みのページHTMLもStatic Assetsから直接配信します。名前変更・WebP変換で更新した本文や部品を公開済みのHTMLへ反映するには、通常の再構築・配信更新が必要です。詳細は下記の「画像の静的配信」を参照してください。

支払い方法を登録せず、Cloudflare公式のローカルWorker・D1・R2を組み合わせて確認するには、Cloudフォルダで `node scripts/test-r2-local.mjs` を実行します。専用の一時データを作成し、移行・中止・画像操作・バックアップ復元の15項目を検証して削除します。既存のローカルデータや実サービスには接続しません。これはローカルでの結合テストで、実際のR2への接続権限・通信・課金を確認するものではありません。結果は `artifacts/r2-local-system-test.json` に保存します。

参考: [D1の制限](https://developers.cloudflare.com/d1/platform/limits/)、[R2の料金](https://developers.cloudflare.com/r2/pricing/)、[R2の初期設定](https://developers.cloudflare.com/r2/get-started/)、[料金と使用量](https://developers.cloudflare.com/billing/understand/usage-based-billing/)。


## v0.4.3の管理画面操作

再構築ボタンで公開HTMLを生成し、配信も更新します。非公開・削除済みのページは同時に配信先から削除します。再構築までは以前の公開ファイルが残ります。画像はアップロード完了後に配信を更新し、削除・名前変更では旧画像の取り下げも管理画面で行います。ブラウザから処理を小分けに進めるので、完了まで画面を開いておいてください。Workers編集権限を持つCloud版専用トークンが必要です。サイト設定で管理者パスワードを確認して入力し、暗号化して保存します。トークンは再表示せず、JSONバックアップにも含めません。期限付きWranglerログインをWorkerへコピーしません。MCPの従来のbuild_ssgはHTML生成のみで、配信更新は管理画面か従来の公開コマンドが必要です。

画像のアップロードでは長辺2,000pxへの縮小を既定で選べます。JPEG・PNG・WebPのリサイズとWebP変換はブラウザで実行し、原本を処理後の画像に置き換えます。WebPへの名前変更ではページ・コンポーネントの参照も更新し、ページ履歴を残します。GIF・SVGのアップロードは原本のまま保存します。変換は16,000px以下かつ4,000万画素以下が対象です。

### 端末認証（試作）

パスワードはありません。管理画面に入れるのは、登録した端末（ブラウザ）だけです。端末のCookieには乱数のトークンを入れ、D1にはそのハッシュだけを保存します。

- **最初の端末**：ログイン画面で `SETUP_TOKEN`・ユーザー名・表示名・端末の名前を入力します。使った `SETUP_TOKEN` は二度と使えません。
- **端末の追加**：登録済みの端末で、サイト →「端末とユーザー」→「端末を追加する」から追加用のコードを出し、新しい端末のログイン画面で入力します。コードは3時間有効で、1回だけ使えます。ほかの人を招くときは「ほかの人を招く」でユーザー名と表示名を決めてコードを出します。コードの入力を5回間違えると、15分間入力できません。
- **端末の期限**：最後に使ってから30日（標準）・90日・180日で切れます。使うたびに延びます。
- **端末を止める**：「端末とユーザー」の一覧から止めます。コードで追加してから3日以内の端末は、ほかの端末を止める、ほかのユーザーを削除・変更する、ユーザーごとの復元、D1の時刻指定の復元ができません。`SETUP_TOKEN` で登録した端末には、この制限はありません。ユーザーを削除すると、そのユーザーの端末と未使用のコードも止まります。新しい端末が登録されると、ほかの端末で管理画面を開いたときに知らせます。
- **復旧**：すべての端末を失ったときは、`wrangler secret put SETUP_TOKEN` で新しい値を設定し、ログイン画面の「復旧」から既存のユーザー名で登録します。登録済みの端末はすべて止まり、未使用のコードとMCPキーも消えます。
- ブラウザのCookieを消す、別のブラウザに変える、プライベートモードで開くことは、端末を失うのと同じです。端末の管理（画面ロック、紛失時の対応）は利用者の責任です。

### JSONバックアップと復元

サイト設定の「データ移行・インポートツール」専用ページで、設定・すべてのページ・コンポーネント・履歴・静的HTML・ユーザー・画像原本を1つのJSONファイルでダウンロードし、そのファイルを選んで復元できます。SQLiteファイルではありません。画像は500KB単位で転送します。大容量では時間とブラウザのメモリを使うため、画面を閉じないでください。バックアップには非公開内容・APIキー・認証ハッシュが含まれます。安全に保管してください。設定などのメタデータは20MBまでです。

保存と復元は確認の画面だけで行います。通常の復元は現在のサイトID・APIキー・ユーザー・Cloudflare接続を維持します。「ユーザーも復元」を選ぶとユーザーも復元します。バックアップにないユーザーの端末は止まります。復元後に再構築してください。復元データを一時領域に保存し、欠損や同時編集があれば元のデータを保持して中止します。D1では現在と復元分・他の復元処理の一時画像の合計450MB以内が必要です。R2では原本と復元用の一時画像をR2に保存します。D1の実際の空き容量によっては、それより少なくても復元できません。

### D1自体のバックアップ

D1のSQL書き出しと、指定時点にDB全体を戻すTime Travelは別の項目です。D1編集権限を持つ専用トークンが必要です。無料プランのTime Travelは直近7日間で、D1の画像原本・ユーザー・保存済み接続設定もその時点に戻りますが、R2の画像実体は含まれません。SQL書き出し中はD1が一時的に利用できず、動的処理が停止することがあります。完了まで画面を開いてください。Time Travelは配信中の静的ファイルを戻しません。復元後の再構築と、古い時点へ戻した場合のコード・DB構造の互換性確認が必要です。SQLファイルのアップロードによるD1復元は管理画面には実装していません。

大量の配信更新やバックアップはD1の読出し・書込みとWorkerリクエストを消費します。静的配信が無料でも更新処理は無制限ではなく、アカウント全体の無料枠を超えると中断します。最大20,000ファイルを毎日更新できるという保証ではありません。

## 構成

管理画面の左ナビゲーションのロゴは、flat版と同じ2行の配置で「mikanBox」「cloud」と表示します。

Cloudflare Workersで実行し、ページ・設定などはD1に保存します。画像は初期状態でD1を使い、画像の保存先メニューからR2へ移行できます。上記のv0.5.0仕様を参照してください。

CSS・AI質問用JavaScript・翻訳は共有正本からCloud版へコピーしたものを使います。画面テンプレートと主要操作のJavaScriptはCloud版専用です。共有CSSだけで画面全体が一致するわけではありません。

## ローカル開発

`mikanBox-cloud/` で次を実行します。

```sh
npm ci
npm run prepare:local
npm run db:local
npm run dev
```

`http://localhost:8787/admin` を開き、初期設定トークン・ユーザーID・表示名・端末の名前を入力します。初期設定トークンは、このフォルダ内の `.dev.vars` の `SETUP_TOKEN` です。同じトークンは一度だけ使えます。`.dev.vars` は公開・コミットしません。

ローカルのD1・R2は `.wrangler/state/` に保存されます。DB接続設定のIDはローカル用の仮値で、本番接続先を指定していません。ローカル試験用には別の `.wrangler/smoke-state/` を使います。検証用データを既存版から読み込む処理はありません。

```sh
npm run check
npm test
npm run build
```

`build` は公開せずにバンドルだけを検証するdry runです。Wranglerのログは権限の問題がある場合、`WRANGLER_LOG_PATH=.wrangler/logs` を指定してこのフォルダ内に保存してください。

## 標準コンテンツ

初回設定時はSQLite版と同じ標準データを選択言語で取り込みます。日本語・英語それぞれページ8件（ホーム、404、検索、各見本、DB見本）とコンポーネント11件（レイアウト、ヘッダー、フッター、カード、検索、AI指示の見本など）です。正本は `../shared/import/`。Cloud内の `npm run sync:defaults` でデータのコピーだけを更新できます。共有元と既存PHP版は変更しません。

既存ページ・コンポーネントは上書きしません。今回の公開サイトでは、公開時に置いた仮トップページが未編集の場合に限り標準ホームへ置き換えます。設定・アカウント・秘密・以前のCloud版のデータはこの取り込みに含めません。

標準検索フォームの `/index.php?page=search&q=...` と `/search?q=...` に対応します。検索結果は公開ページだけを対象にし、下書き・承認待ち・DBは含めません。AI指示の `DESIGN_sample.md` / `DESIGN.md` を編集できます。AI質問の `{{AI_QUESTION}}` と `{{AI_QUESTION:セクションID}}` に対応します。外部取得の `EXT_MD` は未対応です。見本内の画像は同梱されていません。メディア画面から必要な画像をアップロードできます。

## 現在の操作

- ページの一覧、検索、カテゴリ絞り込み、ページ送り、新規作成、編集、削除。
- 下書き・承認待ち・公開（動的）・公開（HTML）・DBの状態を区別。
- メモ、Markdown/HTML入力、ページCSS/JavaScript、SEO情報、ラッパー選択。
- 編集時の履歴保存、直近50件の履歴選択、同時編集ロック、古い編集の上書き防止。
- 承認待ちページのトークン付き共有プレビュー。管理者は下書きもプレビュー可能。
- デザインコンポーネントの作成・編集・削除、パーツ/ページ/AI指示の区別、メモ、CSS、JavaScript。
- サイト設定、言語、メモ、端末の追加・停止、ユーザーの招待・削除。
- ユーザーID・表示名の変更。登録済みの端末は、新しいユーザーIDのまま使えます。
- R2なしでも画像アップロード・配信・削除。最大10 MB、同名ファイルは上書きしません。
- JSONコンテンツとメディアのZIPダウンロード。完全なD1バックアップや復元ではありません。
- 公開HTMLのD1スナップショット生成。ビルド後は次のビルドまで保存済みHTMLを表示し、下書きへ変更したページは公開しません。
- ページ・部品・検索・ナビ・フィード・データバックアップの一覧取得はまとめて行い、件数ごとの個別読出しを避けます。静的ビルドもコンテンツをまとめて読み込みます。データ量やCPU時間のプラットフォーム上限は残ります。
- カテゴリー削除は候補設定だけでなく各ページのカテゴリーも削除し、履歴を保存します。対象ページが編集中・更新済みの場合は全体を中止します。

ページと設定は取得時の内容を確認して保存し、競合した場合はエラーにして再読み込みを求めます。APIキー再発行を古い設定保存で巻き戻さないようにしています。ユーザー削除・パスワード変更は既存セッションを無効にし、同じIDで作り直しても旧セッションは使えません。

コンポーネントの直接JavaScript URLは `/component-js/ID.js`。ページ・コンポーネントのJavaScriptは管理者が記述するコードとして公開ページで実行されます。

ページIDを `test/index` とすると、`/test/index.html`、`/test/index/`、`/test/`、`/test` から表示できます。動的公開・静的HTML公開の両方に対応します。静的公開はビルドが必要です。`test` 自体のページもある場合はそちらを優先します。動的公開ではD1へのURLです。静的公開ではHTMLファイルと別名ルールを配信します。

DB状態のページは `/api/ID` でDATA/DATAROWを公開できます。下書き・承認待ちのページを公開ページのPOST_MD・ナビ・フィード・APIから読み出すことはできません。

## 画像アップロードと制限

メディア欄で画像を選ぶか、画面へドラッグしてアップロードできます。ファイル名をクリックするとコピーできます。本文には `![説明](ファイル名.png)` または `{{IMAGE:ファイル名.png}}` と書きます。「保存」リンクから個別にダウンロードできます。

ファイル名検索・カテゴリー絞り込み・ページ送りが使えます。表示件数はサイト設定の「メディア表示件数」に従います。カテゴリー絞り込みは、そのカテゴリーのページが参照する画像、またはカテゴリー名を接頭辞に持つ画像を対象にします。

D1構成の「名前変更」は本文・CSS・JavaScript・OGP画像・コンポーネントの参照先も更新します。拡張子変更と同名上書きはできません。メモと過去の履歴は書き換えません。参照更新するページの履歴を保存し、同時編集・競合があれば画像を含む操作全体を中止します。変更した静的ページは再ビルドが必要です。コンポーネントに参照があれば全静的HTMLを再ビルドしてください。参照データが大きすぎる場合は一括変更できません。外部サイトや独自JavaScriptで組み立てたURLまでは更新しません。

- 1画像 **10 MB**（10,000,000 bytes）以下。
- D1画像合計 **400 MB**まで。R2ではこの上限を外します。どちらも最大 **10,000ファイル**です。
- 形式は **JPEG / PNG / GIF / WebP / SVG**。拡張子と先頭の形式情報を確認します。D1構成では動画・音声アップロードは未対応です。
- 同名ファイルは上書きしません。v0.4.3では保存前にブラウザでリサイズ・WebP変換でき、処理後の画像を原本として保存します。
- メディアZIPは **合計20 MB**まで。1リクエストの読出し上限に収まる枚数も必要です（小さい画像なら約20枚、10 MB画像なら2枚）。超える場合は個別に保存してください。

D1モードの400 MBはコンテンツ・履歴・DB管理領域の余地を残す画像用上限です。R2モードには適用しません。プラットフォームの容量上限に先に達すると保存できません。

[D1 Freeの枠](https://developers.cloudflare.com/d1/platform/pricing/)は読出し500万行/日、書込み10万行/日、DB合計5 GB。[Workers Free](https://developers.cloudflare.com/workers/platform/limits/)は1日10万リクエストです。D1の画像読出しは500 KBごとに1行を読み出します。R2配信では画像メタデータとR2オブジェクトを読み出します。これらの枠は同じアカウントの他のアプリとも共有します。Freeで日次上限に達すると処理が停止し、リセット後に再開します。アプリから契約を自動変更しません。既にPaid契約の場合はその料金体系に従います。

## Cloud専用MCP

サイト画面でCloud専用のAPIキーを生成し、別ワークスペースから `/mcp` にBearerキー付きで接続します。ルートの `.mcp.json` は公式サーバー専用のままです。

現在のツールは `get_site_info`、`list_pages`、`get_page`、`create_page`、`update_page`、`delete_page`、`list_components`、`get_component`、`create_component`、`update_component`、`delete_component`、`get_revisions`、`get_settings`、`get_ai_context`、`list_ai_docs`、`get_ai_doc`、`update_ai_doc`、`upload_media`、`build_ssg`。

作成・更新はSQLite版と同じ `id` と各フィールドを直接渡す形式に対応し、従来の `id` と `data` も使えます。両形式で同じフィールドを重ねて指定しないでください。更新は未指定のフィールドを保持します。接続直後は `get_site_info`、続けて `get_ai_context` を呼びます。AI指示書IDの `.md` は省略できます。`get_settings` はAPIキー・認証情報・管理メモを返しません。編集操作には公開URLのディレクトリ省略ではなく正確なIDを指定します。

`upload_media` は `filename` と `content_base64` を渡します。JPEG・PNG・GIF・WebP・SVGの10 MBまでです。任意の `category` は英数字・`_`・`-` に限り、ファイル名の接頭辞になります。同名は上書きせずエラーです。大きな画像ではBase64通信と変換処理が増えるため、通常の管理画面アップロードも使ってください。音声・動画や重複時の連番保存はPHP版と差があります。

管理用の互換URL `/mikanBox/mcp` と `/mikanBox/mcp.php` も同じキーが必要です。管理窓口と公開ヘルプ窓口は別です。

書き込み前には `get_site_info` のCloudサイトIDを確認してください。公式サイトIDはCloud版へ引き継ぎません。Cloud APIキーはサイトの管理操作権限を持つため公開しません。

## 公開ヘルプ・WebMCP

公開の `/public-mcp` はAPIキー不要・読み取り専用です。`search_help`、`get_help_section`、`get_product_info`、`get_agent_instructions` の4つだけを提供します。管理用 `/mcp` は引き続きキー必須です。`/mikanBox/public-mcp.php` は公開窓口の互換URLです。

公開済みの `help_ja`・`help_en` ページがあればその本文を読み、なければこのCloud専用マニュアルを使います。下書き・承認待ち・DB・管理情報・AI指示書・その他のページは公開窓口から読みません。Cloud専用マニュアルを更新したら `node scripts/sync-cloud-help.mjs` で同梱コピーを更新します（check/test/buildでも自動実行）。人向けヘルプは `/public-help.html?language=ja` または `en` です。

公開ページと管理画面にWebMCP用スクリプトを読み込みます。対応するブラウザ・エージェントで4つのヘルプツールを利用できます。未対応ブラウザでは登録を省略し、通常画面やAI質問欄は利用できます。[ChromeのWebMCP API](https://developer.chrome.com/docs/ai/webmcp/imperative-api)に従う仕組みで、すべてのブラウザやAIクライアントで利用できるとは限りません。AI質問欄はCloudの公開ヘルプと公開MCPを参照し、APIキーや管理画面URLは外部AIへ渡しません。

## 静的HTMLのZIP出力

サイトの静的生成欄でビルド後、「静的ZIPを保存」を選びます。`ID.html` と `ID/index.html` の構造を選べます。`index` はトップの `index.html`、末尾が `/index` のIDはディレクトリ構造でそのまま `ディレクトリ/index.html` になります。出力先が衝突する場合はエラーにします。

ビルド済みで現在も公開HTML状態のページだけを出力し、同梱ページへのリンクと画像・部品JSの参照を相対パスにします。使用画像と公開アセットを同梱します。動的ページ・検索・APIは元の公開サイトへのリンクとして残ります。APIキー・設定・ユーザー・非公開ページは入れません。ZIP内ではWebMCPを登録せず、AI質問欄はCloudヘルプへのリンクになります。

ZIP全体は20 MBまでで、画像読出し回数にも上限があります。出力画像が不足する場合はエラーにし、途中のZIPを渡しません。任意のJavaScript内の通信処理や、文字列形式のCSS `@import` は自動変換しません。これは静的サイトの持ち出し機能で、完全なD1バックアップではありません。

## 既存版を変更しない手順

この開発作業ではCloudフォルダの中だけを編集します。`../shared/sync.sh` は既存PHP版へ書き込むため実行しません。共通ファイルを取り込むときはCloud側の `npm run sync:assets` を使います。正本の変更が必要になった場合は、既存版への影響を確認してから別の作業として扱います。

着手時の2版・共有ソース・ルート設定/マニュアルのハッシュを `.baseline/protected-files.json` に記録しました。`npm run check` はそのまま保たれていることも確認します。別の環境で使う場合は変更前に新しい基準を記録し、既存の基準を上書きして差分を隠しません。

## 残る互換性作業

SQLite版と同じ見た目・操作の目標は継続します。現段階では画面全体の一致を保証していません。

- 元のPHP画面との配置・余白・編集画面の出し入れ・AJAXの完全一致。
- PHP版の更新/復元、SQLiteファイルの入出力、移行ツール。CloudのJSON復元とは方式が異なります。
- 静的出力の追加設定、ZIP内での検索など動的機能の再現。
- 現行Markdown・CSSスコープ・全タグ構文の完全互換性。EXT_MDは外部取得の方針ができるまで無効。
- MCPの細部の戻り値・エラー・更新日時などの完全互換性、追加の運用ツール。
- 既存コンテンツの明示的な移行と本番での性能・容量検証。

## 公開ページと画像の直接配信

管理・編集・検索・MCP・APIはWorkerで実行します。生成済みの静的公開ページと公開済みの画像はStatic Assetsから直接配信します。まだ公開していない画像はWorkerがD1または移行後のR2から読み出します。

旧v0.3.0では管理画面のビルドでHTMLを保存し、作業環境で `npm run publish:static` を実行して配信先を更新していました。v0.4.3の管理画面からの自動配信は上記の新しい手順を使います。専用トークンを設定するまでは、この作業環境からの公開コマンドも利用できます。

公開処理はファイルごとに取得して送信します。動的公開のページ、下書き、承認待ち、設定・認証情報・AI文書はファイル配信に含めません。検索は静的公開に設定してもWorkerで処理します。公開HTMLと画像の更新は新しい配信版への切り替えでまとめて反映します。公開処理中は編集を一時的に止めます。

公開済みページの取り下げはサイト生成で行い、公開済み画像の削除・名前変更はメディア画面の操作が取り下げを自動で実行します。部品JSの取り下げには配信更新が必要です。公開先のブラウザに保存済みの画像まで回収する機能はありません。上記の「配信モードと取り下げ」を参照してください。

Workerの無料プランでは静的配信ファイル20,000件・1ファイル25 MiB、URL別名は2,000件までです。画像もこの静的ファイル件数に含めます（画像は最大10,000件）。画像・管理・検索・動的ページ・公開処理はWorker/D1/R2の利用枠を消費します。通常のコード更新でも配信済みHTMLを保持するため、公開コマンドを使います。

### メディアの編集とカテゴリ

各画像の操作はPHP版と同じ「リサイズ▼」「名前変更▼」「WebP に変換」の順です。WebP変換はJPEG・PNGだけに表示し、ページ・コンポーネント・サイト共通OGPの参照を更新します。名前変更は拡張子を変えずに行います。上部のカテゴリ選択はファイル名の接頭辞でメディアを絞り込み、g_で始まる共通画像も表示します。アップロードには選択カテゴリの接頭辞が付与されます。

### コンポーネント一覧

「AIに聞く」の右側に3版共通の絞り込みセレクタがあります。すべて、選択中のカテゴリ、ページ、パーツ、AI指示、標準コンポーネントを選べます。標準はID先頭の `_` で判定します。通常の新規作成・複製では付けず、標準扱いを意図する場合は使用できます。保存は拒否しません。
「選択中のカテゴリ」は管理画面上部のカテゴリを使い、画像と同様にIDの接頭辞で判定します。例えば `apps_header` は `apps` カテゴリに含まれます。カテゴリ未選択時は絞り込みません。


ページ・コンポーネントのCSSは全版共通で自動挿入されます。`{{HEAD_CSS}}`で挿入位置を指定でき、複数ある場合は最初の1つにだけ出力し、残りは取り除きます。省略時は`</head>`直前、閉じタグがなければHTML先頭へ挿入します。コメントやscript/style/textarea/title内の文字列は挿入位置として扱いません。


デザインコンポーネントの「なし」、不足するhead情報の補完、サイト共通の計測パーツとページ単位の除外に対応します。ページ編集の概要・本文の間隔、Raw HTMLチェック、JS欄の高さはPHP版に合わせています。詳しくは同梱の共通ヘルプを参照してください。

データ入出力画面はSQLite版の状態カード・ZIP取込・WordPress XML取込・実行ログに合わせ、CSVとCloud固有のJSONバックアップ・復元を追加しています。ZIP/XMLは追加取込で既存IDを保持し、画像・アカウント・サイト設定は取り込みません。上限はファイル20MB、展開15MB、取込内容1MB、300件です。設定フォームとカテゴリ新規ボタンもPHP共通CSSに合わせています。

未公開の画像の変更にCloud公開接続は不要です。公開済み画像の削除・名前変更は取り下げのため配信更新を行うので、接続が必要です。名前変更は参照更新を選べる確認ダイアログを使います。完全バックアップ・容量・移行の仕様はv0.5.0の節を参照してください。
