# 🍊mikanBox Cloudflare版 マニュアル <small class="manual-version">v0.6.10</small>

このマニュアルはCloudflare版の導入と、PHP版との違いを説明します。共通の操作は[操作マニュアル](https://yoshihiko.com/mikanbox/help_ja.html)も参照してください。

## 初期設定・配布について

### 新規インストールと公開

新しいサイトを作る手順です。既存サイトの更新では、D1やWorkerを新規作成せず、[アップデート手順](#manual-update)を参照してください。

画面を見ながら進める場合は、[画像付きインストールガイド](/mikanbox/guides/install-ja.html)を使います。

#### AIに依頼する（おすすめ）

ファイルの取得やコマンド実行ができるAIを使います。作業フォルダで新しい会話を開き、次のように依頼します。

「https://github.com/yoshihik0/mikanBox-cloud からCloudflareにインストールしてください」

ファイルの取得、設定、配置はAIが進めます。利用者が行うのは次の5つです。

1. **Cloudflareにログインしておく。** アカウントがなければ作成します。設置するアカウントでログインしてください。
2. **Cloudflareの認可画面で、設置先のアカウントを確認して「Authorize」を押す。**
3. **サイトのアドレスを決める。** 管理画面と公開サイトの名前を別々に選びます。`workers.dev` のアドレスは公開されるため、メールアドレスやログインIDは使わないでください。公開サイトに独自ドメインを使うこともでき、あとから設定もできます。
4. **普段使うブラウザで管理画面（`/admin`）を開き、端末を登録する。** AIが案内するファイルの `SETUP_TOKEN` を入力します。トークンはチャットに貼らず、管理画面に直接入力します。詳しくは[端末認証](#端末認証)を参照してください。
5. **公開の設定をする。** 管理画面の「サイト」→「Cloudflare公開設定」に、Workers Scripts Edit 権限のAPIトークンを保存し、ページ一覧の「静的サイトをビルド」で公開します。ビルドが終わるまで画面を開いておきます。

#### 注意

- **既存の公開サイトには新規インストールを行わないでください。** 公開サイトが初期ページに置き換わります。更新は[アップデート手順](#manual-update)を使います。
- 設定ファイルと秘密情報（`.env.production.secrets` など）はGitHubに公開せず、安全に保管します。設定ファイルは後の更新にも使います。
- Cloudflareの画面や料金・無料枠は変更されることがあります。
- 管理側のAPIトークンは、Wranglerのログインとは別のものです。D1の書き出し・復元も使う場合は、D1編集権限も必要です。

#### 自分でコマンドを実行する場合

Node.js（22以上）とnpm、ターミナルが必要です。コマンドと設定ファイルの詳細は[詳細リファレンス（インストール手順）](https://github.com/yoshihik0/mikanBox-cloud/blob/HEAD/docs/reference_ja.md#インストール手順)を参照してください。公開URLをあとから変更する手順も、同じリファレンスにあります。

#### 端末認証

パスワードはありません。管理画面に入れるのは、登録した端末（ブラウザ）だけです。 「端末とユーザー」は通常閉じており、端末の期限を変更するとその場に結果を表示します。端末のCookieには乱数のトークンを入れ、D1にはそのハッシュだけを保存します。

- **最初の端末**：ログイン画面で `SETUP_TOKEN`・ユーザー名・表示名・端末の名前を入力します。使った `SETUP_TOKEN` は二度と使えません。
- **端末の追加**：登録済みの端末で、サイト →「端末とユーザー」→「端末を追加する」から追加用のコードを出し、新しい端末のログイン画面で入力します。その端末は、コードを出した人と同じユーザーとして登録されます。コードは3時間有効で、1回だけ使えます。ほかの人を招くときは「ほかの人を招く」で招待のコードを出して渡します。ユーザーIDと表示名は、招待された人が、ログイン画面で自分で決めます。コードの入力を5回間違えると、15分間入力できません。
- **端末の期限**：最後に使ってから30日（標準）・90日・180日で切れます。使うたびに延びます。
- **端末を止める**：「端末とユーザー」の一覧から止めます。コードで追加してから3日以内の端末は、ほかの端末を止める、ほかのユーザーを削除・変更する、ユーザーごとの復元、D1の時刻指定の復元ができません。`SETUP_TOKEN` で登録した端末には、この制限はありません。ユーザーを削除すると、そのユーザーの端末と、発行した未使用の招待コードを含むコードも止まります。新しい端末が登録されると、ほかの端末で管理画面を開いたときに知らせます。
- **復旧**：すべての端末を失ったときは、`wrangler secret put SETUP_TOKEN` で新しい値を設定し、ログイン画面の「復旧」から既存のユーザー名で登録します。登録済みの端末はすべて止まり、未使用のコードとMCPキーも消えます。
- 表示名は、「端末とユーザー」の自分のユーザーにある入力欄から変更できます。ユーザー名は変更できません。
- ユーザーを削除すると、そのユーザーの端末も止まります。同じIDで作り直しても、旧端末は使えません。
- ブラウザのCookieを消す、別のブラウザに変える、プライベートモードで開くことは、端末を失うのと同じです。端末の管理（画面ロック、紛失時の対応）は利用者の責任です。

## 全体像

### 標準コンテンツ

初回設定時はSQLite版と同じ標準データを選択言語で取り込みます。日本語・英語それぞれページ8件（ホーム、404、検索、各見本、DB見本）とコンポーネント11件（レイアウト、ヘッダー、フッター、カード、検索、AI指示の見本など）です。

既存ページ・コンポーネントは上書きしません。設定・アカウント・秘密はこの取り込みに含めません。

標準検索フォームの `/index.php?page=search&q=...` と `/search?q=...` に対応します。検索結果は公開ページだけを対象にし、下書き・承認待ち・DBは含めません。AI指示の `DESIGN_sample.md` / `DESIGN.md` を編集できます。AI質問の `{{AI_QUESTION}}` と `{{AI_QUESTION:セクションID}}` に対応します。外部取得の `EXT_MD` は未対応です。見本内の画像は同梱されていません。メディア画面から必要な画像をアップロードできます。

## ページ・ページ編集

基本の操作はPHP版と同じです。[ページ](https://yoshihiko.com/mikanbox/help_ja.html#page-mgmt)と[ページ編集](https://yoshihiko.com/mikanbox/help_ja.html#page-edit)を参照してください。ここでは、Cloud版で押さえておくことを説明します。

### 編集と保存

- 保存のたびに履歴を残します。履歴は直近50件から選べます。
- 同じページを複数の端末で同時に編集できないよう、編集中のロックがあります。古い内容のまま保存して上書きすることはできず、競合した場合はエラーが表示されます。再読み込みして、最新の内容から編集し直してください。
- ページ・設定とも、取得したあとに他で変更されていると保存できません。
- カテゴリーを削除すると、候補の設定だけでなく、各ページに付いたカテゴリーも削除し、履歴を保存します。対象のページが編集中、または更新済みの場合は、全体を中止します。

### プレビュー

- ページ一覧のプレビューは、保存済みの内容を表示します。
- ページ編集画面のプレビューは、未保存の入力内容を表示します。保存や公開はしません。
- 下書き・承認待ちのページは非公開で、ログインした編集者だけがプレビューできます。公開前の画像もプレビューで表示できます。

### ページのURL

ページIDを `test/index` とすると、`/test/index.html`、`/test/index/`、`/test/`、`/test` から表示できます（ビルドが必要です）。`test` 自体のページもある場合は、そちらを優先します。

DB状態のページは、`/api/ID` でDATA/DATAROWを公開できます。下書き・承認待ちのページは、公開ページのPOST_MD・ナビ・フィード・APIから読み出せません。

### JavaScript

ページ・コンポーネントのJavaScriptは、管理者が書いたコードとして公開ページで実行されます。コンポーネントのJavaScriptは `/component-js/ID.js` で直接読み込めます。

内部動作の詳細は[詳細リファレンス（ページ操作）](https://github.com/yoshihik0/mikanBox-cloud/blob/HEAD/docs/reference_ja.md#ページ操作)を参照してください。

### アップデート

[画像付きアップデートガイド](/mikanbox/guides/update-ja.html)では、GitHubの画面を見ながら設定と更新ができます。

管理画面の「サイト」で、現在のバージョンとGitHub上の最新版を確認できます。「再確認」は最新版の情報を取り直します。更新後は、画面を再読み込みして現在のバージョンを確認します。

更新は、記事や画像を初期化する操作ではありません。**更新の前に**、「データ移行・インポートツール」で必要なバックアップを保存してください。非公開データを含むため、安全に保管します。

#### 更新方法を選ぶ

更新方法は2つです。どちらを選んでも、記事や画像はそのまま残ります。

| | GitHubから更新 | ダウンロードして更新 |
| :--- | :--- | :--- |
| 更新のしかた | 管理画面のボタンから、GitHubで実行 | 最新版をダウンロードし、AIまたはコマンドで実行 |
| 最初の設定 | 必要（フォーク、APIトークン、Secretの登録） | 不要（Cloudflareにログインできればよい） |
| 2回目以降 | ボタンひとつ | 毎回ダウンロードして実行 |
| 向いている人 | 頻繁に更新する人、GitHubに慣れた人 | 設定を増やしたくない人、たまに更新する人 |

更新されるのは管理画面（管理用Worker）です。公開ページや画像の変更は、更新後も管理画面の「静的サイトをビルド」で配信します。

#### GitHubから更新する

設定が済んでいれば、更新はボタンを押すだけです。

##### 更新のしかた

1. 管理画面「サイト」で新しいバージョンを確認し、**GitHubでアップデート**を押します。
2. GitHubで **Run workflow** → 表示された **Run workflow** を押します。
3. 実行履歴で **Success** を確認し、管理画面を再読み込みします。現在のバージョンと記事・画像を確認します。**Failure** の場合は、失敗した工程を開いて内容を確認します。

##### 初回設定（少し難しいですが、最初の1回だけです）

初回だけ、自分のGitHubにコピーを作り、Cloudflareへの権限を登録します。次の3つの手順です。

###### 初回1：自分のリポジトリを作る

1. GitHubにログインし、[制作元のリポジトリ](https://github.com/yoshihik0/mikanBox-cloud)を開きます。
2. 画面右上の **Fork** を押し、所有先を自分のアカウントにして **Create fork** を押します。すでに自分が管理するコピーがある場合はそれを使えます。
3. 作成した自分のリポジトリの **Actions** タブを開き、無効なら表示される有効化ボタンを押します。**Update mikanBox Cloud** が表示されることを確認します。ワークフローがない古いコピーでは、最新版の `.github/workflows/update-cloud.yml` を自分のリポジトリの既定ブランチに追加する必要があります。

###### 初回2：更新先と権限を登録する

トークンを新しく作る場合は、Cloudflareダッシュボードのプロフィールから **APIトークン → トークンを作成する** を開き、「カスタムトークンを作成する」の **始める** を押し、権限に「アカウント / Workers スクリプト / 編集」と「アカウント / D1 / 編集」を追加します。アカウントリソースで対象アカウントを指定し、**概要に進む → トークンを作成する** を押します。表示された値は再表示できないため、安全に控えます。トークンはGitHubのSecret欄へ直接貼り、チャットに送らないでください。

自分のリポジトリで **Settings → Secrets and variables → Actions** を開き、**New repository secret** から次の2件をそれぞれ登録します。Nameに名前、Secretに値を入れて **Add secret** を押します。制作元ではなく自分のリポジトリに登録してください。

- Name：`CLOUDFLARE_API_TOKEN`。Secret：既存サイトのCloudflareアカウントを対象に、**Workers Scripts Edit** と **D1 Edit** の両方の権限を持つAPIトークン。管理画面の公開設定で使ったトークンに両方の権限があれば再利用でき、別のトークンでも構いません。公開設定に保存した値は再表示できません。独自ドメインやルートの操作には追加のゾーン権限が必要になる場合があります。トークンをチャットや公開ファイルに貼らないでください。
- Name：`MIKANBOX_UPDATE_CONFIG`。Secret：現在のサイト用 `wrangler.production.json` の**全文**。設置時のファイルを使い、アカウント、管理Worker、DB、R2、ルート・独自ドメインなどが現在の構成と一致することを確認します。JSONにはJWT_SECRET、SETUP_TOKEN、APIトークンを入れません。ファイルがない場合はCloudflareのWorker設定・バインディング・ルートを確認して構成を復元する必要があります。不明な設定のまま実行しないでください。

###### 初回3：実行してリンクを設定する

自分のリポジトリの **Actions → Update mikanBox Cloud → Run workflow** を開き、表示された **Run workflow** を押します。実行履歴を開き、**Success** になるまで待ちます。成功後、管理画面を再読み込みすると「GitHubでアップデート」が自分のリポジトリを開きます。管理画面に「手動アップデートの設定」がすでにある場合は、自分のリポジトリを `所有者/リポジトリ名` の形式で保存してリンクを設定することもできます。

以上で設定は完了です。次回からは「更新のしかた」の3ステップだけです。

##### 知っておくこと

- Actionsは制作元の最新公開リリースを毎回取得します。公開プレリリースも対象です。
- フォーク側のワークフロー自体は自動更新されません。その修正が公開された場合は、自分のコピーにも反映します。
- 管理WorkerとD1/R2の接続が設定と違う場合や、未対応の追加バインディングがある場合は、Actionsが中止します。接続やルートを変更したら、GitHubに保存した設定も更新してください。
- Workers Buildsなど別の仕組みでGitHubへのpush時に自動デプロイしている場合は、手動更新とは別にその設定を確認してください。
- DBの更新とWorkerの公開は別の工程です。途中で失敗するとDBだけ更新済みの場合があります。失敗した工程を確認してから再実行します。適用済みのDB更新は再適用されません。

動作の詳細は[詳細リファレンス（アップデート手順）](https://github.com/yoshihik0/mikanBox-cloud/blob/HEAD/docs/reference_ja.md#アップデート手順)を参照してください。

#### ダウンロードして更新する

1. 最新版の[リリースページ](https://github.com/yoshihik0/mikanBox-cloud/releases)から **Source code (zip)** をダウンロードして展開します。
2. 既存サイトと同じCloudflareアカウントでログインします。認可画面で対象アカウントを確認し、**Authorize** を押します。
3. 更新を実行します。**AIに頼むか、コマンドで行います。**

AIに頼む場合は、展開したフォルダでAIの新しい会話を開き、既存の管理画面URLを伝えて「このサイトを最新版に更新してください」と依頼します。AIが設定を確認して更新を進めます。コマンドで行う場合の手順は、[詳細リファレンス（アップデート手順）](https://github.com/yoshihik0/mikanBox-cloud/blob/HEAD/docs/reference_ja.md#アップデート手順)を参照してください。

**注意：** 更新には、設置時の設定ファイル `wrangler.production.json` が必要です。現在のサイトの構成と一致しているものを使い、新規用のサンプル値は使いません。見つからない場合は、Cloudflareで既存Workerの設定を確認してから進めてください。

### 公開と配信

Cloud版では、管理画面と公開サイトが別々のWorkerで動きます。公開サイトは静的ファイルだけで、閲覧されてもWorkerやD1の利用枠を使いません。

#### ビルドして公開する

ページ一覧の下の「静的サイトをビルド」を押すと、公開ページのHTMLを作り、公開側へ配信します。

- 進み具合と結果はボタンの横に表示されます。完了まで画面を開いたままにしてください。
- 変更のあったファイルだけを送ります。
- 公開側に反映していない変更のページ数と、最後に公開した日時も表示します。
- ページ一覧の地球のアイコンで、公開ページを開けます。青は公開側が最新の内容、グレーは変更が未反映か、まだ公開されていないページです。ほかのページの変更（ページ一覧のコンポーネントなど）で変わる部分は、ビルドするまで反映されません。
- 公開先のURLは、ビルドボタンの近くに表示します。

##### 公開用のAPIトークン

ビルドには、Cloudflareで作ったAPIトークン（Workers Scripts Edit 権限）が必要です。サイト設定の「Cloudflare公開設定」に入力すると、暗号化して保存します。保存したトークンは再表示されず、JSONバックアップにも含まれません。

トークンは最初に1回だけ作ります。作り直すのは、Cloudflare側でトークンを削除・失効させたとき、権限を変えたとき、サイトのJWT_SECRETを変えたとき、バックアップやTime Travelで別のDBへ戻したときだけです。未設定のときは、ビルドボタンの下に案内が出ます。Cloudflare APIがエラーの詳細を返した場合は、エラーコードとメッセージを表示します。

#### ページの状態

| 状態 | 動作 |
| :--- | :--- |
| 下書き・承認待ち | 非公開。ログインした編集者だけがプレビューできます。 |
| 公開 | ビルドでHTMLを作り、静的ファイルとして配信します。 |
| DB | ページ自体は非公開。データを `/api/ページID` で公開します。 |

ページごとの静的・動的の選択はありません。MCPやインポートで `public_dynamic` を指定しても、「公開」として保存します。

#### 公開をやめる（取り下げ）

配信先に出したファイルはWorkerを通らないため、元データを消しても配信先に残ります。配信先から取り除くことを取り下げと呼びます。

非公開にしたページと削除したページは、ビルドのときに配信先から取り除き、URL別名も取り消します。**ビルドまでは読める状態が続きます。** 公開をやめたら、ビルドも行ってください。

画像の削除時は、メディア画面の操作が自動で取り下げます。名前変更・WebP変換時は、次のビルドまで元の公開画像を維持します。「画像の静的配信」を参照してください。

#### 管理側と公開側の違い

- 管理側のアドレスでは、ログインしていない人にページ・画像・サイトマップなどを出しません。検索エンジンにも載せません。
- ログインした端末で管理側の `/about` などを開くと、プレビュー（`/preview/about`）に移ります。プレビューの中では、ページのJSからCookieや `localStorage` を使えません。
- 公開ページ、サイトマップ、RSSには公開サイトのURLを使います。サイトマップ・RSS・DBページのJSONは、公開側にファイルとして出します。
- 404ページは、PHP版と同じくサイトマップとRSSに載せません。
- 画面上部のログアウトボタンはありません。この端末を使わなくなるときは、「端末とユーザー」で止めます。
- AIの質問ボックスは、公開側では動きません。

仕組みの詳細は[詳細リファレンス（公開と配信）](https://github.com/yoshihik0/mikanBox-cloud/blob/HEAD/docs/reference_ja.md#公開と配信)を参照してください。

#### サイト内検索

サイト内検索は、Googleのサイト内検索を使います。`{{SEARCH_RESULTS}}` は、Googleでこのサイトの中を検索するフォームになります（`as_sitesearch` にサイトURLを入れます）。検索ページ（ID `search`）も静的に公開し、標準の検索ボックス（`_search_box`）から `index.php?page=search&q=…` に送られた検索語は、検索ページからそのままGoogleへ渡します。Googleに登録されたページだけが見つかり、公開したばかりのページはしばらく出てきません。入力した言葉はGoogleに送られます。

### 画像の保存先（D1とR2）

最初はR2を有効にせず、画像をD1に保存して使えます。容量が必要になったら、R2へ切り替えられます。切り替わるのは画像の保存先だけで、ページ・設定・ユーザーなどはD1に残ります。画像の公開URL（`/media/ファイル名`）と本文中のファイル名は、どちらの保存先でも変わりません。

#### 容量と料金

- **D1:** 画像の合計は400 MBまでです。D1 Freeは1DB500 MB、Paidは1DB10 GBまでで、プラン変更は別途必要です。
- **R2:** 画像合計400 MBの制限がなくなります。1画像10 MB・10,000件の制限は変わりません。R2 Standardの無料枠はアカウント全体で月間10 GB-month・書込み系100万回・読出し系1,000万回です。容量の上限ではなく、超過分は課金されます。
- R2を使うには、Cloudflareで支払い方法を登録してR2を有効にする必要があります。無料枠内でも登録が必要です。
- サイト画面に、D1のDB使用量と管理対象のR2容量を表示し、無料枠の80%程度で注意を表示します。他サイトや管理外のR2オブジェクトは含みません。実際のアカウント全体の使用量・料金は、Cloudflareで確認してください。料金通知は利用を停止する機能ではありません。

参考: [D1の制限](https://developers.cloudflare.com/d1/platform/limits/)、[R2の料金](https://developers.cloudflare.com/r2/pricing/)、[R2の初期設定](https://developers.cloudflare.com/r2/get-started/)、[料金と使用量](https://developers.cloudflare.com/billing/understand/usage-based-billing/)。

#### R2へ移行する

1. Cloudflareでバケットを作成し、WorkerのR2接続名を `MEDIA` にします。公開用 `wrangler.production.json` に次の設定を追加し、コードをデプロイします。この準備だけでは保存先は切り替わりません。

```json
"r2_buckets": [{"binding": "MEDIA", "bucket_name": "実際のバケット名"}]
```

2. **移行の前に、完全JSONバックアップを保存します。** 成功後にD1へ戻すメニューはありません。
3. サイト画面の「メディアの保存先」で現在の保存先と使用量を確認し、「D1からR2へ移行」を実行します。確認の画面で移行を開始します。

移行中はD1の原本を表示し、画像の追加・変更・削除を止めます。画面を閉じても、同じメニューから再開・中止できます。未完了・失敗・中止ではD1の原本を保持します。全件の確認が完了すると、R2の参照へ一括で切り替えます。

「不要な一時画像を整理」で、24時間以上保持した未使用の一時画像を最大20件ずつ削除できます。内部動作は[詳細リファレンス（保存先とバックアップ）](https://github.com/yoshihik0/mikanBox-cloud/blob/HEAD/docs/reference_ja.md#保存先とバックアップ)を参照してください。

### バックアップと取り込み

#### JSONバックアップと復元

サイト設定の「データ移行・インポートツール」専用ページで、設定・すべてのページ・コンポーネント・履歴・静的HTML・ユーザー・画像原本を1つのJSONファイルでダウンロードし、そのファイルを選んで復元できます。SQLiteファイルではありません。画像を含み、D1・R2のどちらの保存先にも復元できます（復元先の保存先設定は維持します）。

- 大容量では時間とブラウザのメモリを使うため、保存・復元の間は画面を閉じないでください。画像は500KB単位で転送します。設定などのメタデータは20MBまでです。
- バックアップには非公開内容・APIキー・認証ハッシュが含まれます。安全に保管してください。
- 保存と復元は確認の画面だけで行います。通常の復元は、現在のサイトID・APIキー・ユーザー・Cloudflare接続を維持します。「ユーザーも復元」を選ぶとユーザーも復元します。バックアップにないユーザーの端末は止まります。
- 復元後に再構築してください。
- 欠損や同時編集があれば、元のデータを保持して復元を中止します。D1では、現在のデータと復元分・一時画像の合計が450MB以内である必要があります。

#### D1自体のバックアップ

D1のSQL書き出しと、指定時点にDB全体を戻すTime Travelは、JSONバックアップとは別の機能です。D1編集権限を持つ専用トークンが必要です。R2の画像実体は含まれないため、R2を使っている場合はJSONバックアップを使ってください。詳細は[詳細リファレンス（保存先とバックアップ）](https://github.com/yoshihik0/mikanBox-cloud/blob/HEAD/docs/reference_ja.md#保存先とバックアップ)を参照してください。

#### 静的HTMLのZIP出力

ビルド後、「データ移行・インポート」画面の「静的HTML（ZIP）」で「静的ZIPを保存」を選びます。`ID.html` と `ID/index.html` の構造を選べます。`index` はトップの `index.html`、末尾が `/index` のIDはディレクトリ構造でそのまま `ディレクトリ/index.html` になります。出力先が衝突する場合はエラーにします。

ビルド済みで現在も公開HTML状態のページだけを出力し、同梱ページへのリンクと画像・部品JSの参照を相対パスにします。使用画像と公開アセットを同梱します。動的ページ・検索・APIは元の公開サイトへのリンクとして残ります。APIキー・設定・ユーザー・非公開ページは入れません。ZIP内ではWebMCPを登録せず、AI質問欄はCloudヘルプへのリンクになります。

ZIP全体は20 MBまでで、画像読出し回数にも上限があります。出力画像が不足する場合はエラーにし、途中のZIPを渡しません。任意のJavaScript内の通信処理や、文字列形式のCSS `@import` は自動変換しません。これは静的サイトの持ち出し機能で、完全なD1バックアップではありません。

Macで作成したZIPに含まれる `__MACOSX` や `._` で始まる補助ファイルは自動的に無視します。

インポート画面の「ZIP内のファイルの置き方」を開くと、ページIDとフォルダ配置の例を確認できます。

#### データの取り込み

ZIP・WordPress XML・CSVを取り込めます。ZIP/XMLは追加取込で、既存IDを保持し、画像・アカウント・サイト設定は取り込みません。上限はファイル20MB、展開15MB、取込内容1MB、300件です。

### 更新・復元の途中で失敗した場合

JSON復元では、転送中のデータを一時領域に置き、全件の検証後に現在のデータと一括で切り替えます。画像の転送中に通信が切れた場合は、バックアップファイルを選び直して最初から復元してください。画面を開き直して転送位置から再開する機能はありません。

最後の復元操作で応答だけが届かなかった場合は、同じ操作を一度再試行し、保存済みの完了結果を確認します。完了済みの復元を再実行して、その後の編集を上書きすることはありません。完了を確認できないという表示が出た場合は、再読み込みしてページや画像の内容を確認してから再試行してください。ユーザーも復元した場合は、改めてログインが必要になることがあります。

「復元は完了しましたが、公開更新に失敗しました」と表示された場合、復元済みのデータは残っています。バックアップをもう一度取り込むのではなく、ページ一覧からサイトのビルドを再試行してください。

### AIから管理する（MCP）

MCPに対応したAIから、ページ・コンポーネント・画像を直接読み書きできます。

#### 接続する

1. 管理画面のサイト設定で、Cloud専用のAPIキーを生成します。
2. AIの接続設定に、管理用のアドレス `/mcp` を登録し、APIキーをBearerキーとして渡します。

APIキーはサイトの管理操作権限を持つため、公開しないでください。

#### できること

- ページ・コンポーネントの一覧、取得、作成、更新、削除
- 履歴の取得、サイト設定の取得（APIキー・認証情報・管理メモは返しません）
- AI指示書（DESIGN.mdなど）の一覧、取得、更新
- 画像のアップロード
- 静的HTMLの生成（`build_ssg`）。生成のみで、公開側への配信は管理画面のビルドで行います。

使い方のポイントは次のとおりです。

- 接続したら、最初に `get_site_info`、続けて `get_ai_context` を呼びます。書き込みの前には、`get_site_info` で接続先のサイトIDを確認してください。
- 更新は、指定しなかったフィールドをそのまま保持します。
- 編集には、URLのディレクトリ省略ではなく、正確なページIDを指定します。
- 画像のアップロードは、JPEG・PNG・GIF・WebP・SVGの10 MBまでです。同名のファイルは上書きせず、エラーになります。大きな画像は、通常の管理画面からのアップロードも使ってください。音声・動画はアップロードできません。

ツールの一覧や詳細は[詳細リファレンス（MCPとヘルプ）](https://github.com/yoshihik0/mikanBox-cloud/blob/HEAD/docs/reference_ja.md#mcpとヘルプ)を参照してください。

### Cloud版のヘルプをAIに読ませる

公開の `/public-mcp` は、APIキー不要・読み取り専用です。AIがこのヘルプを検索して読めるようにします（`search_help`、`get_help_section`、`get_product_info`、`get_agent_instructions`）。人向けのヘルプは `/public-help.html?language=ja` で読めます。

対応するブラウザやAIでは、公開ページと管理画面からヘルプを使えます。すべてのブラウザ・AIクライアントで使えるとは限りません。

## デザイン

共通の操作は[デザイン](https://yoshihiko.com/mikanbox/help_ja.html#design-mgmt)を参照してください。

### コンポーネント一覧

「AIに聞く」の右側に3版共通の絞り込みセレクタがあります。すべて、選択中のカテゴリ、ページ、パーツ、AI指示、標準コンポーネントを選べます。標準はID先頭の `_` で判定します。通常の新規作成・複製では付けず、標準扱いを意図する場合は使用できます。保存は拒否しません。
「選択中のカテゴリ」は管理画面上部のカテゴリを使い、画像と同様にIDの接頭辞で判定します。例えば `apps_header` は `apps` カテゴリに含まれます。カテゴリ未選択時は絞り込みません。


ページ・コンポーネントのCSSは全版共通で自動挿入されます。`{{HEAD_CSS}}`で挿入位置を指定でき、複数ある場合は最初の1つにだけ出力し、残りは取り除きます。省略時は`</head>`直前、閉じタグがなければHTML先頭へ挿入します。コメントやscript/style/textarea/title内の文字列は挿入位置として扱いません。


デザインコンポーネントの「なし」、不足するhead情報の補完、サイト共通の計測ID・計測コード（head／body開始直後）とページ単位の除外に対応します。ページ編集の概要・本文の間隔、Raw HTMLチェック、JS欄の高さはPHP版に合わせています。詳しくは同梱の共通ヘルプを参照してください。

## メディア

共通の操作は[メディア](https://yoshihiko.com/mikanbox/help_ja.html#media-mgmt)を参照してください。

### 画像アップロードと制限

画像のアップロードでは長辺2,000pxへの縮小を既定で選べます。JPEG・PNG・WebPのリサイズとWebP変換はブラウザで実行し、原本を処理後の画像に置き換えます。WebPへの名前変更ではページ・コンポーネントの参照も更新し、ページ履歴を残します。GIF・SVGのアップロードは原本のまま保存します。変換は16,000px以下かつ4,000万画素以下が対象です。

メディア欄で画像を選ぶか、画面へドラッグしてアップロードできます。ファイル名をクリックするとコピーできます。本文には `![説明](ファイル名.png)` または `{{IMAGE:ファイル名.png}}` と書きます。「保存」リンクから個別にダウンロードできます。

ファイル名検索・カテゴリー絞り込み・ページ送りが使えます。表示件数はサイト設定の「メディア表示件数」に従います。カテゴリー絞り込みは、そのカテゴリーのページが参照する画像、またはカテゴリー名を接頭辞に持つ画像を対象にします。

D1構成の「名前変更」は本文・CSS・JavaScript・OGP画像・コンポーネントの参照先も更新します。拡張子変更と同名上書きはできません。メモと過去の履歴は書き換えません。参照更新するページの履歴を保存し、同時編集・競合があれば画像を含む操作全体を中止します。変更した静的ページは再ビルドが必要です。コンポーネントに参照があれば全静的HTMLを再ビルドしてください。参照データが大きすぎる場合は一括変更できません。外部サイトや独自JavaScriptで組み立てたURLまでは更新しません。

- 1画像 **10 MB**（10,000,000 bytes）以下。
- D1画像合計 **400 MB**まで。R2ではこの上限を外します。どちらも最大 **10,000ファイル**です。
- 形式は **JPEG / PNG / GIF / WebP / SVG**。拡張子と先頭の形式情報を確認します。D1構成では動画・音声アップロードは未対応です。
- 同名ファイルは上書きしません。保存前にブラウザでリサイズ・WebP変換でき、処理後の画像を原本として保存します。
- メディアZIPは **合計20 MB**まで。1リクエストの読出し上限に収まる枚数も必要です（小さい画像なら約20枚、10 MB画像なら2枚）。超える場合は個別に保存してください。

静的ビルドでは、ローカルの画像（JPEG / PNG / GIF / WebP。SVGは対象外）に、PHP版と同じ `width`・`height` と読み込みのヒント（最初の大きい画像は `fetchpriority="high"`、以降は `loading="lazy"`）を付けます。対象は `![説明](ファイル名)` と `{{IMAGE:}}` で、直接書いた `<img>` は変えません。寸法は画像の先頭部分だけを読んで求め、保存はしません。1回のビルドで調べる画像は30枚までで、超えた分は属性なしになります。公開前のライブ表示と管理画面のプレビューでは付けません。

D1モードの400 MBはコンテンツ・履歴・DB管理領域の余地を残す画像用上限です。R2モードには適用しません。プラットフォームの容量上限に先に達すると保存できません。

[D1 Freeの枠](https://developers.cloudflare.com/d1/platform/pricing/)は読出し500万行/日、書込み10万行/日、DB合計5 GB。[Workers Free](https://developers.cloudflare.com/workers/platform/limits/)は1日10万リクエストです。D1の画像読出しは500 KBごとに1行を読み出します。R2配信では画像メタデータとR2オブジェクトを読み出します。これらの枠は同じアカウントの他のアプリとも共有します。Freeで日次上限に達すると処理が停止し、リセット後に再開します。アプリから契約を自動変更しません。既にPaid契約の場合はその料金体系に従います。

画像はアップロード後に公開されます。下書きのページだけで使う画像も対象です。公開してはいけない画像はアップロードしないでください。JS・CSSファイルはサイトのビルド時に公開されます。

メディア画面では画像変換の補足と最大ファイルサイズの行を省き、ページ内での利用方法を案内します。Markdownはファイル名だけ、HTMLは `media/ファイル名` を標準とします。画像の従来の `images/ファイル名` も利用できます。

メディアの名前変更やWebP変換では、変更先のファイルが既にある場合、元のファイルや公開中の画像を取り下げずに中止します。参照を更新するページが編集中の場合も、保存して編集を終了するまで中止します。失敗した理由は画像の操作欄に表示されます。

### メディアの編集とカテゴリ



操作後も可能な範囲でメディア一覧のスクロール位置を保ちます。各画像の操作はPHP版と同じ「リサイズ▼」「名前変更▼」「WebP に変換」の順です。WebP変換はJPEG・PNGだけに表示し、ページ・コンポーネント・サイト共通OGPの参照を更新します。名前変更は拡張子を変えずに行います。上部のカテゴリ選択はファイル名の接頭辞でメディアを絞り込み、g_で始まる共通画像も表示します。アップロードには選択カテゴリの接頭辞が付与されます。

### 画像の静的配信

未公開の画像の変更にCloudflare公開設定は不要です。公開済み画像の削除・名前変更は取り下げのため配信更新を行うので、接続が必要です。名前変更は参照更新を選べる確認ダイアログを使います。完全バックアップ・容量・移行の仕様は「画像の保存先（D1とR2）」を参照してください。

配信更新に画像を含めます。保存しているファイルは、どのページからも参照されていないものも含めて全件公開します。動的ページも静的ページと同じ `/media/ファイル名` を読むためです。

公開済みの画像はStatic Assetsから配信します。管理画面のプレビューでは、配信前の画像も確認できます。メディア画面から画像をアップロードすると、その画像だけを自動で配信先へ追加し、ページのビルドは行いません。自動配信にはCloudflare公開設定と直前の配信状態が必要です。配信先が外部で変更された場合などは一度ビルドしてください。配信に失敗した画像は管理側に保存されたまま、公開未反映として通知します。MCPからのアップロードは自動配信の対象外です。

配信先の上限は1バージョンあたり20,000ファイル、1ファイル25 MiBです。画像は1ファイル10 MB・最大10,000件のため、ページとコンポーネントを合わせても上限内に収まります。

公開済み画像の名前変更・WebP変換では、公開中の元画像とHTMLは次のビルドまで維持されます。管理画面には変更後の画像と参照が保存され、次のビルドで公開側が切り替わります。元の公開ファイル名はビルドで取り除かれるまで再利用できません。画像を削除するときは、メディア画面が配信先からの取り下げを先に行います。

同じファイル名での差し替えは公開URLが変わらないため取り下げは不要です。ただし公開済みの画像は、配信更新を行うまで配信先に古い内容が残ります。



### JS・CSSライブラリ

メディアでブラウザー用の `.js`・`.css` をアップロードできます。UTF-8の空でないテキスト、1ファイル10 MB以下を受け付け、元のコードをそのまま保存します。管理画面では実行せず、カードからURLや読み込みタグをコピーして、ページ本文・コンポーネントのHTMLに貼ります。アップロードだけでは自動挿入しません。信頼できる管理者・APIキーから、提供元を確認したコードをアップロードしてください。形式検査は安全性を保証しません。

カテゴリ接頭辞と画像変換は適用しません。種類による絞り込み、同じ拡張子のままの名前変更、削除に対応します。同名ファイルは上書きせず、別名でのアップロードを求めます。フォルダ階層をまとめてアップロードする機能はありません。

保存先はメディア設定のD1/R2に従い、公開URLは `/media/ファイル名` です。完全JSONバックアップと復元、D1からR2への移行にも含まれます。コード欄の内容はD1に保存します。静的ページ公開では配信先の静的ファイルから配信します。「画像の静的配信」を参照してください。別サーバー向けの静的ZIPにはHTMLから参照するファイルを同梱します。

## タグ

### 使用できないタグ

- `{{EXT_MD:…}}`（外部のMarkdownやデータの取得）は、Cloud版では使用できません。タグの位置には何も表示されません（HTMLには `<!-- EXT_MD is not available in the Cloud edition -->` というコメントだけが残ります）。データを移行して使う機能ではないためです。編集画面のタグ一覧と、配布するサンプルページには、その旨を書いています。

Markdown のリンク先で `{{SITE_URL}}` を使えます。コード例内のタグは展開しません。画像の名前変更では、サイト共通OGPだけで使っている場合も参照ありとして確認します。
