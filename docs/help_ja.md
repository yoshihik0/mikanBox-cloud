# 🍊mikanBox 操作マニュアル <small class="manual-version">v2.11.6</small>

🍊mikanBoxには、SQLiteデータベースを使う**🍊mikanBox** [SQLite版]{.type-badge .badge-sqlite}と、データベースを使わないJSONファイルベースの**🍊mikanBox flat** [flat版]{.type-badge .badge-flat}があります。基本的な使い方は共通なので、このヘルプは両方に対応しています。バージョンによって内容が異なる箇所には、上記のバッジで区別を示します。

## コンセプト・特長 {#concept}

🍊mikanBoxは、「AI時代のパーツ組み立て型・超軽量CMS」です。数ページから数十ページ規模のWebサイトを、最速かつ安全に構築・運用するために設計された🍊mikanBox flat（JSON版）と、より規模の大きいサイトを快適に運用できる🍊mikanBox（SQLite版）があります。

- ファイルベース（JSON） — データベース不要。PHPの動くサーバーに置くだけ [flat版]{.type-badge .badge-flat}
- SQLite（単一ファイルDB） — データは1つのDBファイルにまとまり、PHPの動くサーバーに置くだけ [SQLite版]{.type-badge .badge-sqlite}
- モードレスUI — ページ遷移なし、1画面で全作業完結。軽快な操作感
- Markdown対応 —  コンテンツを簡単に編集可能、情報のアーカイブとしても適している
- カテゴリで絞り込み — ページや画像をカテゴリで絞り込み、ワークスペースとして利用できる
- ファイル名だけで画像表示 — ファイルのパスを意識せずに画像を張り込める
- コンポーネント構造 — 組み合わせて利用できるページテンプレートやパーツ
- コンポーネント単位のCSS管理 — 小さい範囲でCSSが書けて、干渉を気にしなくてよい
- AI生成コードを直接配置可能 — 手作業でのデザインなしでの運用にも対応
- AIエージェント連携（MCP） — AIがサイト構造やデザイン基調などを理解し、直接ファイルを読み書き
- DESIGN.mdの管理 — AIへの指示もサイトで管理し、AIに伝えられる
- マルチモーダルAI対応** — AIが画像を生成し、そのままメディアフォルダへ送信・配置
- 静的（SSG）も、動的も、それらの混在も — レスポンスの速い静的サイトも、静的・動的の混在も可能
- DB Less DB — ページにデータを埋め込んでAPIで出力。ヘッドレスCMSにも
- ポッドキャスト — RSSを自動生成してポッドキャスト配信も可能

---

## 設計方針 {#design-philosophy}

### 規模を限定する🍊mikanBox flat [flat版]{.type-badge .badge-flat}

🍊mikanBox flatは数千ページ規模のサイトは想定していません。数ページのサイトだけど情報の更新はしたい、そんなサイトにDBを使った重いシステムを導入する必要はないのでは。あえてデータベースを使わないことで、以下の手軽さを実現しています。

- 設置が簡単
- 構造がシンプルで覚えやすい
- バックアップ・サーバー移設が簡単

### ページ数の多いサイトも運用できる🍊mikanBox [SQLite版]{.type-badge .badge-sqlite}

🍊mikanBox（SQLite版）は、もう少し大きなサイトも運用したいご要望にお応えします。しかも、単一ファイルのSQLiteなので、手軽さはほとんどそのままです。

- 設置が簡単
- バックアップ・サーバー移設が簡単
- ページ数の多いサイトにも対応
- 複数ユーザーによる編集や承認システムに対応
- 編集履歴の管理に対応

### 柔軟な設計

ページやコンポーネントがCSSと結びついているのでわかりやすく、また、干渉を気にしなくてよい設計になっています。コンポーネントの使い方次第で、自由で柔軟なサイト設計が行えます。

- ページやコンポーネントがCSSとJavaScriptを持てる
- CSSをスコープ化して、干渉を防止
- コンポーネントの入れ子が可能
- WordPressのテーマにあたるものが手軽に作れ、AIでも作れる
- 画像などのメディアファイルのパスも自動で解決
- ページにデータを簡単に埋め込める
- 他ページ、他サイトのデータを読み込んで利用できる
- データの持ち方が多様で、工夫次第で様々使い方ができる

### AIフレンドリー

- AIで生成したページをそのまま貼り込んで使いやすい。凝ったデザインも、少ない作業でそのまま公開
- コードがコンパクトでシンプル。AIが理解しやすいので、専用のデータ構造にあわせて、ページ制作、デザインしてもらうことも簡単
- MCPを通じして、記事の作成からデザインまで、AIにリモートコントロールさせられる
- DESIGN.mdなど、AIへの指示を管理して、AIに読ませたり、逆にデザインからデザインシステムを生成させることが可能
- GitHubなど外部のMarkdownファイルをソースにできる `{{EXT_MD:url}}` タグを活用することで、管理画面を開かなくても「AIエージェントに指示してレポジトリを更新してもらう」だけでWebサイトが更新される運用スタイルも可能
- コードが小さく、AIが理解しやすいので、機能追加はプラグインではなく、AIでソースを書き換える

### セキュリティをシンプルに

静的サイトにも対応し、攻撃面を増やさない設計です。

- データベースなし（SQL攻撃面なし） [flat版]{.type-badge .badge-flat}
- すべてのDB操作にプリペアドステートメントを使用し、SQLインジェクションを防止 [SQLite版]{.type-badge .badge-sqlite}
- コードベースが小さい
- プラグインなど複雑な依存関係なし
- 大規模CMS特有の攻撃対象になりにくい

## 初期設定・配布について {#setup-dist}

🍊mikanBoxは、PHPが動作するサーバーにアップロードするだけですぐに利用可能です。

### 動作要件

PHP 8.0以上が動作するサーバーが必要です。[SQLite版]{.type-badge .badge-sqlite}はこれに加えて、SQLite3拡張が有効である必要があります（多くのレンタルサーバーで標準有効です）。

### インストール

`index.php` と同じディレクトリに `mikanBox` フォルダをアップロードします。このフォルダ名は変更可能です。変更したほうが、管理画面の場所（ `admin.php` の場所）が推測されにくくなるため、セキュリティの観点から推奨されます。変更した場合は、 `index.php` の冒頭部分の `$core_dir` を修正してください。2.6.4以降、この設定はシステム更新で維持されます（更新プログラムが、実際に使用しているフォルダ名を書き戻します）。2.6.3以前は更新のたびにこの設定が失われ、サイトの表示が止まりました。その状態になっている場合も、管理画面からシステム更新を実行すれば復旧します。以下の説明では `mikanBox` ディレクトリとして説明します。

サイト固有のデータは、初回アクセス時に `index.php` と同じディレクトリの `mikanData` フォルダへ作成されます。旧バージョンの `mikanBox/data` が存在する場合は、安全に移動できるときだけ自動移行されます。移動先がすでに存在する場合やページURLと衝突する場合は、空のデータへ切り替えず、従来の保存先をそのまま使用します。

データフォルダ名を変更する場合は、管理フォルダ内に自動更新の対象外となる `local-config.php` を作成し、`define('MIKANBOX_DATA_DIR_NAME', '任意のフォルダ名');` と記述します。指定できるのは英数字・ハイフン・アンダースコアだけの単一フォルダ名です。データ作成後に名前を変更する場合は、実フォルダも同じ名前へ移してから設定してください。

インストール直後（ページ・コンポーネントのデータがまだ存在しない状態）で最初にアクセスがあると、ブラウザの言語設定（日本語・英語）に応じたサンプルコンテンツが自動的に投入されます。

#### ローカルで動かす

サーバーにアップロードせず、手元のパソコンで動かすこともできます。公開サーバーに管理画面を置かない運用（静的生成したファイルだけを公開する運用）の前提になり、AIのコーディングツールの作業フォルダとしても使えます。

必要なのはPHPだけです。データベースも、ビルドツールも、Node.jsも使いません。

1. PHPが入っているか確認します。ターミナルで `php -v` と入力し、8.0以上が表示されれば準備完了です。
2. 入っていなければインストールします。macOSには標準で含まれていないため、[Homebrew](https://brew.sh/) を入れてから `brew install php` を実行します。Windowsは [windows.php.net](https://windows.php.net/download/) から入手し、Linuxは `sudo apt install php`（Debian系）または `sudo dnf install php`（Fedora系）を実行します。
3. `index.php` と `mikanBox` フォルダを、任意のフォルダへ展開します。
4. そのフォルダへ移動し、`php -S localhost:8000` を実行します。これはPHPに付属する簡易サーバーで、追加のソフトは不要です。
5. ブラウザで `http://localhost:8000/mikanBox/admin.php` を開き、初回設定をします。手順は「[初回設定とログイン](#first-setup)」を参照してください。

`mikanData` フォルダと `media` フォルダは、初回アクセス時に自動生成されます。サーバーへ設置した場合と同じです。サーバーを止めるときは、起動したターミナルで Control+C を押します。

このフォルダをAIのコーディングツールで開くと、AIがページのMarkdownやJSONを直接読み書きできます。管理MCPも同じサイトに対して使えます。コンテンツがファイルとして見えるため、AIが書いた内容を後から開いて確認できます。

公開するときは、静的生成した出力フォルダをアップロードします。この運用では公開側にPHPもデータも管理画面も存在しないため、改ざんの対象がありません。

### 初回設定とログイン {#first-setup}

[flat版]{.type-badge .badge-flat}では、導入後、最初に `mikanBox/admin.php` にアクセスした人が管理用パスワードを設定します。ハッシュ値（暗号化されたデータ）は `mikanData/settings.json` に保存されます。

[SQLite版]{.type-badge .badge-sqlite}（v2.9.0以降）にパスワードはありません。管理画面に入れるのは、登録した端末（ブラウザ）だけです。端末の鍵（乱数のトークン）はそのブラウザのCookieに保存され、サーバーにはそのハッシュ値だけを保存します。データベースが漏れても鍵は復元できず、パスワードの使い回しや漏えいも起こりません。管理画面のURLが推測されても、鍵を持たない人はログイン画面までしか進めません。

#### 最初の端末を登録する {#device-setup}

[SQLite版のみ]{.type-badge .badge-sqlite}

1. ランダムな文字列（20文字以上）を作ります。控えを手元に残してください。1度しか使わないので、長く覚えておく必要はありません。
2. `setup-token` フォルダの中の `setup-token.txt` を開き、説明の下に、その文字列を1行だけ書きます。
3. `mikanBox` フォルダ、`index.php`、`setup-token` フォルダをアップロードします。
4. `mikanBox/admin.php` を開き、控えたトークン、ユーザー名、表示名、この端末の名前（例：仕事用PC）を入力して「この端末を登録」を押します。
5. 登録に成功すると、このブラウザに端末の鍵が保存され、そのまま管理画面に入ります。使ったトークンは二度と使えません。

`setup-token.txt` にトークンが書かれていない、20文字より短い、または同じ文字ばかりのときは、登録画面は表示されません。「インストール方法が変更になりました。こちらのページをご覧ください。」という案内だけが表示されます。誰でも先に開けば管理者になれる、ということはありません。ローカルで動かす場合も同じ手順です。

Cookieを消したときや、別のブラウザ・別のパソコンで入るときは、その端末は未登録になります。次の手順で追加してください。

#### 端末を追加する

[SQLite版のみ]{.type-badge .badge-sqlite}

登録済みの端末で、サイト →「端末とユーザー」→「端末を追加する」→「コードを出す」を押すと、追加用のコードが画面の上部に表示されます。新しい端末で管理画面を開き、コードと端末の名前を入力します。コードは10文字で、3時間有効、1回だけ使えます。人に知られないように扱ってください。コードを10回間違えて入力すると、同じ接続元（IPアドレス）からは15分間入力できません。

ほかの人を編集者として招くときは、同じ場所の「ほかの人を招く」で、招待のコードを出して渡します。ユーザーIDと表示名は、招待された人が、最初に入るときに自分で決めます。追加用のコードで入った端末は、コードを出した人と同じユーザーとして登録されます。

#### すべての端末を失ったとき（復旧） {#device-recovery}

[SQLite版のみ]{.type-badge .badge-sqlite}

1. 新しいトークンを作り、`setup-token` フォルダの `setup-token.txt` に書いて、アップロードします。前に使った値は使えません。
2. ログイン画面の「復旧（すべての端末を失った場合）」を開き、トークン、既存のユーザー名、端末の名前を入力します。

復旧すると、登録済みの端末はすべて止まり、未使用のコード、編集ロック、MCP APIキーが消えます。MCP APIキーは「MCP APIキー」で作り直してください。

#### 2.8.x から更新するとき {#upgrade-to-devices}

[SQLite版のみ]{.type-badge .badge-sqlite}

v2.9.0へ更新すると、パスワードと秘密の質問の回答は削除され、パスワードではログインできなくなります。ユーザー名と表示名は残ります。MCP APIキーは変わりません。

- 更新前にログインしていたブラウザがログイン状態のままなら、更新の方法（「システム更新」でもFTPで上書きでも）に関係なく、新しい版に最初にアクセスしてから2時間以内に管理画面を開くと、まだ端末が1台もなければ、自動的に最初の端末として登録されます。公開ページを先に開いても構いません。ブラウザを閉じるなどしてログイン状態が切れていると、登録されません。
- 別のブラウザから入る場合、ログイン状態が切れた場合、2時間を過ぎた場合は、トークンで登録します。新しいサイトにアクセスすると `setup-token` フォルダが自動的に用意されます（用意されないときは、配布物の `setup-token` フォルダをアップロードしてください）。上の手順1〜2でトークンを書き、`admin.php` に、トークンと既存のユーザー名、端末の名前を入力します（表示名は不要です）。FTPで更新する場合は、更新の前に `setup-token` フォルダとトークンを用意しておくと確実です。
- 自動で登録されたブラウザには、「パスワードを使わない方式に更新しました。…」というお知らせが、「閉じる」を押すまで画面の上部に表示されます。
- 登録されなかったブラウザやユーザーが管理画面を開くと、ログイン画面に「このサイトは、パスワードを使わない方式（端末認証）に変わりました。パスワードではログインできません。…」と理由が表示されます。
- ほかのユーザーは、登録済みの端末から追加用のコードを出してもらいます。
- 承認待ちページの確認用URLは、署名の元が変わるため、更新後は無効になります。

### 複数サイトのログイン {#multi-site-login}

v2.8.6から、同じドメインに複数のmikanBoxを設置しても、ログイン状態・ログアウト・CSRFトークンを設置ごとに分離します。flat版とSQLite版を混在させても、別サイトへのログインは引き継ぎません。サーバー上の設置ディレクトリを移動した場合も再ログインが必要です。同じ実ディレクトリを別URLで公開する場合は同じ設置として扱います。

[SQLite版]{.type-badge .badge-sqlite}では、端末の鍵（Cookie）の名前も設置ごとに異なり、鍵のハッシュ値はその設置のデータベースにしかありません。ほかのサイトの鍵では入れません。

#### パスワードの保存 [flat版のみ]{.type-badge .badge-flat}

ブラウザに保存したパスワードと、サーバーのログイン状態は別です。保存済みの値をブラウザで変更しただけでは、サーバーのパスワードは変わりません。管理画面でパスワード変更を保存した場合に、そのサイトのパスワードが変わります。現在のパスワードを確認し、新しいパスワードは4文字以上必要です。

初回設定・ログイン・パスワード変更には、管理画面のURLパスを使った「保存用サイトID」（例：`/shiro/mikanBox/admin.php`）を表示します。入力不要の識別名で、パスワードマネージャーがサイトごとの保存項目を区別するための手がかりです。保存・更新の確認では、このIDが対象サイトと一致していることを確認してください。URLを移動した場合は保存項目の見直しが必要です。

フォームはユーザー名・現在のパスワード・新しいパスワードの用途をブラウザに伝えますが、保存先や上書きの判断はブラウザ／パスワードマネージャー側で行われます。アプリから保存項目の完全分離や既存項目の自動移行は保証できません。

この分離は意図しないログイン共有を防ぐものです。同一オリジン上の別アプリやスクリプトからの完全な隔離を提供するものではありません。

#### 他者への配布方法

自作したデザインやコンテンツを含めて誰かに配布（納品）する場合、受け取った人が自分の環境で新しく管理者アカウントを設定できるようにするための手順は、バージョンによって異なります。

- [SQLite版]{.type-badge .badge-sqlite}: サーバー上に空のファイル `mikanData/reset-accounts.txt` を設置してください。次回アクセス時に、登録済みのユーザー、端末、未使用のコードがすべて削除され、初回セットアップ画面が表示されます。このファイルは処理後に自動的に削除されるため、置いたままになる心配はありません。受け取った人は、自分で作ったトークンで「[最初の端末を登録する](#device-setup)」の手順を行います。
- [flat版]{.type-badge .badge-flat}: `mikanData/settings.json` ファイル内の `"password_hash"` の値を空にしてください。

#### セキュリティ

`admin.php` 以外のファイル（ `data` フォルダ内のJSONファイルなど）は、ブラウザから直接アクセスできないようになっています（ `.htaccess` 等による制限）。

## 全体像 {#overview}

mikanBoxは、以下の4つのパートでサイトを構築・管理します。

### [description]{.material-symbols-outlined .mat-icon}ページ (Pages)

サイトの「実体」となるページ自体を管理します。URL（ID）を決め、タイトルやSEO情報を設定し、本文（Markdown/HTML）を執筆します。

### [save]{.material-symbols-outlined .mat-icon}サイト (Site)

管理メモ、静的サイト生成（SSG）、言語、MCP APIキー、CSVインポート、データ管理／バックアップ、サイト共通設定、端末とユーザー（SQLite版）、パスワード変更（flat版）などサイト運営に関わる設定・管理機能をまとめています。

### [widgets]{.material-symbols-outlined .mat-icon}デザイン (Design)

ページ全体のデザインを設定する [ページ]{.type-badge .badge-page} 、共通部品を作る [パーツ]{.type-badge .badge-part} 、AIエージェントへの指示を書く [AI指示]{.type-badge .badge-ai} の3種類のコンポーネントがあります。ヘッダーやフッター、ナビゲーションなどの共通で使うものは パーツ として作成しておくことで、どこからでも利用できます。デザイン要素（コンポーネント）の管理が主な役割です。

### [image]{.material-symbols-outlined .mat-icon}メディア (Media)

Cloud版では、各画像は「リサイズ▼」「名前変更▼」「WebP に変換」の順で操作します。WebP変換はJPEG・PNGだけに表示します。WebP変換では拡張子を自動的に `.webp` にし、ページ本文・CSS・JavaScript・OGP画像、コンポーネント、サイト共通OGP画像の参照を更新します。公開済みHTMLの反映には再構築・配信更新が必要です。メディアのカテゴリは管理画面上部のカテゴリ選択と連動し、接頭辞付きの画像と `g_` の共通画像を表示します。選択カテゴリはアップロード時のファイル名にも付与しますが、既に英数字の接頭辞がある名前には追加しません。ファイル名検索はこの絞り込み内で行います。

画像、動画、音声などのファイルを管理します。アップロード、一覧確認、リサイズ、および貼り付け用のファイル名コピーを素早く行えます。

## 共通

#### プレビュー

サイトのトップページを開きます（新規タブ）。

#### ログアウト

システムからログアウトします。

#### （各パートの見出しの横の）ヘルプ

ヘルプページを開きます（新規タブ）。

#### AIに質問

各ヘルプボタンの横に表示されます。クリックすると質問欄が開き、GPTまたはClaudeを別タブで起動できます。外部AIへ渡すのは、入力した質問、現在のページ・Helpセクションと、回答に必要な公開情報の参照先です。管理用MCPのAPIキー、管理メモ、非公開ページ、サイト設定は渡しません。

対応するAIサービスで入力欄の自動反映が利用できない場合に備え、同じ質問文をクリップボードにもコピーします。GPTには、現在のHelpセクションに対応する公式公開マニュアルを案内します。日本語表示では日本語版（`https://yoshihiko.com/mikanbox/help_ja.html`）、日本語以外では英語版を使用します。

ClaudeにはHTMLマニュアルを案内せず、匿名・読み取り専用の公開MCP（`https://yoshihiko.com/mikanbox/mcp`）だけを参照するよう指示します。利用前にClaudeの「設定 > コネクタ > 追加 > カスタムコネクタを追加」で、このURLをリモートMCPサーバーとして登録してください。

起動文の冒頭には、公式公開情報を使った操作案内だけを依頼し、外部サービスの操作や個人情報・非公開情報の取得を依頼していないことを明記します。

WebMCPと公開MCP窓口は、対応ブラウザ内のエージェントや構造化検索向けの追加機能です。公開窓口はサイト直下の `サイトURL/mcp` で、匿名・読み取り専用です。管理用の `サイトURL/mikanBox/mcp` とは分離され、APIキー、管理メモ、非公開ページ、サイト設定、書き込みツールを公開しません。GPTは公式公開マニュアルURLを、Claudeは公開MCPを情報源として利用します。

`/mcp` はRemote MCPクライアントが接続するHTTP窓口です。ページ上のWebMCPツールも同じ公開窓口を利用し、`search_help`、`get_help_section`、`get_product_info`、`get_agent_instructions` の4つだけを提供します。旧URLの `mikanBox/public-mcp.php` は互換性のため残ります。

公開MCPは、MCP 2026-07-28のステートレス接続に加え、Remote MCPクライアントとの互換性のためMCP 2025-11-25、2025-06-18、2025-03-26の `initialize` 型Streamable HTTP接続にも対応します。いずれの方式でも匿名・読み取り専用の4ツールだけが利用でき、OAuthやAPIキーは要求しません。

GPTの起動文には人が読む公式マニュアルURLを含めます。Claudeの起動文にはHTMLマニュアルURLを含めず、あらかじめカスタムコネクタへ登録した公開MCPの `search_help`、`get_help_section`、`get_product_info`、`get_agent_instructions` を使うよう指示します。どちらもマニュアル全文を起動文へ埋め込みません。

公開MCPの情報源は、CMS上の公開ページ `help_ja` と `help_en` です。対象ページが `public_dynamic` または `public_static` の場合だけ本文を見出し単位で読み取り、下書きや他のページは公開しません。対象ページが存在しない場合は、mikanBoxに同梱された読み取り専用マニュアルへフォールバックします。

公開ページや紹介ページに同じ質問ボックスを置く場合は、本文へ `{{COMPONENT:_ai_question}}` を記述します。`_ai_question` コンポーネントの内部で `{{AI_QUESTION}}` タグを呼び出すため、必要に応じてコンポーネントのHTMLや配置を編集できます。特定のHelpセクションを明示する高度な使い方では、`{{AI_QUESTION:page-edit}}` のようにタグを直接記述します。

質問文は選択した外部AIへ送信され、そのサービスの履歴等に保存される場合があります。APIキー、パスワード、個人情報、公開前の内容は入力しないでください。

## ページ {#page-mgmt}

作成済みのページを一覧で確認・管理する画面です。

#### [add]{.material-symbols-outlined} 新規作成{.m-btn .m-btn-blue}

新しいページを作成します。クリックするとページ編集エリアが開きます。カテゴリを絞り込んだ状態で新規作成すると、そのカテゴリがあらかじめ設定された状態でページ編集画面が開きます。

### カテゴリでの絞り込み

ページ一覧の上部に、登録されているカテゴリがタグ（クラウド）状に表示され、クリックでそのカテゴリのページだけに絞り込めます。

#### カテゴリ:

- [すべて]{.m-btn .m-btn-gray} — 絞り込みを解除し、全ページを表示します。
- [カテゴリ名]{.m-btn .m-btn-gray} — クリックすると、そのカテゴリを含むページだけに絞り込みます。タグの右上の「×」をクリックすると、そのカテゴリを全ページから一括削除できます（削除モード時のみ表示）。
- [[add]{.material-symbols-outlined}新規]{.m-btn .m-btn-blue} — 新しいカテゴリ名を直接入力して追加します。まだどのページにも設定されていないカテゴリでも、この時点でクラウドに表示されます。
- [[delete]{.material-symbols-outlined}削除]{.m-btn .m-btn-gray} — クリックすると各カテゴリタグに削除用の「×」が表示される「削除モード」に切り替わります。

### キーワード検索 [SQLite版のみ]{.type-badge .badge-sqlite}

#### 検索ボックス

キーワードでタイトル・本文などを検索できます。SQLite版は入力時に一覧を更新し、flat版とCloud版はEnterで検索します。入力欄右の [[close]{.material-symbols-outlined}]{.m-btn .m-btn-gray} ボタンで検索条件をクリアできます。

### ページ一覧

#### 編集・プレビュー

プレビューボタンは3版とも青で表示します。

- [[edit]{.material-symbols-outlined}]{.m-btn .m-btn-blue} — 鉛筆のボタン。クリックすると、そのページの編集画面へ移動します。
- [[edit_square]{.material-symbols-outlined}]{.m-btn .m-btn-blue} — [ビジュアル編集](#visual-edit)で、そのページを開きます。
- [[open_in_new]{.material-symbols-outlined}]{.m-btn .m-btn-blue} — クリックすると、公開設定に応じたURLでページを新しいタブで開きます。
- 「承認待ち」ステータスのページの場合は、確認用の共有URL（プレビュートークン付き）が開きます。[SQLite版のみ]{.type-badge .badge-sqlite}

#### 公開設定

ページごとの公開状態を切り替えるドロップダウンメニューです。変更すると即座に保存されます。

- **下書き** — 非公開。管理者以外はアクセスできません。
- **承認待ち** — [SQLite版のみ]{.type-badge .badge-sqlite} 非公開ですが、推測不可能な確認用URL（`?preview=トークン`、有効期限7日）を知っている人だけが内容を確認できます。承認者へのレビュー依頼に使います。承認待ちのページは一覧の先頭に表示されます。
- **公開(動的)** — PHPで動的に表示します。
- **公開(静的)** — サイト画面の静的サイト生成 (SSG)の設定に従ったディレクトリ、ファイル設定で静的HTMLファイルとして公開します。
- **DB** — ページとしては非公開になり、`{{DATAROW}}`のデータが、`サイトURL/api/ページID`のアドレスのAPIとして読み取れるようになります。

公開(静的)のページをそれ以外の公開設定に設定すると、静的HTMLファイルは削除されます。

#### ID

ページのURLになる識別子（スラッグ）です。例として `news` と設定すると、URLは `/news` の形になります。

#### タイトル

ページのタイトルです。クリックすると編集画面へ移動します。

#### 更新

ページ作成時に設定されます。日時は変更可能です。

#### 表示順

ナビゲーションなどの一覧での表示優先順位です。リスト表示する`NAV_LINKS``NAV_CARDS`のなかで、またこのページ一覧のなかで、数字が小さいほど前（上）に表示されます。0より小さいものは、リスト表示されません。

#### カテゴリ

ページに設定されたカテゴリが表示されます。`{{NAV_LINKS:カテゴリ}}` などで絞り込みに利用されます。

### 静的サイトビルドボタン

#### [auto_awesome]{.material-symbols-outlined} 静的サイトをビルドする{.m-btn .m-btn-blue}

ページ一覧の下部にあります。公開設定が「公開(静的)」のページをすべて静的HTMLファイルとして書き出します。「公開(静的)」のページを編集した際には、他のページとの矛盾が生じる場合もあるので、ここでサイト全体のビルドをしておくことをおすすめします。

## ページ編集 {#page-edit}

ページの内容や設定を細かく編集する画面です。「新規作成」ボタンやページのタイトル・編集ボタンをクリックすると表示されます。

右上の [[edit_square]{.material-symbols-outlined} ビジュアル編集]{.m-btn .m-btn-blue} ボタンで、そのページを[ビジュアル編集](#visual-edit)で開けます。

#### 履歴 [SQLite版のみ]{.type-badge .badge-sqlite}

[history]{.material-symbols-outlined .mat-icon} アイコン付きのドロップダウンです。保存するたびに過去の内容が自動的に最大10件保存され、日時と編集者名（複数ユーザーで運用している場合）付きで選択できます。過去のリビジョンを選ぶと内容がフォームに読み込まれ、「過去のリビジョンをプレビュー中」という警告バナーが表示されます。そのまま [[save]{.material-symbols-outlined}保存]{.m-btn .m-btn-blue} を押すと、そのリビジョンの内容が現在のバージョンとして復元されます。ドロップダウンの先頭（「最新バージョン (現在)」）を選び直すと、最新の内容に戻ります。

#### 更新日

ページ作成時に設定されます。日時は変更可能です。下書き・承認待ちなど非公開の状態から「公開(動的)」「公開(静的)」へ切り替えたタイミングで、実際に公開した日時に自動的に更新されます（すでに公開済みのページを編集しただけでは変わりません）。

#### タイトル

ページのタイトルです。必須項目です。コンポーネント内では `{{TITLE}}` や `{{FULL_TITLE}}`（「ページタイトル - サイト名」の形式）で出力できます。

#### 公開設定

ページの公開状態をラジオボタンで選択します。

- **下書き** — 非公開。管理者以外はアクセスできません。
- **承認待ち** — [SQLite版のみ]{.type-badge .badge-sqlite} 非公開ですが、推測不可能な確認用の共有URL（`?preview=トークン`、有効期限7日）が自動生成され、この画面にも表示されます。URLを知らせるだけで、承認者に管理画面へログインさせずに内容を確認してもらえます。
- **公開(動的)** — PHPで動的に表示します。
- **公開(静的)** — サイト画面の静的サイト生成 (SSG)の設定に従ったディレクトリ、ファイル設定で静的HTMLファイルとして公開します。
- **DB** — ページとしては非公開になり、`{{DATAROW}}`のデータが、`サイトURL/api/ページID`のアドレスのAPIとして読み取れるようになります。

公開(静的)のページをそれ以外の公開設定に設定すると、静的HTMLファイルは削除されます。

#### 確認用共有URL [SQLite版のみ]{.type-badge .badge-sqlite}

公開設定を「承認待ち」にすると表示されます。テキストボックスにURLが入り、隣の [[content_copy]{.material-symbols-outlined}コピー]{.m-btn .m-btn-gray} ボタンでクリップボードにコピーできます。

mikanBox 2.9.5以降、このURLには7日間の有効期限があります。期限が過ぎたURLは開けなくなるので、この画面を開き直して新しいURLを確認し、渡し直してください。同じ日のうちは同じURLが表示されます。2.9.5より前に発行したURLは、更新後は使えません。確認用URLのページには、リファラを送らない・検索エンジンに載せない・キャッシュしない指定が付きます。

#### メモ

管理者だけが見られる非公開のメモ欄です。覚えておきたいことや引き継ぎ事項などを自由に入力できます。サイトには一切表示されず、AI（MCP）にも渡りません。

#### ID

URLになるページの識別記号（スラッグ）です。半角英数字とハイフンが使用できます。ページのURLは `サイトのURL/ID` の形になります。既存のIDと同じものを指定して保存すると、その内容で上書きされますのでご注意ください。indexページのIDは変更できません。ID自体に「/」を使用することもできます。静的サイトの際、IDに「/」が含まれていると、その部分がディレクトリとして扱われます。また、動的サイトの場合も擬似的にディレクトリ構造が作られます。例えば、`news/2024` のようなIDを設定すると、`サイトのURL/news/2024` のようなURLになります。

#### デザインコンポーネント

このページのレイアウトに使用するページコンポーネントを選択します。「デザイン」メニューで「ページコンポーネントとして使用する」にチェックを入れたコンポーネントが選択肢として表示されます。

#### カテゴリ（カンマ区切り）

ページを分類するカテゴリをカンマ区切りで自由に入力します。入力欄の下に現在使用中のカテゴリが表示されます。カテゴリの一覧ページは自動では作成されません。必要な場合は、ページを作成し、`{{NAV_LINKS:カテゴリ}}` や `{{NAV_CARDS:カテゴリ:コンポーネントID}}` を配置してください。

#### 表示順

ナビゲーションなどでの並び順を指定できます。数字の小さい順に並びます。0より小さいものは、リスト表示されません。

#### サムネール・OGP画像

SNSでシェアされた際や、カード一覧などで表示される画像ファイル名（例: `ogp.jpg`）を指定します。`meta` タグの `og:image` として出力されます。コンポーネント内では `{{OGP_IMAGE}}` で利用できます。

#### キーワード

ページの検索用キーワード（meta keywords）をカンマ区切りで入力します。コンポーネント内では `{{KEYWORDS}}` で出力されます。

#### ページ概要 (meta description)

ページの概要となる説明文を設定します。 `{{DESCRIPTION}}` で出力され、検索結果のタイトル下に表示される紹介文として利用されます。本文欄とすき間なく接続して表示され、ひと続きの内容として編集できます。

#### 本文 (Markdown or HTML)

ページのメインコンテンツを Markdown 記法やHTMLで記述します。MarkdownとHTMLは混在できます。AIが生成した複雑なHTMLをそのまま貼り付けても正常に動作します。利用できるMarkdown記法と独自タグは編集画面下部のガイドを参照してください。詳しくは [Markdown](#markdown)・[コンポーネント（タグ）](#components) の項目を参照してください。

#### ページ専用CSS

このページだけに適用したいスタイルを記述します。自動的にスコープ化されるため、他のページや本文以外の部分へ影響を与えません。CSSのなかでも独自のタグが使えます。

レイアウトなどスコープ外の要素へ意図的にスタイルを適用する場合は、セレクタ全体を `:global(...)` で囲みます。たとえば `:global(.hero_box) { display: none; }` と記述すると、`.hero_box` だけにスコープ外からスタイルを適用できます。通常のセレクタはこれまでどおり、このページの本文内だけに適用されます。

#### ページ専用JavaScript

mikanBox 2.6.10以降で利用できます。CSS欄と同じ太字の見出しを持つ、折りたたみ式の専用欄に、`<script>` タグを付けずにJavaScriptを記述します。コードがある場合は欄が開いた状態で表示されます。CMSがページ本文末尾（通常は `</body>` の直前。閉じタグのないHTMLでは末尾）へスクリプトを自動挿入します。コンポーネントのJavaScriptに続いて、このページのコードが一度出力されます。動的表示・プレビュー・静的HTMLのいずれでも利用できます。

JavaScriptにはCSSのスコープ設定は適用されません。JS欄ではMarkdown変換・独自タグの展開・URLの自動補完は行われず、コードをそのまま使用します。HTML本文に直接書く `<script>` も引き続き利用できます。外部ライブラリへの依存など、必要な読み込み順はコード側で指定してください。

#### [save]{.material-symbols-outlined} 保存{.m-btn .m-btn-blue}

ページの内容をすべて保存します。

#### [open_in_new]{.material-symbols-outlined} プレビュー{.m-btn .m-btn-blue}

保存していない本文・CSS・JavaScriptなど、編集画面の現在の内容を新しいタブで確認します。プレビューでは保存や公開は行いません。内容をさらに変更した場合は、もう一度プレビューを開いてください。新規ページでも利用できます。

#### [arrow_back]{.material-symbols-outlined} 一覧へ戻る{.m-btn .m-btn-gray}

ページ一覧へ戻ります。未保存の内容は失われますのでご注意ください。

#### [delete]{.material-symbols-outlined} 削除{.m-btn .m-btn-red}

ページを完全に削除します。削除後は元に戻せません。

編集画面下部には、Markdown記法の簡易ガイドと、利用可能なタグ一覧（タグガイド）が折りたたまれた状態で表示されます。クリックで展開できます。

## ビジュアル編集 {#visual-edit}

ページを、**実際の見た目のまま**開いて、本文やページ専用CSSを、その場で直せる画面です。サイトのレイアウト・CSS・画像がそのまま表示されるので、仕上がりを見ながら、Markdownを書き換えられます。管理画面と同じログインが必要で、ログインしていないときは、管理画面のログインへ移ります。公開デモ（デモモード）のサイトでは使えません。

#### 開き方

- ページ一覧の [[edit_square]{.material-symbols-outlined}]{.m-btn .m-btn-blue} ボタン（鉛筆と、プレビューのボタンの間）。
- ページ編集画面の右上の [[edit_square]{.material-symbols-outlined} ビジュアル編集]{.m-btn .m-btn-blue} ボタン。
- 管理フォルダの `visual.php`（`admin.php` と同じ場所）を直接開く。ページを選ぶ画面が出ます。

#### 本文のブロックを直す

- 段落・見出し・リスト・表などを**クリック**すると、その部分のMarkdownが入力欄になります。保存は ⌘/Ctrl+Enter、やめるときは Esc です。保存しても、ページは読み込み直されません。
- 入力欄の上のバーで、見出し・太字・斜体・リンク・箇条書き・番号つきリスト・引用・コード・画像を入れられます（⌘/Ctrl+B・I・K も使えます）。バーを使っても、入力欄の取り消し（⌘/Ctrl+Z）は効きます。
- 画像は、入力欄に**貼り付け**（またはドラッグ）でも入れられます。`media` フォルダに保存され、`![](ファイル名)` が入ります（png・jpg・gif・webp、10MBまで）。
- 入力欄の下のボタンで、そのブロックの上・下に段落を足す、ブロックを複製する、削除する（確認のため、**2回押す**）ができます。
- HTMLのブロックは、タグが閉じるまでの途中に空行があっても、**ひとつのブロック**として開きます。
- 開いたブロックが `<div>` や `<ul>` のような入れ物のときは、ボタンの [[subdirectory_arrow_right]{.material-symbols-outlined}]{.m-btn} で、**中の要素を編集対象**にできます（バッジの数字が、中の要素の数です）。中が1つならそのまま、並んでいれば「1 `<li>` …」のように番号を選びます。上の階層は `div › p` のように表示され、[[arrow_back]{.material-symbols-outlined}]{.m-btn} でひとつ外に戻ります。中を対象にしたときの「上・下に段落を足す」「複製」「削除」は、その要素に対して働き、足すものは同じタグで包まれます。書きかけがあるときは切り替えられません（先に保存か取り消し）。開きタグと子要素、または子要素どうしが同じ行にあるものは、行で分けられないので選べません。
- ナビのカードなど、`{{…}}` のタグが作る部分をクリックすると、タグの1行が開きます。カードの文字や画像は、リンク先のページの設定から読み込んでいるので、ここでは直せません。開いた欄の下のリンクから、そのページ（本文・設定）へ移れます。
- 編集中は、本文の中のリンクを押しても移動せず、編集が開きます。リンク先へ行くには、⌘/Ctrl+クリックするか、右下の「編集中」を押して「編集オフ」にします。

#### 本文全体・ページ専用CSS

- 右下の「本文」で、ページ本文の全体のMarkdownを、画面の下のパネルで直せます。入力すると、すぐページに反映されます。
- 「CSS」で、そのページ専用のCSSを直せます。入力しながら反映され、保存は ⌘/Ctrl+Enter です。未保存のまま閉じると、元に戻ります。

#### 元に戻す・やり直す

- 右下の ↶ ↷（⌘/Ctrl+Z、⌘/Ctrl+Shift+Z）で、ブロック・本文・CSSの保存を、直近3回分まで戻せます。ページを開き直す（ほかのページへ移る、再読み込みする）と、この履歴は空になります。
- 右下の [[history]{.material-symbols-outlined}]{.m-btn .m-btn-blue} で、**編集の履歴**が開きます。ページを開いて最初に保存したときの、保存する前の状態が、1回の作業につき1件、最大10件まで残ります。選ぶと、その状態に戻します（直前の状態は、↶ で戻せます）。
- 保存してもステータスは変わりません。新規作成と複製だけが、下書きになります。
- flat版では、履歴をデータフォルダの `visual-history/` に保存します（バックアップには含まれません。ページを削除すると、一緒に消えます）。SQLite版では、管理画面のページ編集にある履歴（リビジョン）に残ります。

#### ページの切り替え・新規作成・複製

- ⌘/Ctrl+K で、横から、ページの一覧が出ます。いま開いているページが一番上に、その次に、最近開いたページが並びます。タイトルとIDで絞り込めます。
- 「新規ページ」と「このページを複製」（各ページの行の複製ボタンも）で、ページを作れます。**いつも下書きで作ります**。公開するには、管理画面で、ステータスを変えてください。IDの決まりは、管理画面と同じです。
- 入力欄の外で、`g` のあとに `l` で管理画面（ページ一覧）、`g` のあとに `e` でこのページの設定、`g` のあとに `p` でページ選択の画面を、開きます（管理画面は、別のウィンドウで開きます）。

#### 確かめる道具

- 虫眼鏡: ページ上の要素をクリックすると、その要素のセレクタ（クラス名など）の候補が出ます。コピーして、ページ専用CSSに使えます。各セレクタの行の [[edit]{.material-symbols-outlined}]{.m-btn} で、**その行の階層の要素を編集対象にして**ブロックのエディタが開きます（上の行はクリックした要素、下の行ほど外側の親です。本文のブロックの中の要素のときだけ）。
- 画面幅: スマホ（375）・タブレット（768）・PC（1200）・全幅の幅で、同じページを表示します。CSSの入力は、この表示にも、すぐ反映されます。

#### 安全のためのきまりと制限

- 書き込みは、管理画面と同じログインと、CSRFトークン、同一サイトからの要求の確認を通ったものだけです。
- ページ自身のスクリプト（インライン・外部のタグ）は、この画面では動きません。ログイン中の管理者の権限で、ページのスクリプトを動かさないためです（見た目と編集には影響しません）。サイトの外部のスタイル・画像・フォントは、表示されます。
- 「Raw HTML」のページと、`{{DATA…}}` のブロックは、クリックでは直せません。「本文」のパネルで直します。HTMLの途中のブロック（`<div>` の開始だけ、など）の削除は、HTMLが壊れるので、断ります。
- 画面の文字は、管理画面の言語の設定に従います。

#### 更新したあとに

2.9.x 以前から更新するときは、更新のしくみ自体が新しくなるため、ビジュアル編集のファイルは、その更新では入りません。更新のあとに、サイト画面の「システム更新」で、**[再インストール]** を1回実行してください（FTPで上書きしても入ります）。ファイルが入ると、ページ一覧にビジュアル編集のボタンが出ます。

### システム更新

最新版を使用中の場合は [再インストール] を選べます。同じバージョンのプログラムファイルを入れ直すもので、更新がうまく適用されずプログラムファイルが不完全な状態になったときの復旧手段です。記事・設定・画像には触れません。

更新時は、記事・設定・画像・データベース・静的出力には触れず、プログラムファイルだけを置き換えます。更新前のプログラムはサーバー上の保護領域へ1世代分保存され、更新に失敗した場合は自動的に元へ戻ります。更新後は、表示される [元に戻す] ボタンから直前のバージョンへ復元することもできます。

### 静的サイト生成 (SSG) {#site-ssg}

mikanBoxは、PHPで動的にページを表示するだけでなく、サイト全体を「静的なHTMLファイル」として書き出す機能（SSG: Static Site Generation）を備えていて、混在することも可能です。

#### SSGのメリット

- **超高速な表示** — サーバーがPHPを実行する必要がないため、高速に表示されます。
- **高セキュリティ** — 公開領域にPHPファイルやデータ(JSON)を置かない構成にできるため、改ざんリスクを極限まで減らせます。

#### 静的サイトの作成方法

- **サーバー内で静的ページを生成** — 基本的にサイトルートへHTMLを書き出します。別の場所へ生成する場合だけ、出力先ディレクトリを指定します。
- **アップロード用フォルダを作成（ローカルで運用している場合）** — HTMLと `media/` を専用の出力先へまとめて書き出します。サイトルート、mikanBox本体、既存のmediaフォルダと重なる出力先は安全のため指定できません。

アップロード用フォルダでは、ページや画像を出力先からの相対リンクにする「相対リンク（推奨）」と、指定した公開先URLへ固定する「公開URL固定」を選択できます。相対リンクではフォルダを別の場所へ移動してもリンクが保たれます。

公開先ルートURLは、どちらのリンク方式でも入力できます。`https://example.com/site` のように、公開先のルートを丸ごと指定します。Cloudflare PagesやNetlifyのように公開URLが決まっている場合は、そのURL（例: `https://yoursite.pages.dev`）をそのまま入れてください。

公開先ルートURLは、静的サイトを書き出すときにだけ使われます。手元で動かしている管理画面やプレビューは、いま開いているアドレスを使うため、公開先ルートURLを入れても画像やリンクがそちらを向くことはありません。

- **公開URL固定** — 必須です。ページ内のリンクと `sitemap.xml` `rss.xml` の両方に使われます。
- **相対リンク** — 任意です。ページ内のリンクには使われません。`sitemap.xml` と `rss.xml` の生成にだけ使われ、空欄ならこの2つは生成されません。

#### 出力先ディレクトリ

静的HTMLファイルの書き出し先を、`mikanBox` フォルダが置かれている場所（サイトルート）を基準にした相対パスで指定します。例えば `blog` と入力するとサイトルート直下の `blog/` フォルダの中に書き出され、`../` と入力するとサイトルートより1つ上の階層に書き出されます。未指定（空欄）の場合は、サイトルート直下に直接書き出されます。

「サーバー内で静的ページを生成」で空欄の場合はサイトルートへ生成します。「アップロード用フォルダを作成」を選ぶと、出力先の初期値として `export` が設定されます。必要に応じて別の専用フォルダ名へ変更できます。

#### 出力構成 / URL形式

生成するHTMLファイルの形式を選択します。

- **ディレクトリ型 (folder/index.html)**: `ページID/index.html` の形で書き出します。URLは `/ページID/` となります。
- **ファイル名型 (filename.html)**: `ページID.html` の形で書き出します。URLは `/ページID.html` となります。

ディレクトリ型は、動的公開と同じURLで公開できます。切り替えてもリンク切れが起こりません。ファイル名型は、URLに拡張子が含まれ、シンプルなファイル構成で公開できます。

初期値は、「サーバー内で静的ページを生成」ではディレクトリ型、「アップロード用フォルダを作成」ではファイル名型です。作成方法ごとに最後に選んだ出力構成を記憶するため、切り替えてもそれぞれの設定が保たれます。

#### [auto_awesome]{.material-symbols-outlined} 保存して静的サイトをビルド{.m-btn .m-btn-blue}

設定を保存した上で、公開設定が「公開(静的)」のすべてのページを静的HTMLファイルとして書き出します。

ページIDに `/`（スラッシュ）を含めると（例: `news/2024`）、そのままディレクトリの階層構造として扱われます。静的ビルド時は、実際に `news/2024/index.html`（ディレクトリ型）のように、出力先ディレクトリのなかに本当のフォルダが作られ、そのなかにファイルが生成されます。

ビルドは画面を切り替えずにその場で実行され、生成したファイル数が通知で表示されます。設定や開いている欄はそのまま残ります。

#### サイトマップ・RSS・Podcast RSSの扱いについて

`sitemap.xml` `rss.xml` `podcast.xml` は、通常はアクセスのたびにPHPがその場で最新の内容を生成します（後述の[サイトマップ・RSS・API](#site-mapfeed)を参照）。SSGでサイトマップやRSSをファイル出力するには絶対URLが必要なため、公開先ルートURLが設定されている場合に生成します。「サーバー内で静的ページを生成」では、未設定時に現在のサイトURLを使用します。生成後にページを追加・変更しても、次に静的サイトをビルドし直すまでは内容が更新されません。

404ページ（ページID `404`）は、サイトマップにもRSSにも含めません。エラー応答であってコンテンツではないため、検索エンジンや読者に案内する対象ではないからです。これは静的・動的のどちらの生成でも同じです。

### MCP APIキー {#site-mcp-key}

AIエージェント（Claude Codeなど）がMCP経由でこのサイトに接続するためのAPIキーを発行・管理します。

mikanBoxの管理用MCPサーバーは、ステートレスな **MCP 2026-07-28** に加え、移行期間の互換性確保のため、`initialize` を使う MCP 2025-11-25、2025-06-18、2025-03-26にも対応します。いずれの方式でも管理用APIキーによる認証が必要です。

接続には、AIアプリが提供するネイティブのRemote MCP（Streamable HTTP）機能を使用します。

- MCPエンドポイント: `サイトURL/mikanBox/mcp`（旧URLの `mcp.php` も利用可能）
- プロトコル: `2026-07-28`、`2025-11-25`、`2025-06-18`、`2025-03-26`
- 認証: `Authorization: Bearer 発行したAPIキー` または `X-API-Key: 発行したAPIキー`

固定ヘッダーを設定できるクライアントでは、発行したAPIキーを上記のいずれかのヘッダーとして指定します。APIキーをURLのクエリ文字列へ入れてはいけません。

各ツールには、読み取り専用か、既存データを上書き・削除しうるかを示す注釈（`readOnlyHint`、`destructiveHint`、`idempotentHint`）が付いています。対応するMCPクライアントはこれを見て、ページの更新や削除など影響の大きい操作の前に確認を求めます。また、ページやコンポーネントの本文を返すツールには `untrustedContentHint` が付き、取得した本文は資料として扱われ、AIへの指示としては扱われません。

Claudeのカスタムコネクタ画面が扱う認証は「認証なし」またはOAuthです。表示されるOAuth Client IDとOAuth Client シークレットは管理用APIキーの入力欄ではありません。mikanBoxがOAuthに対応するまでは、管理用MCPをClaudeカスタムコネクタへ安全に登録できません。APIキーをClient ID／シークレット欄へ貼り付けないでください。認証不要の公開ヘルプMCPは、カスタムコネクタへURLだけで登録できます。

APIキーはパスワードと同じように扱い、公開リポジトリや共有ファイルへ記録しないでください。複数のmikanBoxサイトを接続している場合、AIは初回接続時と書き込み前に `get_site_info` を呼び、対象サイトを確認します。

mikanBox 2.5.1以降では、MCPの接続指示によりAIは初回接続時に `get_ai_context` を呼びます。このツールは `DESIGN.md`、`BRAND.md`、`CONTENTS.md` など、登録されているすべての [AI指示]{.type-badge .badge-ai} コンポーネントを一度に返します。AIは受け取った内容をそのサイト固有のプロジェクト指示として、コンテンツ・デザイン・コードの変更に適用します。指示コンポーネントを更新すれば、次回取得時からAIへの指示も更新されます。

#### 接続URL

このサイトの管理用MCPのURLです。「コピー」で、そのままクライアントの設定に貼り付けられます。

- [[content_copy]{.material-symbols-outlined}コピー]{.m-btn .m-btn-gray} — 接続URLをクリップボードにコピーします。

#### APIキー

発行済みのAPIキーが読み取り専用の欄に表示されます。未発行のときは欄は出ず、「APIキーを生成」だけが表示されます。

- [[content_copy]{.material-symbols-outlined}コピー]{.m-btn .m-btn-gray} — APIキーをクリップボードにコピーします。生成したキーは、Claude Desktopなど接続するツール側の設定（`.mcp.json`など）に貼り付けて使用します。
- [[auto_awesome]{.material-symbols-outlined}APIキーを生成]{.m-btn .m-btn-blue} — （未発行のとき）新しいAPIキーを発行します。
- [[auto_awesome]{.material-symbols-outlined}APIキーを再生成]{.m-btn .m-btn-gray} — （発行済みのとき）現在のキーを無効化し、新しいキーを発行します。既存のAI連携設定は再設定が必要になります。

#### MCPの有効・無効と最終使用日時（PHP版）

「MCP を有効にする」を外して保存すると、管理用MCPはキーを保持したまま停止します。HTTP接続は403を返し、ローカルstdio接続も次の要求から拒否します。処理中の要求を途中で取り消すものではありません。公開ヘルプMCPは利用できます。既存の接続は更新後も有効で、再び有効にすると同じキーで接続できます。漏洩したキーは停止だけでなく再生成してください。サーバーのファイルを直接編集する権限を持つツールまで制限する機能ではありません。

現在のキーについて、HTTPで認証に成功した最終使用日時をUTCで表示します。保存は最大1時間に1回で、無効なキーや公開ヘルプの利用では更新しません。キーを再生成すると記録なしに戻ります。キーを使わないローカルstdioの利用は含めません。

### 操作の記録（PHP版） {#site-audit}

サイト画面の「最近の操作記録」に直近50件を表示します。MCPキーの発行・再発行・有効化・停止、ページの公開状態の変更、ログイン失敗を両PHP版で記録します。SQLite版では端末登録・停止、招待・端末追加コードの発行、ユーザー削除、復旧・アカウント初期化も記録します。プログラムを以前の版へ戻す操作も成功時に記録します。

記録するのは日時、操作、実行者、必要な対象ID、伏せたIPです。キー、トークン、コード、パスワード、本文、完全なIPは保存しません。IPv4は末尾を、IPv6は48ビット以降を伏せます。約1 MBを上限に古い記録から削除します。記録できない場合は管理画面に通知しますが、成功した操作を失敗扱いにはしません。

ログとMCP状態はデータフォルダの `security/` に保存します。`events.jsonl.php` はWebからの実行を拒否するPHPガード行の後にJSON Linesが続く形式です。Apacheのアクセス拒否とフロントコントローラーでもデータ領域を保護します。PHPを通さず静的ファイルを配信するサーバーでは、データフォルダ全体をWebから読ませない設定も必要です。データフォルダを含むバックアップには操作履歴も入るため、安全に保管してください。サーバーのファイルを書き換えられる人による改変を検出する監査証跡ではありません。

### CSVインポート {#csv-import}

CSVデータをサイト内で利用できるデータベースの形（DATAROWブロック）に変換するツールです。

PHP版はサイト画面、Cloud版はデータ移行・インポート画面にあります。

#### ファイルを選択

CSVファイルを選択します。エンコーディング（UTF-8 / Shift-JIS）は自動判定します。

#### [content_copy]{.material-symbols-outlined} 変換してコピー{.m-btn .m-btn-gray}

1行目をフィールド名として読み込み、各行を `{{DATAROW:連番}}` ブロックに変換してクリップボードにコピーします。コピー後、ページ編集の本文に貼り付けて保存してください。

#### 使い方のポイント

- フィールド名（1行目）は英数字で記述してください。
- 価格の位取りカンマ（例: `1,000`）はExcelが自動的にクォートするため正しく読み込めます。
- データ専用ページは**下書き**にしておくことを推奨します。訪問者には見えませんが、`{{POST_MD:pageID#rowID:FIELD}}` や `{{NAV_CARDS}}` からは参照できます。
- 公開設定を**DB**にすると、ページとしては非公開になり、`{{DATAROW}}`のデータが、`サイトURL/api/ページID`のアドレスのAPIとして読み取れるようになります。

### サイト共通設定 {#site-settings}

最上段は左に変更不可のサイトID、右にサイト名を表示します。サイトURLなどの説明は入力欄の下に配置しています。

サイト共通設定は、最初の行に左側のサイト名と右側の変更できないサイトIDを同じ幅で表示します。次の行にサイトURLを表示し、説明は入力欄の下に配置します。静的サイト生成の作成方法の補足説明は通常の文字の太さで表示します。Cloud版のJSONデータの一括バックアップ・復元は、サイト設定の「データ移行・インポートツール」から専用ページを開きます。

#### サイトID（AI識別用）

サイトごとに自動生成される変更不可のIDです。複数のmikanBoxサイトをAIへ接続したとき、AIが操作対象を取り違えないために使用します。既存サイトでは、サイト共通設定の保存時またはAIが初めてサイト情報を確認したときに生成されます。

#### サイト名

サイトの名前を設定します。 `{{SITE_NAME}}` で出力できます。 `{{FULL_TITLE}}` は、「ページタイトル - サイト名」という形で表示され、ブックマークや検索時のページタイトルなどにも利用されます。

#### サイトURL

AIが操作対象を確認するためのURLです。通常は空欄のままで、トップページの `index.php` がある場所をHTTPリクエストから取得します。SSGの出力先・公開先とは別です。別の公開URLをAIに伝えたい場合だけ指定してください。この設定でサイトの移動・リダイレクトやSSGの出力先変更は行いません。CLI接続ではHTTP情報がないため、必要ならURLを明示してください。

#### サイト環境

本番、ステージング、開発、ローカル、未指定から選択します。AIはMCPの `get_site_info` を使い、サイトID・サイト名・URLとともにこの環境を確認できます。

用途を伝える目印で、操作やアクセスを自動で制限する機能はありません。例えばAIが試験用のページ変更を行う前に、接続先が「本番」と分かれば、開発用のサイトに切り替えるか確認する判断材料になります。サイトIDと併せて確認する運用が必要です。MCPのサイト識別対応としてv2.3で追加されました。

#### サイトの共通概要

サイトの概要を設定します。ページごとの概要が設定されていない場合は、検索時のページ概要として、この設定が利用されます。`{{SITE_DESCRIPTION}}` で出力されます。

#### 共通キーワード

サイトのキーワードを設定します。ページごとのキーワードが設定されていない場合は、検索に使われるキーワードとして、この設定が利用されます。

#### 共通OGP画像

サイト共通のOGP画像を設定します。ページごとのOGP画像が設定されていない場合は、SNSでシェアされる際に使われるOGP画像として、この設定が利用されます。`{{SITE_OGP_IMAGE}}` で出力されます。推奨サイズは 1200 × 630 px です。

#### ページ一覧の表示件数 (1ページあたり)

「ページ」画面の一覧を、何件ごとにページ分割するかを指定します（初期値: 30件）。ページ数がこの件数未満の場合、ページ送りのリンクは表示されません。

#### メディア一覧の表示件数 (1ページあたり)

「メディア」画面の一覧を、何件ごとにページ分割するかを指定します（初期値: 100件）。

#### [save]{.material-symbols-outlined} 保存{.m-btn .m-btn-blue}

「サイト共通設定」の内容を保存します。

### 端末とユーザー [SQLite版のみ]{.type-badge .badge-sqlite} {#site-users}

管理画面に入れる端末と、編集者のアカウントを管理する機能です。編集者ごとに端末を登録でき、編集履歴には編集者名が記録されます。パスワードはありません（「[初回設定とログイン](#first-setup)」を参照）。端末の管理（画面ロックや紛失時の対応）は利用者の責任です。なくした端末は、ほかの端末からここで止めてください。

#### ユーザーと端末

ユーザーごとに、そのユーザーの端末をまとめて表示します。ユーザー名と表示名、端末の名前、登録日時、最終利用、期限が分かります。自分の端末には「（この端末）」と表示されます。

- [止める]{.m-btn .m-btn-red} — その端末と、発行した未使用コードを止めます。止めた端末はすぐにログアウトされ、再び使うには追加用のコードが必要です。自分の端末を止めると、ログアウトと同じになります。管理画面の右上に、ログアウトのボタンはありません。
- コードで追加した端末は、登録から3日間、ほかの端末を止めたり、ユーザーを削除したりできません。盗まれたコードで追加された端末に、持ち主が締め出されるのを防ぐためです。最初の端末には制限がありません。
- ほかの人が新しい端末を登録したときは、次に管理画面を開いたときにお知らせが出ます。心当たりがなければ、この一覧で止めてください。
- 自分のユーザーには、「表示名」の入力欄があります。編集履歴などに表示される名前を変えて、「保存」を押します。ユーザー名は変更できません。
- [[delete]{.material-symbols-outlined}削除]{.m-btn .m-btn-red} — ほかのユーザーを削除します。そのユーザーの端末と、発行した未使用の招待コードを含むコードも一緒に消えます。削除後は元に戻せません。ログイン中のユーザーと、最後の1人は削除できません。端末停止・ユーザー削除のDB処理が失敗した場合は、関連する変更をまとめて取り消し、エラーを表示します。

#### 端末を追加する

追加用のコードを出します。新しい端末で管理画面を開き、コードを入力してください。コードは3時間有効で、1回だけ使えます。コードは出した直後の画面にだけ表示され、あとから見ることはできません。

##### ほかの人を招く

招待のコードを出して、招待したい人に渡します。ユーザーIDと表示名は決めません。招待された人が、ログイン画面でコードと端末の名前を入力すると、ユーザーIDと表示名を決める画面が出ます（半角英数字・アンダースコア・ハイフンのみ）。決めて登録すると、そのユーザーが作られ、端末が登録されます。ほかの人が使っているユーザーIDは選べません。選べなかった場合でも、コードは使われずに残ります。

#### 未使用のコード

発行済みでまだ使われていないコードの一覧です。「取り消す」で無効にできます。

#### 使わない端末が切れるまで

使わない端末の有効期間を、30日・90日・180日から選びます。端末を使うたびに期間は延びます。期限が切れた端末は、コードで追加し直す必要があります。

**すべての端末を失った場合：** 「[すべての端末を失ったとき（復旧）](#device-recovery)」の手順で、新しいトークンから登録し直します。

## データ移行・インポートツール {#data-migration}

SQLite版では、管理画面（`admin.php`）とは別の独立したツール（`convert.php`）です。ブラウザで `mikanBox/convert.php` に直接アクセスして利用します。データベースやメディアの現在の状態確認と、外部データの一括インポートを行えます。

### 現在の状態

#### SQLiteデータベース状態

データベースファイルの作成有無・ファイルサイズ・登録ページ数・登録コンポーネント数・登録ユーザー（編集者）数を確認できます。

#### メディアファイル状態

保存ディレクトリ・登録メディアファイル数・総メディア容量を確認できます。

### コンテンツパッケージ (ZIP) インポート

`posts/`・`components/` フォルダなどを含むZIPパッケージ（テーマや初期データ一式）をアップロードして、現在のSQLiteデータベースに取り込みます。取り込まれるのは `posts/` と `components/` の中身のみで、`settings.json` の中身（サイト設定の値）が読み込まれることはありません。

ZIP内で `テーマ名/posts/` のように外側のフォルダに入っていても、`posts/` または `components/` がある階層を起点として扱い、外側のフォルダ名はIDに含めません。画面の「ZIP内のファイルの置き方」を開くと配置例を確認できます。Macが作成する `__MACOSX` や `._` の補助ファイルは取り込みません。

ページのIDは、`posts/` 以下の**フォルダ名とファイル名**（拡張子を除いた部分）が使われます。例えば `posts/coffee/menu.json` は `coffee/menu` です。コンポーネントのIDも `components/` 以下のパスから決まります。中身に書かれているタイトルなどとは関係ありません。既存IDと重複するものはスキップされ、上書きはされません。特定のページ・コンポーネントを上書きするような形で取り込みたい場合は、先に管理画面側の該当データを削除してからインポートするか、取り込みたいJSONファイルの名前を目的のIDに変更してからZIPに含めてください。

取り込みが終わったフォルダは `import/` フォルダ配下に `{フォルダ名}_imported` という名前にリネームされ、そのまま残ります（削除はされません）。

#### ファイルを選択

アップロードするZIPファイルを選択します。

#### [publish]{.material-symbols-outlined} アップロード & インポート{.m-btn .m-btn-orange}

選択したZIPファイルをインポートします。

### Cloud版のデータ入出力

サイト設定から`/admin?view=import`を開きます。SQLite版と同じ構成の状態カード、ZIP取込、WordPress XML取込、実行ログを表示します。ページ・コンポーネント・ユーザー数、メディア数・総容量を確認できます。PHPの保存ディレクトリやSQLiteファイルサイズはCloudには表示しません。

ZIPは`posts/`・`components/`のJSONだけを取り込み、既存IDはスキップします。settings.json、アカウント、画像は取り込みません。WordPress WXRでは公開記事を動的ページ、承認待ちを承認待ち、それ以外を下書きとして取り込み、本文を簡易Markdownへ変換します。画像は別途アップロードしてください。ZIP/XMLは20MB以内、ZIP展開サイズは合計15MB以内、取込内容はUTF-8換算1MB以内・合計300件以内です。ZIPは非圧縮・Deflateに対応し、暗号化や破損したZIPは拒否します。ZIP展開・XML解析はブラウザーで行います。

後段にCSV変換とCloud固有のJSON一括バックアップ・復元を配置します。JSON一括復元は、ZIP/XMLでの追加取込と異なり、現在のサイトデータを置き換えます。既存の管理者パスワード確認とユーザー復元の設定に従います。取込後は静的ページを再構築してください。サイト設定の2列入力欄、アカウント管理の折りたたみ欄、カテゴリの新規ボタンは共通CSSで表示をそろえています。

---

ページ一覧・メディアのキーワード検索は検索欄のクリアから解除できます。カテゴリによる絞り込みは維持します。Cloudの画像名変更は、使用箇所がある場合にキャンセル・名前だけ変更・参照も更新から選べます。画像の変更にCloud公開接続は不要です。接続設定はサイト画面のユーザー管理の下にあります。完全バックアップ（復元用・JSON）は画像・ユーザー・編集履歴まで含み、個別のデータ・メディア保存より広い範囲を復元します。現在のD1画像保存には400 MBの上限があり、復元時は現在の画像と復元分などの合計を450 MB以内に収める必要があります。

### Cloud版: D1からR2への移行（開発版 v0.5.0）

最初はR2を有効にせずD1で利用できます。サイト画面の「メディアの保存先」で現在の保存先と使用量を確認し、「D1からR2へ移行」を実行します。これは画像・アップロードしたJS/CSSの保存先の切り替えで、ページ・設定・ユーザーなどはD1に残ります。

R2の準備にはCloudflareで支払い方法を登録してR2を有効にする必要があります。無料枠内でも登録が必要です。バケットを作成し、WorkerのR2接続名を `MEDIA` にします。ローカルのWrangler設定にはテスト用接続がありますが、公開用設定にR2接続は追加していません。公開用 `wrangler.production.json` に次の設定を追加し、実際のバケット名でコードをデプロイしてください。この準備だけでは保存先は切り替わりません。

```json
"r2_buckets": [{"binding": "MEDIA", "bucket_name": "実際のバケット名"}]
```

現在の管理者パスワードを入力して移行を開始します。1画像ずつコピーし、チェックサムとR2への保存結果を検証します。移行中はD1の原本を表示し、画像の追加・変更・削除を止めます。画面を閉じても、同じメニューから再開・中止できます。全件の確認が完了するとD1の画像データを除去し、R2の参照へ一括で切り替えます。未完了・失敗・中止ではD1の原本を保持します。成功後にD1へ戻すメニューはありません。移行前に完全JSONバックアップを保存してください。画像URLと本文中のファイル名は変わりません。

D1の画像上限は400 MBです。D1 Freeは1DB500 MB、Paidは1DB10 GBまでで、プラン変更は別途必要です。R2へ移行すると画像合計400 MBの制限を外し、1画像10 MB・10,000件の制限を維持します。R2 Standardの無料枠はアカウント全体で月間10 GB-month・書込み系100万回・読出し系1,000万回です。容量の上限ではなく超過分は課金されます。

サイト画面にはD1のDB使用量と、管理対象のR2容量（一時画像・保持画像を含む）を表示し、無料枠の80%程度で注意を表示します。他サイトや管理外のR2オブジェクトは含みません。実際のアカウント全体の使用量・リクエスト数・料金はCloudflareで確認してください。料金通知は利用を停止する機能ではありません。D1から画像を削除してもDBの確保済み領域がすぐ小さくなるとは限りません。

R2の書き換えは新しい一意のオブジェクトへ保存してからD1の参照を切り替えます。「不要な一時画像を整理」で、使用中・移行中・復元中の画像を除き、24時間以上保持した未使用画像を最大20件ずつ削除できます。完全JSONバックアップは画像も含み、D1・R2のどちらの保存先にも復元できます。復元先の保存先設定は維持します。D1復元は画像400 MB・現在と一時画像の合計450 MBまで、R2復元は原本と一時画像の両方を使用量に含めます。D1 Time TravelとSQL書き出しにはR2の画像実体が含まれず、古い参照先が整理済みの場合は戻せません。R2では完全JSONバックアップを使用してください。

画像は保存先にかかわらず `/media/ファイル名` をWorkerから配信し、画像操作にCloud公開接続は不要です。画像リクエストはWorkerの利用枠を消費します。R2利用時はD1のメタデータ読出しとR2の読出しも発生します。生成済みのページHTMLはStatic Assetsから直接配信します。名前変更・WebP変換で更新した本文や部品を公開済みのHTMLへ反映するには、通常の再構築・配信更新が必要です。

支払い方法を登録せず、Cloudflare公式のローカルWorker・D1・R2を組み合わせて確認するには、Cloudフォルダで `node scripts/test-r2-local.mjs` を実行します。専用の一時データを作成し、移行・中止・画像操作・バックアップ復元の15項目を検証して削除します。既存のローカルデータや実サービスには接続しません。これはローカルでの結合テストで、実際のR2への接続権限・通信・課金を確認するものではありません。結果は `artifacts/r2-local-system-test.json` に保存します。

参考: [D1の制限](https://developers.cloudflare.com/d1/platform/limits/)、[R2の料金](https://developers.cloudflare.com/r2/pricing/)、[R2の初期設定](https://developers.cloudflare.com/r2/get-started/)、[料金と使用量](https://developers.cloudflare.com/billing/understand/usage-based-billing/)。

#### 編集

この [[edit]{.material-symbols-outlined}編集]{.m-btn .m-btn-blue} ボタンをクリックすると、そのコンポーネントの編集画面へ移動します。


コンポーネント一覧では「AIに聞く」の右側のセレクタで、すべて（初期状態）、選択中のカテゴリ、ページ、パーツ、AI指示、標準コンポーネントを選べます。標準コンポーネントはIDが `_` で始まるものです。タイプはページ・パーツ・AI指示の設定で判定します。通常の新規作成・複製では `_` を付けず、標準扱いを意図する場合は付けて構いません。名前による保存拒否は行いません。 「選択中のカテゴリ」は管理画面上部のカテゴリを使い、画像と同様にIDの接頭辞で判定します。例えば `apps_header` は `apps` カテゴリに含まれます。カテゴリ未選択時は絞り込みません。
#### コンポーネントID

コンポーネントの識別記号です。クリックしても編集画面へ移動します。「_」で始まるIDは、初期設定で用意されているシステムコンポーネントです。これらを編集して使用することもできます。

'{{COMPONENT:_global_head}}'には、'<head>'タグ内の共通設定が記述されていて、CSSを集約出力する'{{HEAD_CSS}}'もあらかじめ含まれています。`{{HEAD_CSS}}`はCSSの挿入位置を指定する任意のタグです。複数ある場合は最初の1つにだけCSSを出力し、残りのタグは取り除きます。省略時は`</head>`の直前へ自動挿入し、閉じタグがない場合はHTML先頭へ挿入します。AIによる出力をそのまま利用する際には、デザインコンポーネントで「なし（本文のHTMLをそのまま使用）」を、それ外は'_layout'をベースに使用するとよいでしょう。もちろん、他にも自由に作成できます。その際は「_」をつける必要はありません。

#### ラッパーなし・共通の読み込み

デザインコンポーネントの「なし（本文のHTMLをそのまま使用）」は、`_layout`などのラッパーを使わず本文を表示します。完成済みのHTMLではRaw HTMLを有効にしてください。MCPでは`wrapper_comp: "__none"`を指定します。未指定は従来どおり`_layout`です。

全版で、本文のHTMLにあるtitle・metaは上書きせず、不足分だけhead内へ補います。charsetはUTF-8、viewportは`width=device-width, initial-scale=1.0`、titleは`{{FULL_TITLE}}`と同じ値です。description・OGP画像は、タグがなくページまたはサイト設定に値がある場合だけ補います。日本語・英語のタイトルをそのまま使い、自動翻訳はしません。robots・canonicalは自動追加しません。headがない場合は作成し、HTML断片には最小限のhtml・head・bodyを補います。既存タグの重複を自動で削除する処理は行いません。

サイト設定の「共通の読み込み」→「計測ID」に、GoogleタグのID（`G-…`）またはタグマネージャーのコンテナID（`GTM-…`）を入力すると、公開ページへ計測タグを自動挿入します。IDの種類は先頭の文字で自動判別します。`G-…`はhead内にgtag.jsを、`GTM-…`はhead内のスクリプトに加えて、body開始直後にnoscriptも挿入します。空欄で無効になります。

サーバーサイドGTMやConsent Modeの初期化など、標準のタグでは足りない場合は、その下の「コードを直接入力する（上級者向け）」を開き、「head用コード」と、必要に応じて「body開始直後用コード」へ貼り付けます。コードは入力どおりに挿入され、`{{...}}`タグも展開しません。コードが入力されている間は計測IDより優先され、IDの欄は読み取り専用になります。

以前の「計測コンポーネント」で設定していた場合、設定画面を開くと、そのパーツのHTMLが「head用コード」に表示されます。そのまま保存すると新しい設定へ移行し、元のパーツは変更されません。パーツがコンポーネントタグ・JavaScript・CSSを含む場合は自動では移行せず、保存するまで従来どおりに動作します。

計測ID・head用コード・body開始直後用コードのいずれかが設定されているときだけ、ページ編集のデザインコンポーネント欄の下に「このページでは計測タグを読み込まない」が表示されます。チェックすると、head・bodyの自動挿入を抑止します。以前の計測コンポーネントが使われている場合は、そのパーツの通常の埋め込みも抑止します。MCPでは`exclude_tracking: true`で指定します。HTMLに直接記述された計測コードや、別のコンポーネントの計測コードは抑止しません。プレビューもページの設定に従います。設定変更後は静的ページを再ビルドしてください。


#### タイプ

コンポーネントの種類を示します。一覧では [AI指示]{.type-badge .badge-ai} タイプが上部にまとめてソートされます。

- [ページ]{.type-badge .badge-page} — 「ページコンポーネントとして使用する」にチェックが入ったコンポーネントです。ページ編集の「デザインコンポーネント」で選択できます。
- [パーツ]{.type-badge .badge-part} — ページや他のコンポーネントに埋め込む部品です。
- [AI指示]{.type-badge .badge-ai} — サイトのデザインルールなど、AIエージェントに読み込ませるための指示書です（`DESIGN.md`, `BRAND.md` など）。

#### タグ名

コンポーネントを埋め込むためのタグ（例: `{{COMPONENT:header}}`）が表示されます。クリックするとクリップボードにコピーされます。ページの本文や他のコンポーネントのHTMLに貼り付けて利用します。

## デザイン編集 {#design-edit}

コンポーネントの構造（HTML・CSS・JavaScript）と設定を定義する画面です。

#### コンポーネントID

コンポーネントの識別記号です。必須項目です。半角英数字とアンダースコアが使用できます。テンプレート内で `{{COMPONENT:ID}}` として呼び出せます。タイプで「AI指示」を選んだ場合はドット（`.`）も使用でき、末尾に `.md` が付いていなければ保存時に自動的に付与されます。

#### メモ

管理者だけが見られる非公開のメモ欄です。サイトには一切表示されず、AI（MCP）にも渡りません。

#### タイプ

ラジオボタンで3種類から選択します。

- [パーツ]{.type-badge .badge-part} — ページや他のコンポーネントに埋め込んで使う部品です。
- [ページ]{.type-badge .badge-page} — ページ全体をレイアウトするコンポーネントです。選択するとデザイン一覧で [ページ]{.type-badge .badge-page} として表示され、ページ編集画面の「デザインコンポーネント」で選べるようになります。以下のタグが追加で利用できます。
  - `{{CONTENT}}` — ページの本文が出力される位置に挿入します。
  - `{{HEAD_CSS}}` — ページとコンポーネントのCSSを集約して挿入します。省略時は`</head>`直前（閉じタグがなければHTML先頭）へ自動挿入します。複数ある場合は最初の1つだけを使用し、残りは取り除きます。
- [AI指示]{.type-badge .badge-ai} — CSSエディタ・CSSスコープ化のチェックボックスなど、デザインには不要な項目が非表示になり、本文欄がプレーンなテキスト入力（Markdown/HTML兼用）に切り替わります。デザインルールなど、AIエージェントに読ませたい内容をそのまま書けます。これ自体をAIに生成させることもできます。

#### HTML (タイプが「パーツ」「ページ」の場合)

コンポーネントの内容をHTMLで記述します。ここで使える独自のタグは、編集画面下部のガイドを参照してください。他のコンポーネントを入れ子にして読み込むこともできます。

#### 本文 (Markdown / HTML) (タイプが「AI指示」の場合)

AIエージェントに伝えたい内容を自由に記述します。Markdown・HTMLどちらでも構いません。

MCP接続時には `get_ai_context` がすべてのAI指示コンポーネントを一括取得します。用途ごとに `DESIGN.md`、`BRAND.md`、`CONTENTS.md` などへ分けて管理しても、AIへは効率よくまとめて伝えられます。

#### CSS (この部品専用のスタイル) (タイプが「パーツ」「ページ」の場合)

このコンポーネントのなかだけに適用したいスタイルを記述します。CSSのなかでも独自のタグが使えます。

#### CSSをスコープ化する (他の部品への影響を防止) (タイプが「パーツ」「ページ」の場合)

チェックボックスです。通常はONを推奨します。CSSで記述した内容が、他の部分に影響することを防ぎます。サイト全体に適用したいグローバルなリセットCSSや `<head>` 用の部品を作る場合のみチェックをはずします。

スコープをONにしたまま一部のセレクタだけをグローバルにするには、セレクタ全体を `:global(...)` で囲みます。例：`:global(.hero_box) { display: none; }`。スコープがOFFのコンポーネントはもともとグローバルなため、`:global(...)` は不要です。

#### JavaScript (タイプが「パーツ」「ページ」の場合)

2.6.12以降は、同じコンポーネントIDのJSを1ページにつき一回にまとめます。2.6.10〜2.6.11では埋め込みごとに出力していました。

CSS欄と同じ太字の見出しを持つ、折りたたみ式の専用欄に、`<script>` タグなしでコードを記述します。通常の `{{COMPONENT:ID}}` 呼び出しでは、同じコンポーネントIDのJSを1ページにつき一回だけ、ページ本文末尾へ出力します。入れ子では呼び出し元、子の順に収集し、同じIDが再登場しても最初の収集位置を保ちます。カード一覧・検索結果の部品も、通常の埋め込みと共通で同じIDにつき一回です。その後、まだ収集していないデザインコンポーネント（ラッパー）のJS、ページ専用JSが続きます。異なるIDのJSやページ専用JSは、コードが同じでもそれぞれ出力します。コードの自動スコープ化は行いません。「AI指示」ではJS欄を表示せず、JavaScriptとしての配信・実行もしません。

JavaScript欄は他の開閉欄と同じ「JavaScript ▼」の表示で、見出し行全体をクリックして開閉できます。

2.7.0以降は、JSだけを読み込む際にファイル名だけで記述でき、編集画面にもHTMLの記述例を表示します。

保存済みのコンポーネントのJavaScript欄には、JSだけを読み込むための記述例、その下にパスの自動補完の説明と完全なJavaScript専用URLが表示されます。ページとコンポーネントのJavaScript欄の説明・表示順は全版共通です。`component-js/ID.js` ではHTML・CSSの有無に関係なく、JS欄の内容だけを取得できます。IDの大文字・小文字は保存したものと一致させてください。例えば `Test` のJSだけを読み込むには、本文や部品のHTMLに次のように書きます。JavaScript欄には書きません。

```html
<script src="Test.js" defer></script>
```

保存済みの通常コンポーネントに対応する `ID.js`（`./ID.js` も可）は、画像のファイル名と同じように、設置先とページ階層に合わせて専用URLへ自動補完されます。`component-js/Test.js` と書く方法も使えます。該当する部品がないファイル名や外部URLは補完しません。静的サイトの書き出しでは `component-js/` にJSファイルが同梱され、相対URLモードでは出力ページの階層に合わせて参照が補完されます。URL書き換えを使わない環境では `index.php?component_js=Test` でも取得できます（このクエリ形式はPHPサーバー用です）。存在しないID・不正なID・AI指示は404、JS欄が空の通常コンポーネントは空のJavaScriptを返します。

通常の `{{COMPONENT:Test}}` 埋め込みではJSも自動で出力されるため、上記のscriptタグは不要です。ページ内に同じコンポーネントを複数配置しても、JavaScriptの初期実行は一度だけです。クリックなどのイベント処理は、その都度実行されます。また、CSSのスコープ設定はJavaScriptには適用されません。JS欄のコードは、独自タグを展開せずそのまま使います。外部URLでの読み込みと通常のコンポーネント埋め込みを併用した場合も、自動で実行回数を調整しません。例えば同じ部品のボタンを3個置く場合、コードの初期実行は一度だけなので、`document.querySelectorAll()` で3個すべてを取得し、一つずつクリック処理を設定します。`document.querySelector()` は最初の一つだけを取得します。読み込み順はコード側で設計してください。MCPの `create_page`・`update_page`・`create_component`・`update_component` でも `js` フィールドで設定できます。

#### [save]{.material-symbols-outlined} 保存{.m-btn .m-btn-blue}

コンポーネントを保存します。

#### [arrow_back]{.material-symbols-outlined} 一覧へ戻る{.m-btn .m-btn-gray}

「デザイン」管理画面に戻ります。未保存の内容は失われますのでご注意ください。

#### [delete]{.material-symbols-outlined} 削除{.m-btn .m-btn-red}

コンポーネントを完全に削除します。削除後は元に戻せません。

編集画面下部には、利用可能なタグ一覧（タグガイド）が折りたたまれた状態で表示されます。クリックで展開できます。

## メディア {#media-mgmt}

画像・音声・動画ファイルのアップロードと管理を行う画面です。


### JS・CSSライブラリのアップロード

ブラウザーでそのまま使える `.js`・`.css` ファイルもメディアにアップロードできます。JS・CSSはUTF-8のテキスト、空でないファイル、1ファイル10 MB以下が対象です。PHP版ではサーバーのアップロード上限も適用します。ファイル名は半角英数字・`_`・`-`・`.`を使い、それ以外は`_`に置き換えます。拡張子は小文字に揃えます。パスや危険な二重拡張子は受け付けません。

JS・CSSにはカテゴリ接頭辞を付けず、カテゴリを選んでいても一覧に表示します。画像のリサイズ・WebP変換は適用しません。「ファイルの種類」で画像・音声・動画・JS・CSSを絞り込めます。JS・CSSのカードには「URLをコピー」「読み込みタグをコピー」があり、管理画面でファイルのコードを実行しません。名前変更で拡張子は変更できません。同名ファイルは上書きせず、PHP版は連番を付け、Cloud版は別名でのアップロードを求めます。更新時は `library-1.2.3.min.js` のようなバージョン付きの名前を推奨します。

読み込みタグはページ本文やデザインコンポーネントのHTMLに貼ります。JS欄・CSS欄には貼りません。

```html
<link rel="stylesheet" href="media/library-1.2.3.min.css">
<script src="media/library-1.2.3.min.js" defer></script>
```

これらの `media/` パスは、ページ階層に合わせて補完され、静的書き出しにもファイルが含まれます。アップロードしただけではページへ自動挿入しません。読み込み順や `type="module"` などはライブラリの説明に従って指定してください。複数ファイルのフォルダ構造をまとめてアップロードする機能はありません。CSSやJSが相対パスで別ファイルを参照する場合は、その配置も利用者側で調整します。

アップロードはコード編集と同じく、信頼できる管理者・MCP APIキーから行ってください。形式検査はコードの安全性を保証するものではありません。提供元と内容を確認して利用します。PHP版は `media/` 内のファイルとして保存し、ApacheではJS・CSSの配信形式と `nosniff` を設定します。Apache以外ではサーバー側で `text/javascript` / `text/css` と `X-Content-Type-Options: nosniff` を設定してください。Cloud版は既存のメディア保存設定に従ってD1またはR2へ保存し、どちらも同じ `/media/ファイル名` で配信します。バックアップ・復元とD1からR2への移行にも含まれます。ページ・コンポーネントのコード欄の内容は、引き続きD1に保存します。MCPの `upload_media` もJS・CSSに対応します。

### アップロードエリア

#### ファイル選択

「ファイルを選択」をクリックしてアップロードするファイルを選択します。このウィンドウにファイルをドラッグ＆ドロップすると、ドロップした段階でアップロードできます。

#### [upload]{.material-symbols-outlined} アップロード{.m-btn .m-btn-blue}

選択したファイルをアップロードします。

#### アップロード設定...

「アップロード設定...」をクリックすると展開します。ここでの選択はアップロード時にだけ適用され、ブラウザに記憶されるため次回以降も同じ設定が使われます。ドラッグ＆ドロップでアップロードした場合も同じ設定が適用されます。

- **長辺を〇〇pxに制限** — 画像の長辺が指定した値を超えている場合、縦横比を維持したまま縮小して保存します。既定は 2000px です。スマートフォンやデジタルカメラの写真をそのまま貼り付けると数千ピクセルの巨大な画像になりがちで、表示速度を大きく損ないます。これを防ぐための設定です。
- **WebP に変換（jpg / png のみ）** — 画像を WebP 形式に変換して保存します。ファイルサイズがおおむね 25〜35% 小さくなります。拡張子が `.webp` に変わるため、ファイル名も変わります。jpg は非可逆（品質82）、png は可逆で変換されるため、スクリーンショットや図版の文字がにじむことはありません。

いずれも**元の画像データは残りません**。原寸のまま配布したいファイルには使わないでください。

gif と svg はどちらの対象にもなりません。gif はアニメーションが失われるため、svg は拡大しても劣化しないベクター形式であるためです。

また、画像の画素数が大きすぎてサーバーのメモリ上限に収まらない場合は、自動処理を行わずに元のファイルのままアップロードし、その旨を表示します（アップロード自体は成功します）。

メディア画面の案内は、対応形式・JS/CSSの条件・ページ内での利用方法を表示します。画像変換の補足とサーバーの最大サイズ表示は省略します。Markdownではパスを省略できます。HTMLでは `media/ファイル名` を指定します。

#### 対応形式・制限

jpg, png, gif, webp, svg, mp3, m4a, mp4 に対応しています。最大ファイルサイズはサーバーの設定に依存します。

アップロードされたファイルは `media` ディレクトリに保存されます。Markdown や HTML での参照方法：

- Markdown: `![説明](ファイル名)` または `{{IMAGE:ファイル名}}`（`{{AUDIO:ファイル名}}`、`{{VIDEO:ファイル名}}`）
- HTML: `media/ファイル名` を標準として指定します（例: `<img src="media/ファイル名">`）。画像では従来の `images/ファイル名` とファイル名だけの指定も引き続き利用できます。

### カテゴリでの絞り込み

「ページ」画面でカテゴリを絞り込んだ状態からメディア画面に遷移すると、そのカテゴリの接頭辞が付いたファイル名（例: `blog_photo.jpg`）だけに自動的に絞り込まれます。「カテゴリ「〇〇」で絞り込み中」という案内とともに、以下のボタンが表示されます。

#### [filter_list]{.material-symbols-outlined} カテゴリ絞り込みを適用する{.m-btn .m-btn-blue}

現在のカテゴリでの絞り込みを有効にします（既定の状態）。

#### [visibility_off]{.material-symbols-outlined} カテゴリで絞り込みしない{.m-btn .m-btn-orange}

一時的に絞り込みを解除し、すべてのメディアファイルを表示します。

「ページ」画面でカテゴリを絞り込んだ状態からメディア画面に遷移してアップロードすると、ファイル名の先頭に自動的にそのカテゴリ名の接頭辞が付きます（例: カテゴリ「blog」で `photo.jpg` をアップロード → `blog_photo.jpg`）。ただし、ファイル名がすでに何らかの接頭辞（英数字＋`_`）で始まっている場合は、二重に付与されることはありません。

ファイル名は `_` で区切って複数のカテゴリ名を含めることができます。例えば `blog_news_001.jpg` という名前にしておくと、「blog」カテゴリで絞り込んだ時にも「news」カテゴリで絞り込んだ時にも、どちらでも表示されます。また、`g_` から始まるファイル名（例: `g_logo.png`）は、常にどのカテゴリで絞り込んでも表示される「共通（グローバル）」画像として扱われます。

### メディア一覧

#### プレビュー

画像はサムネイルが表示されます。動画・音声ファイルはアイコンが表示されます。

#### ファイル名（クリックでコピー）

ファイル名をクリックするとクリップボードにコピーされます。ページの本文へ貼り付けて使用します。

#### 形式・サイズ表示

ファイルの形式（例: JPG）と、画像の場合は解像度（幅×高さ）が表示されます。

#### [delete]{.material-symbols-outlined} 削除{.m-btn .m-btn-red}

メディアファイルを削除します。削除後は元に戻せません。

#### リサイズ...

「リサイズ...」をクリックすると展開します。幅(W)または高さ(H)のどちらか一方を入力して [[save]{.material-symbols-outlined}]{.m-btn .m-btn-blue} を押すと、縦横比を維持したままリサイズされます（jpg, png, webp のみ対応）。リサイズ後は元のサイズに戻せません。

gif は対象外です。処理に使用しているライブラリがアニメーションの1コマ目しか読み込めないため、リサイズするとアニメーションが失われてしまうためです。gif のサイズを変更したい場合は、専用のツールで作り直してからアップロードしてください。

また、画像の画素数が大きすぎてサーバーのメモリ上限に収まらない場合は、リサイズを行わずにその旨を表示します。

#### 名前変更▼

「名前変更▼」をクリックすると展開します。ファイル名を書き換えて [[save]{.material-symbols-outlined}]{.m-btn .m-btn-blue} を押すと、メディアファイルの名前を変更できます。既存のページ・コンポーネント内でそのファイル名が使われている場合は確認ダイアログが表示され、以下から選べます。

- **リンクを更新** — ファイル名を変更し、そのファイルを参照しているページ・コンポーネント内の記述も新しいファイル名に一括で書き換えます。
- **ファイル名のみ変更** — ファイル名だけを変更し、既存の参照は書き換えません（参照先が見つからなくなる点に注意してください）。
- **変更しない** — 名前変更をキャンセルします。

PHP版ではサイト共通OGPで使っている場合も確認されます。「リンクを更新」はページ本文・CSS・JavaScript・ページOGP、コンポーネントのHTML・CSS・JavaScript、サイト共通OGPの該当するファイル名を更新し、似た別のファイル名やメモ・過去の版は変更しません。SQLite版では更新対象のページやコンポーネントが編集中の場合、操作を中止します。静的ページへの反映には再ビルドが必要です。

---


### メディアの操作

ファイル名検索とページ送りも全版で共通の配置です。検索は現在のカテゴリ絞り込み内で行います。

アップロード設定は「アップロード設定▼」で開閉します。 アップロード、名前変更、リサイズ、WebP変換、削除の後も、可能な範囲でメディア一覧のスクロール位置を保ちます。各ファイルの操作は「リサイズ▼」「名前変更▼」「WebP に変換」の順です。リサイズの幅・高さと名前変更の入力欄、保存ボタンは同じ高さで表示します。幅または高さを指定すると縦横比を維持して変更します。

既存のJPEG（jpg/jpeg）・PNGだけに「WebP に変換」を表示します。WebP・GIF・SVG・音声・動画には表示しません。PHP版ではサーバーのWebP変換機能が必要です。変換すると拡張子が`.webp`になり、ページ本文・CSS・JavaScript・OGP画像、コンポーネントのHTML・CSS・JavaScript、サイト共通のOGP画像の参照を更新します。メモ・過去の版は変更しません。同名のWebPが存在する場合は上書きせず、元画像と参照を保持します。静的ページは再ビルドしてください。Cloud版はブラウザーで画像を変換し、保存します。更新した参照を静的HTMLに反映するには再構築・配信更新が必要です。操作完了まで画面を開いたままにしてください。

## Markdown {#markdown}

ページの本文では、標準的なMarkdown記法を使うことができます。

Markdown記法については、ページ編集画面の下部に使用できる記法についてのガイドがあります。

### MarkdownとHTML

MarkdownとHTMLは混在できます。本文は基本的にMarkdownとして処理されますが、以下のHTMLタグから始まる行はHTMLコードとして扱われます（Markdown変換されません）。

`html` `head` `body` `div` `section` `article` `aside` `header` `footer` `main` `nav` `form` `p` `h1`〜`h6` `ul` `ol` `li` `dl` `dt` `dd` `table` `thead` `tbody` `tr` `th` `td` `blockquote` `pre` `figure` `figcaption` `details` `summary` `dialog` `a` `span` `button` `select` `video` `audio` `script` `style` `link` `meta` `<!-- コメント -->` など

開始タグ・終了タグ（`</div> </a>` など）どちらも対象です。前後に改行を入れる必要はありません（入れても表示は変わりません）。

前後に空行があり、HTMLタグやMarkdown記号がなければ「段落」として扱われ`<p>〜</p>`で囲まれます。段落内の改行は`<br>`になります（HTMLタグの直前・直後には入りません）。段落の中にHTMLタグを混ぜることも可能です。

Markdown＋HTML混在では対応しきれない複雑なレイアウトの場合は、ページ編集画面の「Raw HTML」チェックボックスをONにすると、Markdown処理を完全に無効化してHTMLをそのまま出力できます。

### 段落

前後に空行をいれることで、HTMLタグやMarkdown記法の記号がなければ、段落として扱われ `<p>内容</p>` のようにタグで囲まれます。段落のなかで改行すると `<br>` タグが挿入されます。また、段落のなかで、HTMLタグを挿入することも可能です。

### 見出し

行頭で `## 見出し` のように使うと見出しとして扱われ、 `<h2>見出し</h2>` の形で出力されます。通常、`#` で示される `<h1>` タグはページタイトルに使用されるので、本文内では、 `## 見出し` `### 小見出し` を利用するのが良いでしょう。`#` 記号の後にスペースを入れる必要があります。

Markdown:`## 見出し`
HTML:`<h2>見出し</h2>`

### その他のブロック要素

リスト、番号付きリスト、引用、水平線、インラインコードについては、行頭で使用することで、それぞれのHTMLに置き換えられます。

Markdown:`- リスト項目`
HTML:`<ul><li>リスト項目</li></ul>`

Markdown:`* リスト項目`
HTML:`<ul><li>リスト項目</li></ul>`

番号付きリスト `1.`：`<ol><li>`
Markdown:`1. 番号付きリスト項目`
HTML:`<ol><li>番号付きリスト項目</li></ol>`

リスト項目は`-`または`*`どちらも使えます。これらは、記号の後にスペースを入れる必要があります。

Markdown:`> 引用`
HTML:`<blockquote>引用</blockquote>`

記号の後にスペースはあってもなくても構いません。

Markdown:`---`
HTML:`<hr>`


### コードブロック

コードは、行頭にバッククォートを3つ以上、またはチルダ（`~`）を3つ以上だけ書いた行で囲みます。閉じる行には、開く行と同じ文字を、同じ数以上並べます。囲まれた中は、Markdown、HTML、`{{タグ}}` のどれも変換されず、書いたとおりに表示されます。HTMLでは `<pre><code>…</code></pre>` になります。

- 開く行の後ろに、言語名を1語だけ書くと（例：`php`、`json`、`html`）、`<code class="language-php">` のように、`language-` で始まるクラスが付きます。CSSやハイライトのライブラリで、言語ごとに見た目を変えるときに使えます。
- コードの中に、バッククォート3つのコードブロックを書きたいとき（Markdownの書き方を説明するページなど）は、外側のフェンスを4つ以上のバッククォートにするか、チルダにします。中のフェンスより長ければ、中のフェンスでは閉じません。
- 閉じる行を書き忘れると、そこから最後までが、コードとして扱われます。

### 文中で使用できるインライン要素

Markdown:`**太字**`
HTML:`<strong>太字</strong>`

Markdown:`*斜体*`
HTML:`<em>斜体</em>`

### リンク

リンクは `[リンクしたい文字](URL)` の形で指定できます。 `<a href="URL">リンクしたい文字</a>` の形で出力されます。

Markdown:`[リンクしたい文字](URL)`
HTML:`<a href="URL">リンクしたい文字</a>`

### メディアの利用

画像を表示する際には、 `![画像の説明](filename)` でページに埋め込むことができます。`[ ]` のなかには、画像の説明を入れ、 `<img src="画像のURL" alt="画像の説明">` の形で出力されます。メディア管理でアップロードした画像は、ファイル名を指定するだけで利用できます。また、独自タグの `{{IMAGE:ファイル名}}` の形でも同様に利用できます。メディア管理で管理している音声や映像ファイルは、 `{{AUDIO:ファイル名}}` `{{VIDEO:ファイル名}}` で利用することができます。

Markdown:`![画像の説明](filename)`
HTML:`<img src="画像のURL" alt="画像の説明">`

独自タグ:`{{IMAGE:ファイル名}}`
HTML:`<img src="画像のURL">`

#### 自動的に付与される属性

`media` ディレクトリにある画像を参照した場合、出力される `<img>` タグには表示速度のための属性が自動的に付きます。書き方を変える必要はありません。

- `width` / `height` — 画像本来の縦横のピクセル数。ブラウザが読み込み前に表示場所を確保できるため、画像が表示された瞬間にレイアウトがずれる現象がなくなります。
- `fetchpriority="high"` — そのページで最初に現れる大きな画像に付きます。ページの第一印象を決める画像を優先的に読み込ませるためです。
- `loading="lazy" decoding="async"` — 2枚目以降の大きな画像に付きます。画面に近づくまで読み込みを遅らせます。

縦横どちらも 200px 未満の小さな画像（ロゴ、アイコン、区切り線など）には `width` / `height` だけが付き、読み込みの指示は付きません。数KBの画像を遅延させても効果がなく、かえって表示が遅れるためです。

svg と外部URLの画像、および `media` ディレクトリに存在しない画像には何も付きません。ラッパーやコンポーネントに直接書いた `<img>` タグも、書いた内容がそのまま出力されます。

独自タグ:`{{AUDIO:ファイル名}}`
HTML:`<audio src="音声のURL" controls></audio>`

独自タグ:`{{VIDEO:ファイル名}}`
HTML:`<video src="映像のURL" controls></video>`

### テーブルの表示

テーブルは、セルを `|` で区切って表示します。 `|---|` の行を入れることがテーブルとして必須です。1行目が見出し行 `<th>` 、3行目以降がデータ行 `<td>` となります。`|:---|:---:|---:|` のようにコロンを入れることで、表示位置を指定できます。

`| 指定なし | 左寄せ | 中央 | 右寄せ |`
`|---|:---|:---:|---:|`
`| A | B | C | D |`

| 指定なし | 左寄せ | 中央 | 右寄せ |
|---|:---|:---:|---:|
| A | B | C | D |

### クラス・IDの指定（Markdown独自拡張）

Markdownの行末に `{.className}` `{#idName}` を追加すると、その行のブロック要素にCSSの `class` や `id` を指定できます。

Markdown:`## 見出し{.highlight}`
HTML:`<h2 class="highlight">見出し</h2>`

Markdown:`段落テキスト{.note #intro}`
HTML:`<p class="note" id="intro">段落テキスト</p>`

インラインのテキストに対しては `[text]{.className}` の記法でクラス・IDを付与した `<span>` を出力できます。複数クラスやIDとの組み合わせも可能です。

Markdown:`[赤いテキスト]{.red}`
HTML:`<span class="red">赤いテキスト</span>`

Markdown:`[**太字**で強調]{.highlight .bold}`
HTML:`<span class="highlight bold"><strong>太字</strong>で強調</span>`

Markdown:`[アンカー]{#my-id .note}`
HTML:`<span id="my-id" class="note">アンカー</span>`

#### 入れ子のスパン（アイコン付きボタンなど）（Markdown独自拡張）

`[text]{.className}` は入れ子にできます。内側の `[...]{...}` から順に処理され、外側のスパンがそれを包みます。三重以上の入れ子も可能です。

Markdown:`[[save]{.material-symbols-outlined}保存]{.m-btn .m-btn-blue}`
HTML:`<span class="m-btn m-btn-blue"><span class="material-symbols-outlined">save</span>保存</span>`

Material Symbolsなどのアイコンフォントのアイコンを、ボタン風スパンやバッジの中に埋め込む場合に便利です。なお、`[...]{...}` の内容に、対応する `{...}` を持たない裸の `[` を含めることはできません（入れ子のブラケットはスパンとして解釈されるため）。

これらの記法はmikanBox独自のMarkdown拡張です。他のMarkdownレンダラー（GitHub等）では動作しません。

## コンポーネント（独自タグ） {#components}

### タグの利用

ページの本文・CSS、コンポーネントの本文・CSSのなかには、 `{{TITLE}}` などの用意されたタグを使用できます。利用可能なタグは、ページ編集画面・デザイン編集画面の下部にガイドがあります。

### コンポーネントの利用

デザイン管理で作成したコンポーネントは、 `{{COMPONENT:ID}}` の形で、ページや他のコンポーネントに埋め込むことができます。

### 画像・音声・映像

画像・音声・映像は、 `{{IMAGE:ファイル名}}` `{{AUDIO:ファイル名}}` `{{VIDEO:ファイル名}}` の形で埋め込むことができます。

`{{IMAGE:ファイル名}}` → `<img src="media/ファイル名">`
`{{AUDIO:ファイル名}}` → `<audio src="media/ファイル名" controls></audio>`
`{{VIDEO:ファイル名}}` → `<video src="media/ファイル名" controls></video>`

### ナビゲーション

リンクの一覧は `{{NAV_LINKS:カテゴリ}}` はリスト形式 `<li>` で出力されます。

画像付きのカードなどで出力したい場合は、 `{{NAV_CARDS:カテゴリ:コンポーネントID}}` で出力できます。カードのデザインは、コンポーネントで定義できます。コンポーネントIDを省略すると、標準的なデザイン（`_nav_card`コンポーネント）で出力されます。

リストやカードの順番はページの「表示順」で指定できます。表示順が0より小さい場合は、表示されません。

どちらも、カテゴリを「all」にすると全ページのリスト、未設定にするとカテゴリのないページのリストが出力されます。ページのカテゴリは複数設定できるので、カテゴリを適切に設定することで、多様な形でのナビゲーションを設定することができます。

### 他のページの埋め込み

他のページの内容は、 `{{POST_MD:ID}}` の形で埋め込むことができます。AIで作成した複雑なページのなかの一部だけ（お知らせなど）を、簡単に編集できるようにするには、Markdownで作ったページを埋め込むようにすると便利です。埋め込まれる側のページは「下書き」にしておくことで、単独では見えない設定にすることもできます。

### 他のサイトのMarkdown文書の埋め込み

GitHubなど、他のサイトに設置したMarkdown文書を `{{EXT_MD:url}}` の形で埋め込むことができます。GitHub上で直接編集できるのはもちろん、AIエージェントにGitHub上のファイルを書き換えてもらうだけでサイトを更新できる「AIフレンドリー」な運用が可能です。

**Cloud版では使用できません。** `EXT_MD` は、外部のサーバーから文書を取得するタグです。Cloud版は取得しないため、タグの位置には何も表示されません。

### ページコンポーネント

ページ全体をレイアウトするコンポーネントは、本文を出力する `{{CONTENT}}` を挿入してください。CSSの挿入位置を指定する場合は `{{HEAD_CSS}}` を配置します。省略時は `</head>` 直前（閉じタグがなければHTML先頭）へ自動挿入され、複数ある場合は最初の1つにだけ出力され、残りは取り除かれます。基本的な構成は、初期コンポーネントの `_layout` を参照してください。

|`_nav_card`|[パーツ]{.type-badge .badge-part}|カード型ナビゲーションでコンポーネントIDを省略した場合に使用される標準カードデザインです。サムネイル画像・タイトル・概要・日付を表示するカードを出力します。|
|`_ai_question`|[パーツ]{.type-badge .badge-part}|公開ページ用のAI質問ボックス。`{{COMPONENT:_ai_question}}` で配置し、質問、現在のページ、公式公開マニュアルを外部AIへ案内します。|
|`_search_box`|[パーツ]{.type-badge .badge-part}|検索ボックスのデザイン。フォーム内に `<input type="hidden" name="page" value="search">` が書かれているため、送信すると「search」ページ（`_search_result_item` を使って検索結果を表示するページ）に遷移する仕組みです。|
|`_search_result_item`|[パーツ]{.type-badge .badge-part}|検索結果の１件ごとの表示デザイン。`{{SEARCH_RESULTS:_search_result_item}}` の形で検索結果ページに配置します。|

## データの埋め込み、読み込み、API {#data-embedding}

### データの形式

以下の3種類の形式の情報を扱うことができます。

- Markdown: サイト内部、あるいは外部（GitHub等）のMarkdownデータ
- Data: WordPressの拡張フィールドのような、key-value形式の個別データ
- DataBase: `{{DATAROW}}` を用いたテーブル形式のデータ

### Markdownの読み込み

#### 他のページをMarkdownとして読み込める

コンポーネントだけでなく、他のページ自体もMarkdownとして読み込むことができます。複雑なページを直接編集するのではなく、更新用のシンプルなページを更新するだけで、反映させられます。

#### 他のサイトのページをMarkdownとして読み込める

GitHubなど、他のサイトのページをMarkdownとして読み込むことで、サイトに直接触らなくても更新できます。もちろん、セキュリティ上、JavaScriptは動かないようにしています。

### GitHubのページをMarkdownとして出力

GitHubのmdファイルのページは以下のようにURLを変えて、Rawデータにすることで読み込むことができます。

変換前: [https://github.com/yoshihik0/testData/blob/main/md-test.md](https://github.com/yoshihik0/testData/blob/main/md-test.md)

変換後: [https://raw.githubusercontent.com/yoshihik0/testData/main/md-test.md](https://raw.githubusercontent.com/yoshihik0/testData/main/md-test.md)

#### 変換ルール
github.com → raw.githubusercontent.com
/blob/ → /（消す）

読み込み：
`{{EXT_MD:https://raw.githubusercontent.com/yoshihik0/testData/main/md-test.md}}`

#### GitHub以外では：

Dropbox: `?dl=1` に変える
Google Docs: 公開設定して `/export?format=txt`

### ページへのデータの埋め込みと利用

`{{DATA:key}}データ{{/DATA}}`と書くだけで、WordPressの拡張フィールドのように、ページに情報を埋め込んで、ページ内や他のページから利用できます。キー（key）は、半角英数字と「_」を使うことができます。しかも`{{DATA:key:GHOST}}データ{{/DATA}}`のように「:GHOST」を付け加えると、ページ内では表示されなくなります。

ページ内からの利用：`{{POST_MD::key}}`
他のページからの利用：`{{POST_MD:pageID:key}}`

### 他のサイトでのデータの埋め込みと利用

`{{DATA:key}}データ{{/DATA}}`の形式は、GitHubなど、他のサイトのページからも読み込めます。サイトに直接触らなくても更新できるので、AIと相性のよいGitHubを利用すれば、自動運用もしやすいです。

他のサイトからのデータの利用：`{{EXT_MD:url:key}}`

### DB Less DB：ページにデータベースを埋め込める

`{{DATAROW:rowID}}{{DATA:key}}データ{{/DATA}}{{/DATAROW}}`と書くだけで、表形式のデータを埋め込んで、ページ内や他のページから利用できます。データベースを使っていないのに、ページ自体がデータベースになれます。

ページ内のテーブル系形式のデータを表示：`{{POST_MD::#rowID:key}}`
IDページのテーブル系形式のデータを表示：`{{POST_MD:pageID#rowID:key}}`

### 他のサイトのデータベースも読み込める

`{{DATAROW:rowID}}{{DATA:key}}データ{{/DATA}}{{/DATAROW}}`の形式は、GitHubなど、他のサイトのページからも読み込める。

外部ページのテーブル系：`{{EXT_MD:url#rowID:key}}`

### CSVデータを変換

PHP版はサイト画面、Cloud版はデータ移行・インポート画面の「CSVインポート」で、エクセルなどのCSVデータを `{{DATAROW}}` の形式に変換できます。

エクセルから書き出したCSV形式のファイルを選択し、
#### [content_copy]{.material-symbols-outlined} 変換してコピー{.m-btn .m-btn-gray}
をクリックして、データをコピーします。ページ内の本文にペーストして利用してください。

1行目をフィールド名として読み込み、各行を `{{DATAROW:連番}}` ブロックに変換してクリップボードにコピーします。コピー後、ページ編集の本文に貼り付けて保存してください。


### ヘッドレスCMSにもなる

`{{DATAROW}}`を埋め込んだページを、公開設定「DB」で公開することで、外部からAPIで読み取ることができるようになります。

`https://yoursite.com/api/pageID`

例：[https://yoshihiko.com/mikanbox/demo/api/sample-DB](https://yoshihiko.com/mikanbox/demo/api/sample-DB)


### さまざまな情報のカードが作れる

これらの情報は、カード形式の表示（レコードの一覧表示）のなかでも利用できるので、商品情報一覧なども作成できます。

|タグ|内容|
|:---|:---|
|`{{TITLE}}`|ページタイトル|
|`{{UPDATE_DATE}}`|更新日|
|`{{UPDATE_DATE:JP}}`|更新日・日本語|
|`{{UPDATE_DATE:SLASH}}`|更新日・/区切り|
|`{{IS_NEW:30}}`|N日以内 new、それ以外は空|
|`{{DESCRIPTION}}`|ページ概要）|
|`{{OGP_IMAGE}}`|ページのOGP画像のURL|
|`{{PAGE_URL}}`|ページのフルURL|
|`{{POST_MD::name}}`|データの表示|
|`{{POST_MD::date}}`|データの表示|
|`{{POST_MD::#test:book}}`|データの表示ROW|
|`{{IS_ACTIVE}}`|現在のページなら active、それ以外は空|

## ポッドキャスト配信 {#podcast}

音声を張り込んだページを作成し、カテゴリを「podcast」に設定すると、「podcast」カテゴリのページのみのRSSが、以下のURLで出力され、ポッドキャストを配信できます。

`https://yoursite.com/podcast.xml`

おもに、以下の情報を埋め込みます。AUDIO_FILEは必須です。

`{{DATA:AUDIO_FILE:GHOST}}episode01.mp3{{/DATA}}`
`{{DATA:DURATION:GHOST}}25:30{{/DATA}}`
`{{DATA:FILE_SIZE:GHOST}}24500000{{/DATA}}`

### ポッドキャストのページに可能なデータ

`{{DATA:AUDIO_FILE:GHOST}}episode01.mp3{{/DATA}}` ← 必須
`{{DATA:DURATION:GHOST}}25:30{{/DATA}}`
`{{DATA:FILE_SIZE:GHOST}}24500000{{/DATA}}`
`{{DATA:EPISODE_NUM:GHOST}}1{{/DATA}}`
`{{DATA:SEASON:GHOST}}1{{/DATA}}`
`{{DATA:SUBTITLE:GHOST}}今回のテーマは...{{/DATA}}`
`{{DATA:EPISODE_IMAGE:GHOST}}ep01-cover.jpg{{/DATA}}`
`{{DATA:EPISODE_TYPE:GHOST}}full{{/DATA}}`
`{{DATA:EXPLICIT:GHOST}}false{{/DATA}}`

タイトル`{{DATA:TITLE}}`と概要`{{DATA:DESCRIPTION}}`はページの設定から自動で取得します。

利用可能なデータはサービスによって異なります。

### ポッドキャスト配信の手順

1. 🍊mikanBoxでポッドキャストエピソードページを作る（カテゴリ「podcast」）
2. `https://yoursite.com/podcast.xml` が自動で生成される
3. そのURLを各プラットフォームに登録する

登録先：
| プラットフォーム | 登録場所 |
|:---|:---|
|Apple Podcasts|podcastsconnect.apple.com|
|Spotify|podcasters.spotify.com|
|Google Podcasts|google.com/podcasts/publish|
|Amazon Music|music.amazon.com/podcasts|

一度登録すれば、あとは新しいエピソードページを追加するたびに自動で各プラットフォームが `podcast.xml` を取りに来て更新されます。

音声ファイルは🍊mikanBoxのメディアにアップロードしておくだけでOKです。

## AIで作ったデザインをそのまま公開する方法 {#ai-guide}

### ページ全体をAIで作る場合のプロンプト

`CSS・JSも含めて1つのHTMLファイルとして出力して。画像は media/ファイル名 で`

デザインを作るプロンプトに以上の情報を加えてください。

### ページ全体をAIで作った場合の利用法

ページを生成したら、以下の手順で配置します。

1. 「ページ編集」画面で、デザインコンポーネントに「なし（本文のHTMLをそのまま使用）」を選択します。
2. 生成したHTMLのすべての内容を「本文」にペーストして保存してください。

### 複数ページで共通部分を作りたい場合

共通部分（ヘッダー、フッター、&lt;head&gt;内など）を切り分けて管理できます。

- `_header`、`_footer`、`_global_head` などに切り分けて登録してください。
- 「デザインコンポーネント」で `_layout` を選ぶと、これらが自動的に機能します。
- 各ページのSEO情報（タイトル・概要・OGP画像など）を反映させるには、コンポーネント内に `{{COMPONENT:_global_head}}` を入れてください。
- サイト共通や各ページで管理しているCSSは自動挿入されます。挿入位置を指定したい場合は `{{HEAD_CSS}}` を配置してください。
