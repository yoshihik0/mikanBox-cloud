# マニュアル構成メモ

最終確認: 2026-10-30

## 決定した整理方針（2026-10-30）

**共通の章立ては、現在の正規マニュアル `help_ja.md` / `help_en.md` をそのまま基準にする。新しい章立ては提案し直さない。**

### 第1段階：Cloud版を整理してベータ公開に備える

- Cloudマニュアルの説明を、正規マニュアルの対応する章・順序に配置する。冒頭に変更メモや個別の注意を積み重ねない。
- 同じ機能の説明をまとめ、重複を削る。共通の操作説明を丸ごと複製して別管理しない。Cloudだけを読む利用者が手順を追えるよう、共通説明への案内を関連箇所に置く。
- インストール、編集、公開、更新・復元、MCPなどを既存の章立てに沿って整理する。画像公開の注意は画像の操作に、復元の注意は復元の操作に置く。
- 開発メモ・内部実装・修正履歴は利用者向け本文から分離する。READMEは製品概要、ベータの位置づけ、導入・マニュアルへの入口を簡潔に示す。
- 日英を同じ構成にし、既存のリンク・見出しID・公開ヘルプMCPの参照を確認する。
- ドキュメント整理と修正コードの検証・公開確認を経て、Cloud版のベータ公開を目指す。この方針の記録自体は公開・デプロイの指示ではない。

### 第2段階：正規マニュアルへ統合し、版を選んで読む

- 正規マニュアルに `flat` / `sqlite` / `cloud` / `all` の切り替えを設ける方向で進める。
- 各版では共通説明とその版に適用する説明だけを表示する。`all` では全版の情報を版の違いが分かる形で表示する。
- 本文だけでなく目次・検索・MCPの回答対象も版に合わせる。共通説明は一か所で管理する。
- 具体的なファイル分割、生成方法、版ごとのバージョン表示は統合時に決める。切り替え機能をベータ公開の必須条件にはしない。

### 編集規則

1. 同じ説明は一か所にまとめる。
2. 利用者の操作・判断に必要な内容だけを本文に残す。
3. 注意事項は該当操作の直前など、必要な場所に一度だけ書く。
4. 新情報は関連する既存節に統合する。冒頭・末尾への追記で済ませない。
5. 作業の中心は移動・統合・削減とする。短縮のために必須手順や重要な制約を落とさない。

### 正本と移行

第1段階では既存の2系統と同期経路を維持する。基本マニュアルの正本は
`help_ja.md` / `help_en.md`、Cloud固有の正本は `mikanBox-cloud/docs/cloud_ja.md` / `cloud_en.md`。
生成物は直接編集しない。統合の実装時に `AGENTS.md` の関連方針と同期・公開経路も揃える。

従来の「正式リリース後に統合」と2026-10-24の検討案は、上記の段階的な方針へ更新した。
過去の保護対象ファイル変更の記録は `mikanBox-cloud/.baseline/authorized-manual-structure.json`
にあり、元の `protected-files.json` は書き換えない。

## 2 系統の内訳

### 正本系統（製品マニュアル。PHP 2 版が対象）

| 役割 | 場所 |
|---|---|
| 正本 | `help_ja.md` / `help_en.md`（ワークスペース直下） |
| 配布コピー | `mikanBox-flat/mikanBox/docs/help_??.md` |
| 配布コピー | `mikanBox-sqlite/mikanBox/docs/help_??.md` |
| 配布コピー | `mikanBox-cloud/docs/help_??.md` |
| 同期 | `shared/sync.sh`（正本 → 3 版の `docs/`）。`shared/sync-cloud.sh` は Cloud だけへコピー |
| 公開 | 公式サーバーのページ `help_ja` / `help_en`（MCP `update_page` → `build_ssg`） |
| バージョン表記 | H1 の `<small class="manual-version">` に `MIKANBOX_VERSION`（両 PHP 版の `mikanBox/config.php`） |

配布コピーは生成物なので直接編集しない。正本を直してから同期スクリプトを実行する。

### Cloud 専用系統（Cloudflare 版の違いと開発メモ）

| 役割 | 場所 |
|---|---|
| 正本 | `mikanBox-cloud/docs/cloud_ja.md` / `cloud_en.md` |
| 生成物 | `mikanBox-cloud/src/cloud-help-data.json`（`scripts/sync-cloud-help.mjs` が生成。`npm run check` / `test` / `build` の前処理で自動実行） |
| 公開 | Cloud サイトの `/public-help.html?language=ja` と公開 MCP `/public-mcp` |
| バージョン表記 | H1 のラベルに `CLOUD_VERSION`（`mikanBox-cloud/src/version.ts`）。PHP 版のリリース番号とは別系統 |

`cloud-help-data.json` は生成物なので直接編集しない。

### 履歴（対象外）

`mikanBox-cloud/.backups/php-pre-2.7.*/` に v2.7.0〜v2.7.2 の正本コピーが残っている。
これは単なるバックアップで、更新対象でも参照先でもない。

## 統合前に片づける必要があること

1. **バージョンラベルが 2 系統ある。** 正本は PHP 版、Cloud は Cloud 版の番号を出している。
   1 ファイルに H1 は 1 つなので、統合するならラベルの規則を先に決め直す。
2. **Cloud マニュアルに開発メモが混在している。** `## 構成` `## ローカル開発`
   `## 既存版を変更しない手順` `## 残る互換性作業` `## 本番公開` は開発者向けで、
   ユーザー向けマニュアルへ持っていく部分ではない。統合時はまずここを分ける。
3. **Cloud 側の節名に開発版番号が埋まっている。** 例 `## 画像の静的配信（開発版 v0.6.0）`。
   統合するなら機能名だけの節へ正規化する。
4. **適用する版を整理する。** 共通説明と版固有の説明を分類し、重複を統合する。Cloudに当てはまらないPHP専用の手順を表示しない。
